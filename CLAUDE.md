# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

DOKA (Dock Operations Kit for Apple) — меню-бар-приложение macOS для голосовой диктовки: глобальный хоткей → запись с микрофона → транскрипция через OpenAI-совместимый API → автозамены по словарю → вставка текста в активное приложение. Бывшее имя проекта — Whisper (осталась миграция данных).

Репозиторий — `ippitenin/DOKA-macOS` (до переименования `ippitenin/DOKA`, GitHub перенаправляет старые URL): это версия для Mac. iOS-версия — отдельный репозиторий `DOKA-iOS`, общего кода с этим нет. Суффикс `-macOS` относится только к репозиторию: имя продукта остаётся «DOKA», и `DOKA.app`, bundle id, таргет `DOKA`, `Application Support/DOKA`, аккаунты Keychain, `DOKA.dmg` под имя репозитория НЕ переименовывать — пользователи потеряют данные, TCC-разрешения и ключи.

Структура корня:
- `DOKA-app/` — само приложение (SPM executable, macOS 15+, AppKit + SwiftUI; зависимости — KeyboardShortcuts, WhisperKit из argmax-oss-swift и FluidAudio, две последние — для локальных моделей распознавания).
- `DOKA_LOGO/` — исходники фирменного логотипа (`Vector_DOKA.svg/.pdf`); из `Vector_DOKA.svg` 1:1 перенесён контур `DokaPetalsShape` (см. дизайн-систему). `media/` — картинки для README.
- `README.md` / `README.ru.md`, `CONTRIBUTING.md` / `CONTRIBUTING.ru.md` — документация на двух языках; при правке одной версии обязательно править парную. `LICENSE` — GPL-3.0.

Локальные материалы вне репозитория (лежат на диске, перечислены в `.gitignore` — проект открыт, и в публичную историю они не попадают):
- `DOCS/NEXARA/` — локальная копия документации API Nexara: снимок docs.nexara.ru из дампа `llms-full.txt`, по странице на файл `GUIDES/<slug>.md`; дата дампа, способ регенерации и список пустых страниц — в `DOCS/NEXARA/README.md`. Не публикуется: это дословный чужой контент. `DOCS/superpowers/` — спеки и планы фич.
- Черновики соседних продуктов в корне (PRD и HTML-прототип) к коду DOKA-app отношения не имеют и в репозиторий не входят.

Язык кода и комментариев — русский. Строки интерфейса — только через `L("ключ")` (хелпер в `Sources/DOKA/Localization.swift`); каждый ключ обязан присутствовать в обоих файлах `Sources/DOKA/Resources/{ru,en}.lproj/Localizable.strings`. Второй слой локализации — `DOKA-app/Resources/{ru,en}.lproj/InfoPlist.strings` (тексты системных запросов разрешений): эти файлы `swift build` вообще не видит, в бандл их кладёт `build.sh`. Внимание: `swift build` НЕ валидирует синтаксис `.strings` — после правок прогонять `plutil -lint`. Язык интерфейса переключается настройкой `SettingsStore.appLanguage` (механизм `AppleLanguages`, применяется после перезапуска); названия языков в `AppLanguage.title` намеренно не локализуются — каждое на своём языке.

## Команды

Все команды выполняются из `DOKA-app/`:

```bash
swift build        # быстрая проверка компиляции (debug, только нативная архитектура)
./build.sh         # release-сборка (universal: arm64 + x86_64), подпись, установка в ~/Applications/DOKA.app
./build.sh --dmg   # то же + сборка DOKA.dmg в корне репозитория (hdiutil, UDZO): образ с приложением
                   # и симлинком на /Applications — установка перетаскиванием (артефакт в .gitignore)
./run.sh           # build.sh + запуск приложения

scripts/make-appicon.sh [исходник.png]   # перегенерация Resources/AppIcon.icns
                                         # (по умолчанию из Resources/AppIcon.png; поля по сетке macOS)
```

Коммиты — conventional commits с описанием на русском: `feat:` / `fix:` / `docs:` / `chore:` (см. `git log`).

### Гейты верификации

Тесты чистой логики — `Tests/DOKATests` (XCTest, ~531 проверка, прогон `swift test` меньше секунды). **Сплит на `DOKACore` НЕ нужен и не планируется**: SPM тестирует executable-таргет напрямую через `@testable import DOKA`, несмотря на top-level код в `main.swift` (прежняя запись про необходимость сплита была неверна — проверено). Покрыты `ReplacementEngine`, `TranscriptFormatter`, `TranscriptSegmentSplitter` (+ идемпотентность `withDetail`), `LightMarkdown`, `HistoryExport`, `DashboardMetrics`, `PerformanceMetrics`, `WordCount`, `SpeakerName`, `SpeakerRolesParser`, `SpeakerAssignment` (сшивка локальной диаризации со словами), слой правок `TranscriptEdits` (имена, слияния, переназначения, правка текста, `splitWithSources` — `TranscriptEditsTests`), `ProviderConfig.normalizeEndpoint`, `clockMMSS`, `Float.smoothed`, `FileTranscriptionClient.decode`/`decodeAsyncStatus`, библиотека транскрибаций (`TranscriptLibraryStorageTests`, `LibrarySearch`, `FileTranscriptionParams`, `LibraryGrouping`, `SegmentTimeline`, `LibraryExport`), таблица планов «Повторить» (`RetryPlanner`), чистая логика локального ИИ-анализа (`LLMTextTests` — сборка UTF-8 при каждом возможном разрезе байтового потока, фильтр размышлений, детектор зацикливания; `LocalAnalysisTests` — вход модели и отпечаток, чанкер, промпты, шаблоны, `TimestampLinker`), а также шейдеры панели (`ShaderLibraryTests`: наличие metallib, имена функций и — главное — зашитая в его заголовок минимальная версия macOS). Добавлены: `SilenceRemoverTests` (четыре порога обрезки тишины и паддинг, фикстуры — синтетический WAV через `WavWriter`), `LocalModelTests` (инварианты путей и идентификаторов локальных ресурсов, в т.ч. имя папки Parakeet), `ServiceIdentityTests` (аккаунты Keychain, включая историческое `nexara-api-key`), `LibraryModelsTests` (`FailureKind.classify` по всем веткам, `RecordSummary.make`), `RetentionTests`, `StatsSnapshotTests`, `TranscriptBodyCodableTests` (устойчивость декодеров тела).

**Ловушка, стоившая отдельного теста.** `TranscriptionProvider.openai` и `.groq` выглядят мёртвыми (в пикере их нет), но `HistorySectionView`, `TranscriptionControls` и `PerformanceAnalysisView` разбирают ими поле `provider` СТАРЫХ записей истории через `TranscriptionProvider(rawValue:)?.title ?? raw`. Удалить кейсы — показать людям сырые строки вместо названий сервисов. То же с `RecordSummary.preview` и `FileTranscriptRecord.updatedAt`: читателей в UI нет, но они ПЕРСИСТЯТСЯ в `meta.json`, и удаление не-опционального поля сделало бы новый файл нечитаемым для предыдущей версии приложения.

Ловушка тестов локализации: `SpeakerName.displayName` и сообщения `SpeakerRolesParser.RolesError` идут через `L()`, то есть зависят от языка бандла — проверять в них надо номер или структуру, а не конкретный перевод.

Вне покрытия принципиально: запись звука, вставка через CGEvent, Keychain, панели рекордера, сетевые запросы — им нужен живой Mac с разрешениями. Поэтому гейты остаются:

1. `swift build` — без предупреждений, затем `swift test` — все зелёные. **Автоматизировано** в CI (`.github/workflows/build.yml`): гейт предупреждений грепает лог по `Sources/DOKA/`, потому что `-warnings-as-errors` применился бы и к FluidAudio, у которой три своих предупреждения.
2. **Шейдеры**: после правки любого `Shaders/*.metal` — `scripts/build-shaders.sh`. SwiftPM `.metal` НЕ компилирует, поэтому голый `swift build` соберёт приложение со старым шейдером (или вовсе без него — капелька «Авроры» останется пустой, в лог уйдёт предупреждение). `build.sh` зовёт скрипт сам, в CI это отдельный шаг, а `ShaderLibraryTests` проверяет и наличие `default.metallib` в бандле, и имена функций — но только на ЧИСТОЙ сборке: на грязном `.build` старый metallib остаётся лежать в бандле и тест зеленеет вхолостую.
3. `plutil -lint` обоих `Localizable.strings` (при их правке — и обоих `InfoPlist.strings`): `swift build` синтаксис `.strings` НЕ проверяет. **Автоматизирован** там же, вместе со `scripts/check-localization.sh` — он сверяет парность ключей ru/en, дубли, плейсхолдеры, наличие ключей из `L(...)` и отсутствие мёртвых строк. Скрипт знает про девять префиксов ключей, собираемых интерполяцией `\(rawValue)` (`transcribe.roles.`, `transcribe.llm.preset.`, `transcribe.llm.prompt.`, `transcribe.detail.`, `transcribe.diarizeSetting.`, `transcriptRetention.`, `analysis.template.`, `analysis.format.`, `analysis.prompt.format.`) и про `sidebar.group.*` из массива в `SidebarView` — при добавлении новых динамических ключей список `DYNAMIC_PREFIXES` надо пополнять, иначе строки будут объявлены мёртвыми.
4. `./build.sh` — release + подпись. В CI выполняется только по тегу (`.github/workflows/release.yml`) и уходит в ad-hoc-ветку подписи: сертификата «DOKA Dev» на раннере нет. **Отдельно для llama.framework** (движок ИИ-анализа): `lipo -archs .../Contents/Frameworks/llama.framework/Versions/A/llama` — обязан быть `x86_64 arm64`; `otool -L .../MacOS/DOKA | grep llama.framework` и `otool -l ... | grep '@executable_path/../Frameworks'`; `codesign --verify --deep --strict`. Те же четыре проверки стоят шагом в `release.yml`; сам `build.sh` роняет сборку guard'ом `lipo`, если срез не universal.
5. Ручной smoke по затронутым областям:
   - **Диктовка**: end-to-end при `saveAudio` вкл/выкл, отмена Esc во время записи и во время распознавания, все стили панели, копирование. Гейт тишины: 2 с молчания → «Речь не услышана», в истории и на дашборде пусто, короткое «да» проходит, тумблер «Не отправлять запись без речи» выкл → тишина снова уходит в API; отсеянная запись длиннее секунды появляется в меню «Повторить неудачную диктовку». Повтор: Wi-Fi выкл → ошибка → пункт в меню-баре → Wi-Fi вкл → «Повторить» вставляет в то же приложение; переключение в другое приложение во время повтора → текст в буфере с сообщением; Esc во время повтора — пункт возвращается; ошибка вставки (поле пароля) пункт НЕ создаёт; успешная новая диктовка убирает пункт; после выхода/запуска пункта и временных `doka-*.wav` нет.
   - **Словарь**: «документ дока, привет» с правилом «дока» → «DOKA» даёт «документ DOKA, привет»; «Внутри слов» у «ё» → «е» меняет букву внутри слова; словарь, сохранённый прошлой версией, после обновления на месте. Тумблер «Применять словарь замен» на «Транскрибации»: показ, «Скопировать» и все форматы «Сохранить как…» с заменами, смена детализации их сохраняет, выключение сразу возвращает исходник. Для «Авроры» отдельно: волна реагирует на голос, после отпускания хоткея сменяется кольцом капель, на ошибке показывается классическая плашка, ореол не обрезан кромкой окна.
   - **Дашборд**: тест скорости печати, геро-метрики.
   - **История**: воспроизведение/экспорт записей, срок хранения, «Стереть всё аудио», экран анализа производительности.
   - **Звук**: буст микрофона с возвратом громкости, удаление тишины, громкость сигналов.
   - **Расширенные**: Dock-иконка, окно при запуске, перенос папки данных туда-обратно.
   - **Клавиши**: push-to-talk, кнопка мыши, Cmd+W/Cmd+M.
   - **Сервис**: добавление/удаление пресета; локальные модели — скачивание с прогрессом, отмена скачивания, удаление модели с подтверждением, «Подготовка модели…» после скачивания.
   - **Локальные модели**: диктовка на Whisper Large v3 Turbo (Local) и Parakeet TDT 0.6B v3 (Local) (русский и английский), Esc во время локального распознавания, транскрибация файла (аудио и видео) с тайм-кодами/SRT/VTT/сменой детализации, неактивные Nexara-контролы, перенос «Папки данных» туда-обратно — модели остаются в `Application Support/DOKA/Models` и продолжают работать.
   - **Локальная диаризация**: тумблер на локальной модели → модель качается сама, прогресс и «Отмена» работают, запуск заблокирован до готовности; запись с 2–3 голосами разделяется верно; отмена во время диаризации; экспорты «по спикерам» и «тайм-коды + спикеры»; смена детализации не теряет спикеров; запись короче секунды и тишина → расшифровка БЕЗ спикеров, а не ошибка; то же со своим сетевым сервисом (в запрос `task=diarize` не уходит); неактивные «Тип записи», «Роли» и «Анализ ИИ» не открываются по клику.
   - **Транскрибация файла**: диаризация (спикеры/тип записи/роли), смена детализации тайм-кодов на готовом результате, LLM-анализ, сворачивание карточек «Анализ»/«Транскрибация», блокировка дропзоны во время распознавания, неактивные Nexara-контролы на кастомном сервисе; async-путь builtin: отмена во время загрузки и во время опроса, kill приложения во время распознавания → добор результата после перезапуска.
   - **Транскрибация → результат**: готовый файл показывается записью библиотеки прямо на странице (плеер строкой, подсветка сегмента без прокрутки), «Открыть в библиотеке», крестик «Скрыть», полоса «Недавние» из трёх строк и «Вся библиотека».
   - **Библиотека**: поиск (заголовок и текст, ё = е, й ≠ и, сниппет с подсветкой, «Ищу в текстах…»), группы на границе суток, переименование в строке и в шапке записи (Enter / клик мимо — сохранить, Esc — отмена, пустое — имя файла), мультивыбор → экспорт одним файлом MD/TXT и файлами в папку (существующие файлы не затираются, незавершённые записи пропускаются), пакетное удаление вместе с выполняющейся задачей. Запись: плеер (play, ±5 с, скорость, слайдер до первого Play), клик по тайм-коду, подсветка и автоследование, ручная прокрутка выключает «Следовать» (macOS 15+), пробел в поле переименования не ставит паузу, Esc и ⌘[ — назад, ⌘F — поиск, «Удалить аудио записи»; уход из секции останавливает звук. Смена срока хранения в «Расширенных» (мгновенная чистка + живой тултип у заголовка), однократная плашка «теперь хранятся всегда» после миграции v1, перенос «Папки данных» во время воспроизведения.
   - **Повторить / Распознать заново / уведомления**: отмена builtin во время опроса → «Повторить» забирает результат без нового POST `/async`; отмена сразу после сабмита — `jobID` сохранён; «Повторить» ошибки сетевого сервиса — алерт тарификации (с анализом Nexara — с пометкой), локального — без алерта; исходник перенесён → повтор из архива, архива нет → выбор файла; удалённый пресет → «Распознать заново…»; «Отмена» у добираемой записи; во время чужой транскрибации «Повторить» недоступно, кроме бесплатного опроса. «Распознать заново» Whisper → Parakeet с диаризацией — новая запись с заголовком и аудио исходной, исходная на месте; кнопка «Распознать» заблокирована, пока идёт распознавание, без ключа или модели. Kill во время async → добор → уведомление, «прервано перезапуском» уведомления не даёт; окно на «Библиотеке»/«Транскрибации» — баннера нет, в другом приложении — есть; клик по уведомлению при закрытом приложении открывает запись; тумблер «Уведомлять о готовности» и запрет в Системных настройках → «Открыть настройки».
   - **Локальный ИИ-анализ**: «Сервис» → карточка «Анализ ИИ на этом Mac» — скачивание с прогрессом, «Отмена» на середине убирает огрызок (в `Models/llm` не остаётся `.incoming-*`), обрыв Wi-Fi на середине → докачка с того же места, «Удалить модель» с подтверждением. Первый запуск анализа после скачивания — «Подготовка модели…» около 12 с (компиляция Metal-кернелов), второй — мгновенно. Получасовая русская встреча с 2–3 спикерами → «Протокол встречи»: текст льётся в карточку по мере написания, стадии прогресса сменяются, «Отмена» и на разборе расшифровки, и на генерации ничего не сохраняет; повторный запуск даёт ВТОРОЙ анализ рядом с первым, попап переключает их. Запись на 1,5 ч → стадии «Часть N из M» и «Свожу итог…». Клик по `[12:34]` в списке и в таблице анализа перематывает плеер и подсвечивает сегмент. Переименовать спикера → на анализе оранжевая метка «Расшифровку изменили…» → «Повторить» даёт отчёт с новыми именами; тумблер «Применять словарь замен» метку НЕ зажигает. «Язык ответа» English на русской записи. Запись Nexara с анализом при загрузке → он в том же списке как «Nexara», «Повторить» у него нет, удаляется он так же. Смена сервиса и диктовка во время анализа его НЕ прерывают (кроме диктовки на локальном сервисе при ОЗУ ≤ 8 ГиБ — там «Анализ прерван диктовкой»); через 3 минуты простоя модель выгружается из памяти (видно по процессу). Автоанализ: включить в «Сервисе» → распознать файл → отчёт появляется сам. Шаблоны: создать свой, дублировать встроенный (встроенный не правится), удалить свой — готовые анализы остаются. Перенос «Папки данных» → анализы переехали с записями, модель осталась в `Models/llm`. На Intel карточки и кнопки видны, но неактивны, с объяснением.
   - **Спикеры и правка**: Nexara diarize — «Спикер 1» → «Анна» через чип и через бэйдж, имя во всех экспортах («по спикерам», «тайм-коды + спикеры», SRT, VTT) и после перезапуска; слияние (общий цвет, склейка «по спикерам») и «Отделить»; переназначение фрагмента длинной реплики на «Подробно» → на «Как сервер» реплика разрезана, «Вернуть исходного спикера», «Новый спикер»; двойной клик → правка → Return, Esc отменяет, пустое не сохраняется, клик мимо сохраняет, маркер ✎ с исходным текстом в тултипе, правка переживает все 4 детализации, «Вернуть исходный текст»; «Скопировать» и .txt с правкой, поиск находит правленый текст; Parakeet (правка на «Средне» → «Как сервер»), Nexara + анализ ИИ (без words), кастомный whisper-1 (частичная правка теряет пунктуацию сегмента — ожидаемо); «Сбросить правки» с подтверждением; пробел и ←/→ в редакторе не трогают плеер, Esc в редакторе не уводит из записи; меню «⋯», контекстное меню и вложенное «Назначить реплику» в английском интерфейсе.

Переменные окружения сборки: `DOKA_SIGN_ID` (имя сертификата, по умолчанию «DOKA Dev»), `DOKA_INSTALL_DIR` (по умолчанию `~/Applications`).

### Особенности сборки — не «чинить»

- **iCloud**: проект лежит на Рабочем столе, синхронизируемом iCloud. FileProvider вешает на файлы xattr, из-за которых `codesign` падает («detritus not allowed»). Поэтому `build.sh` собирает бандл во временной папке в `/tmp` и копирует с `cp -X`. Не пытаться подписывать бандл внутри папки проекта.
- **Подпись**: нужен самоподписанный сертификат «DOKA Dev» (инструкция — `DOKA-app/scripts/make-dev-cert.md`). При ad-hoc подписи macOS сбрасывает TCC-разрешения (микрофон, Accessibility) на каждой пересборке.
- **Шейдеры и SPM**: `default.metallib` собирается ОТДЕЛЬНЫМ скриптом и лежит в `Sources/DOKA/Resources` (в `.gitignore` — артефакт сборки), откуда `.process("Resources")` кладёт его в `DOKA_DOKA.bundle`, а `build.sh` забирает бандл своим циклом `*.bundle` — правок в копировании не нужно. Build-tool-плагин SwiftPM здесь пробовать НЕ надо: на `swift build -c release --arch arm64 --arch x86_64` он падает с «Unable to resolve build file … missing target», и это воспроизводится на пустом пакете. Исходники шейдеров лежат в `DOKA-app/Shaders/`, а не в `Sources/`, тоже намеренно: `.metal` внутри таргета даёт предупреждение «found 1 file(s) which are unhandled», которое уронит гейт предупреждений.
- **Universal binary**: release собирается `swift build -c release --arch arm64 --arch x86_64`, поэтому продукты лежат в `.build/apple/Products/Release/` (мультиарх-путь SPM), а НЕ в `.build/release/` — `build.sh` берёт бинарник и ресурсные бандлы именно оттуда. Debug-проверка `swift build` остаётся нативной (быстрая, одна архитектура).
- `build.sh` убивает запущенный процесс DOKA перед заменой бандла.
- **Минимум — macOS 15, и это не косметика.** Подняли с 14 из-за бага Apple
  (FluidAudio #878): на macOS 14 офлайновая диаризация роняет приложение —
  `EXC_BAD_ACCESS` в `libBNNS` (`BNNSGraphContextExecute_v2` → `_platform_memmove`).
  Матрица upstream: macos-14 — 1200/1200 крэшей, macos-15 и 26 — ноль на том же
  коде. Библиотечного обхода нет, починено в самой macOS 15; в 0.15.6 добавлено
  только предупреждение в лог. Понижать `platforms` обратно нельзя.
- **Шейдеры собираются с `-mmacosx-version-min`.** Компилятор Metal зашивает
  минимальную версию ОС в заголовок metallib и без флага берёт её из SDK
  сборочной машины: на Xcode 26 это давало «нужна macOS 26», и на всех
  системах ниже `makeLibrary(URL:)` молча отказывался грузить библиотеку —
  «Аврора» и «Мини» показывали пустую капельку. Ни сборка, ни CI этого не
  ловили (оба на macOS 26). `MIN_MACOS` в `scripts/build-shaders.sh` обязан
  совпадать с `platforms` в `Package.swift`; `ShaderLibraryTests` сверяет
  зашитую версию, читая байт по смещению 12 в заголовке (0x0f = 15).

## Архитектура

Точка входа `main.swift`: `LegacyMigration.run()` (обязательно до первого чтения настроек) → `AppDelegate`. Приложение — `.accessory` / `LSUIElement`: только меню-бар, без Dock.

**Центр всего — `DictationController`** (`Sources/DOKA/DictationController.swift`): конечный автомат `idle → recording → transcribing → idle` плюс состояние `error`. Счётчик поколений `generation` инвалидирует устаревшие задачи транскрипции: любая смена состояния увеличивает его, и задача со старым значением не имеет права трогать автомат или вставлять текст. Любое изменение жизненного цикла диктовки проходит через `transition(to:)`.

**Владение объектами**: `AppDelegate` владеет всеми верхнеуровневыми объектами (DictationController, HotkeyManager, MenuBarManager, RecorderPanelController); остальные держат `weak`-ссылки. Весь код `@MainActor`.

**Поток данных диктовки**:
`HotkeyManager` (KeyboardShortcuts) → `DictationController` → `AudioRecorder` (WAV во временный файл) → `TranscriptionClient` (multipart POST на `/audio/transcriptions`) → `ReplacementEngine` (правила словаря) → `HistoryStore` (JSON в Application Support/DOKA, максимум 200 записей; метаданные — всегда, сжатое m4a-аудио — только если включён тоггл `SettingsStore.saveAudio`, по умолчанию ВЫКЛ; см. раздел «История») и `StatsStore` (lifetime-агрегаты для дашборда) → `Paster` (буфер обмена + синтетический Cmd+V через CGEvent). Кодирование m4a — ещё один `await` в пайплайне (между распознаванием и вставкой), поэтому при выключенном `saveAudio` его пропускают целиком и вставка быстрее; после кодирования автомат повторно проверяет `generation` (отменённая диктовка не пишется в историю и не вставляется). Ключевые переходы автомата озвучиваются системными звуками macOS через `SoundPlayer` (`Audio/SoundPlayer.swift`: старт/стоп/отмена/ошибка), гейтится настройкой `SettingsStore.soundsEnabled`.

**Гейт тишины и повтор диктовки.** Решение «отправлять ли запись» — чистый `Audio/DictationGate.swift` (`minDuration 0.4` с — случайное нажатие; `minSpeechDuration 0.25` с активной речи по `AudioRecorder.speechDuration`, т.е. по СТАРОЙ dB-кривой — сам порог `speechLevelThreshold` не трогать). Запись без речи не уходит ни в API, ни в историю/статистику (`error.noSpeech` через обычный канал `.error`, звук `.cancel`); гейт выключается тумблером `SettingsStore.skipSilentRecordings` («Звук») для тихих голосов. Слот повтора `DictationController.lastFailedDictation` (один, только в памяти, WAV во временной папке): заполняется при ошибке ДО `history.add` (маршрут, распознавание, движок) и отсеянной гейтом записью длиннее `retryableMinDuration` 1 с — «распознать всё равно». Приоритет слота: отсеянная тишина (`FailedDictation.gated`) НЕ вытесняет настоящую неудачу — иначе случайное нажатие хоткея после сбоя сети стёрло бы реальную диктовку; такая тишина просто выбрасывается. Ошибка ВСТАВКИ слот не заполняет: текст уже в истории и в буфере, повтор задублировал бы запись. Судьбу WAV решает одно место — `settle(outcome)` в `defer` `transcribeAndPaste`: он не трогает автомат, а `outcome = .failed` выставляется только при `generation == gen`, поэтому устаревшая задача слот не перезапишет; Esc во время ПОВТОРА возвращает исходник в слот, Esc живой диктовки выбрасывает запись. Пункт меню-бара «Повторить неудачную диктовку (0:12)» (`isHidden` по `CombineLatest(state, slot)` — `isEnabled` перетёр бы `autoenablesItems`) распознаёт запись текущим сервисом в обход гейта; результат вставляется, только если frontmost PID не сменился с момента клика, иначе — буфер обмена и сообщение. Слот чистится успешной новой диктовкой и в `applicationWillTerminate`; сироты `doka-*.wav|tmp` прошлых запусков подчищает фоновый sweep на старте (`sweepOrphanedTempFiles`, только файлы старше запуска).

**Сервисы транскрипции** (`Network/TranscriptionProvider.swift`, маршрут и фасад — `Network/ServiceRoute.swift`): в UI `builtin` (Nexara), две локальные модели (см. «Локальные модели») и пользовательские пресеты `CustomService` (список в UserDefaults, у каждого свой ключ в Keychain под аккаунтом `custom-<uuid>`); `SettingsStore.providerID` — `"builtin"`, `"custom:<uuid>"` либо `"local:whisper"`/`"local:parakeet"`. Доступ к активному сервису — ТОЛЬКО через фасады `SettingsStore.currentAPIKey / currentKeychainAccount / providerConfig / providerTagForHistory / selectedLocalModel / isLocalService / isServiceReady / resolveRoute` (не через Keychain напрямую). `isServiceReady` — единая проверка готовности (локальный: модель скачана; сетевой: разбирается конфиг И сохранён ключ) — именно её используют гейты диктовки, онбординга и транскрибации файлов, других редакций этой проверки не заводить; `providerConfig` и `currentAPIKey` для локального сервиса возвращают `nil` (ключа нет, Keychain не трогается). `resolveRoute()` отдаёт enum `ServiceRoute` (`local(LocalModel)` / `remote(apiKey:config:)`, свойство `modelTag` для метаданных истории) — ЕДИНСТВЕННАЯ форма ветвления «локальный/сетевой» в контроллерах (`DictationController` и `FileTranscriptionController` свитчатся по нему); бросает `ClientError.notConfigured`/`.noAPIKey`, читает Keychain — не звать синхронно в пути запуска. Enum `TranscriptionProvider` остался ради keychain-имён и `normalizeEndpoint`; у `builtin` историческое имя аккаунта `nexara-api-key` — не менять, потеряются ключи пользователей. Прежние openai/groq/custom один раз мигрируются в пресеты (`migrateLegacyServices`, флаг `servicesMigrated`; префикс `local:` проходит через его `default: return` нетронутым). Пикер в `ServiceSectionView` построен на enum `ServiceMenuItem: Equatable` (builtin → локальные → пресеты → «Новый сервис…»; пресет несёт сам `CustomService`, выбор — `firstIndex(of: currentItem)`) — не возвращать ни позиционную арифметику индексов, ни индексы внутри case'ов.

**Локальные модели** (`Sources/DOKA/Local/`) — распознавание on-device, без сети и ключа: «Whisper Large v3 Turbo (Local)» = openai whisper large-v3-turbo через WhisperKit (вариант `openai_whisper-large-v3-v20240930`, ~1.6 ГБ) и «Parakeet TDT 0.6B v3 (Local)» = NVIDIA parakeet-tdt-0.6b-v3 через FluidAudio (~700 МБ, int8-энкодер). Названия в UI (`LocalModel.title`) соответствуют фактическим моделям: «Turbo» — у Whisper (v20240930 и есть turbo-релиз), у Parakeet никакого «Turbo» нет. Оба — CoreML (ANE/GPU/CPU), русский поддержан обоими.
- **Зависимости**: WhisperKit пинится линией `.upToNextMinor(from: "0.18.0")` — в 1.x два executable-продукта (`argmax-cli`/`whisperkit-cli`) делят таргет `ArgmaxCLI`, и universal-сборка `--arch arm64 --arch x86_64` падает с «duplicate key found»; при обновлении пина сначала проверять release-сборку. FluidAudio пинится ТОЧНО (`exact: "0.15.5"`), и это проверено живьём: на 0.15.7 debug собирается и тесты зелёные, `--arch arm64` тоже, а `--arch arm64 --arch x86_64` падает с `ld: library not found for -ltext_processing_rs` — срез `macos-arm64_x86_64` у нового артефакта `NemoTextProcessing.xcframework` есть, ломается мультиарх-путь SwiftPM (как у WhisperKit 1.x). Прежний `.upToNextMinor` от этого не защищал: он разрешает 0.15.7. У 0.15.5 бинарных таргетов и xcframework нет — при сборке по сети тянутся только git-репозитории зависимостей, в бандл ничего докладывать не надо (`otool -L` чистый). Учтите, что «патч» у FluidAudio не означает патч: между 0.15.5 и 0.15.7 — 237 файлов и +28 000 строк. Ресурсные бандлы новых зависимостей (`swift-crypto`, `swift-transformers`) `build.sh` подхватывает своим циклом `*.bundle`. **Тулчейн сборки: Xcode 26+** — `swift-collections` объявлен как `swift-tools-version: 6.2`, и на Xcode 16 сборка падает ещё на резолве; deployment target при этом — macOS 15 (объявлен строкой `.macOS("15.0")`, а не `.v15`: тот кейс появился только в tools-version 6.0, а манифест у нас 5.9).
- **Хранение** — `LocalModelStore` (синглтон, `@Published` состояние notDownloaded/downloading/preparing/ready/failed). Ключ состояния — `LocalAsset` (`.speech(LocalModel)` / `.diarizer`), а НЕ `LocalModel`: диаризатор — не сервис, в `providerID` и в пикер «Сервис» он попадать не должен, а `LocalModel.allCases` как раз строит меню сервисов; общий у них только механизм скачивания. Для существующих вызовов оставлены тонкие перегрузки с `LocalModel`. Ловушка путей FluidAudio: у ASR (`AsrModels.download/load/modelsExist`) переданный путь теряет последний компонент и получает вместо него имя репозитория — поэтому `parakeetFolder` обязан называться `Models/parakeet-tdt-0.6b-v3` (пока он назывался `Models/parakeet`, папка не существовала: размер модели показывался нулевым, а «Удалить модель» было no-op); у офлайнового диаризатора наоборот — путь идёт как есть, а репозиторий создаётся ВНУТРИ (`Models/diarizer/speaker-diarization`). Модели живут в ФИКСИРОВАННОЙ `AppDataFolder.modelsURL` (`Application Support/DOKA/Models`), за кастомной «Папкой данных» НЕ следуют — это перекачиваемый кеш, а перенос 1.5+ ГБ сделал бы миграцию блокирующей. `AppDataFolder.migrateToTarget` копирует и удаляет по элементам, пропуская `Models` в обе стороны, и не считает её «непустотой» цели при возврате на дефолт. Скачивание — API самих SDK с прогресс-колбэками через общий `ProgressSink` (квантование до целого процента: URLSession шлёт колбэки на каждый чанк, без квантования SwiftUI перерисовывался бы сотни раз в секунду); отмена и провал подчищают частично скачанное (иначе огрызок притворится готовой моделью). Размер папки модели считается ФОНОМ (`refreshSize`, до подсчёта показывается `approxDownloadBytes`): рекурсивный stat 1.6-ГБ дерева в `init` синхронно блокировал бы запуск приложения, а `markPreparing(false)` берёт закешированный `knownSizes` — без пересчёта в критическом пути диктовки. Удаление модели — мгновенный rename в `*.deleting-<uuid>` + фоновое стирание (`removePartial`; осиротевшие после kill папки подчищает `sweepDeleteLeftovers` на старте).
- **Движки** — протокол `LocalTranscriptionEngine` (`transcribeDictation` → чистый текст, `transcribeFile` → `LocalFileTranscription` с сегментами/словами в типах DOKA) и реализации `WhisperLocalEngine`/`ParakeetLocalEngine`; импорты WhisperKit/FluidAudio намеренно заперты в файлах движков `Local/` (у пакетов свои `TranscriptionResult`/`TranscriptionSegment`/`Language`). Владелец загруженного движка — `LocalEngineManager`: один движок на приложение, загрузка через общую задачу `loading` (кортеж модель+задача; прогрев и диктовка не грузят модель дважды), выгрузка после 5 минут простоя (`idleUnloadDelay`, модель держит ~2 ГБ ОЗУ), при смене сервиса (didSet `providerID`) и при удалении модели. Прогрев (`prewarm`) стартует сразу после скачивания: первая CoreML-компиляция под чип (минуты) уходит в статус «Подготовка модели…», заодно WhisperKit кэширует токенайзер с HuggingFace (сеть нужна ровно один раз — сразу после скачивания она есть).
- **Локальная диаризация** (`Local/LocalDiarizer.swift`) — разделение по спикерам на этом Mac поверх ОФЛАЙНОВОГО (VBx) диаризатора FluidAudio: `OfflineDiarizerModels.load` + `OfflineDiarizerManager.process(url)`, модели pyannote community-1 + WeSpeaker, **всего ~22 МБ** (CC-BY-4.0, см. `THIRD_PARTY_LICENSES.md`), ~12× быстрее реального времени на M-чипе. Онлайновый `DiarizerManager` НЕ использовать: его `DiarizerConfig.numClusters` («ожидаемое число спикеров») в 0.15.5 не читается ни одной строкой пайплайна — подсказки о числе спикеров у него фактически нет, плюс сегменты могут перекрываться. У офлайнового подсказка настоящая (`config.withSpeakers(exactly:)`), сегменты неперекрывающиеся; проверено стендом: принудительная единица схлопывает диалог в одного спикера, а лишних спикеров подсказка не выдумывает. Менеджер создаётся на КАЖДЫЙ прогон (число спикеров живёт в конфиге, а не в вызове), тяжёлые модели переиспользуются. Идентификаторы `S1`/`S2` ремапятся в формат Nexara `speaker_0`/`speaker_1` по порядку первого появления — иначе `SpeakerName` и все экспорты покажут сырой id. Требования Apple Silicon у диаризатора нет (в отличие от Parakeet). Владелец — тот же `LocalEngineManager` (диаризатор живёт РЯДОМ с речевым движком, та же выгрузка по простою). Сшивка со словами — чистый `Util/SpeakerAssignment.swift`: сегмент целиком внутри одной реплики сохраняет исходный текст, сегмент со сменой говорящего режется по словам; без слов спикер берётся по наибольшему перекрытию. Ошибка диаризации (в т.ч. `noSpeechDetected` на записи короче секунды и на тишине) НЕ роняет расшифровку — результат просто остаётся без спикеров.
- **Диктовка**: ветка в `DictationController.transcribeAndPaste` (switch по `SettingsStore.resolveRoute()`) — те же 4 проверки `generation == gen` плюс одна после загрузки движка; WAV диктовки уже 16 кГц mono, конвертация не нужна. Отмена по Esc кооперативная: у Whisper колбэк декодера возвращает `false`, у Parakeet — `Task.checkCancellation` после инференса.
- **Файлы**: ветка `case .local` в `FileTranscriptionController.transcribe()` (мимо async/sync сетевых) — `AudioFileDecoder` (AVAssetReader → WAV 16 кГц mono, единый вход и для аудио, и для видео: сами SDK видеоконтейнеры не читают; работа в detached-задаче с пробросом отмены) → `engine.transcribeFile` → `TranscriptResult` (`llmOutput = nil`), дальше общий путь; загрузка движка перекрывается с декодированием (`async let`) — холодный старт не ждёт сумму двух операций: перенарезка `withDetail`, все экспорты, библиотека. Parakeet предложений не делит — отдаётся один сегмент на всю запись + пословные тайм-коды, красивую нарезку делает `TranscriptSegmentSplitter`. При включённой диаризации тот же временный WAV идёт в `LocalDiarizer` ДО `defer`-удаления файла, спикеры сшиваются `SpeakerAssignment`. Роли и LLM-анализ для локальных недоступны (гейт `isBuiltinService`); recovery на старте помечает локальных сирот «прервано перезапуском» (ветка `jobID == nil`).
- **Intel**: на x86_64 Whisper работает через CPU в разы медленнее (предупреждение в карточке), Parakeet не работает вовсе — FluidAudio требует Apple Silicon. Источник знания — `LocalModel.requiresAppleSilicon` + `LocalModel.isAppleSiliconMac` (`#if arch`); барьер — в `LocalModelStore.download` (кнопка в UI лишь презентация, `.disabled`), предупреждение жёстче.

**Синглтоны**: `SettingsStore.shared` (обёртка над UserDefaults, все настройки `@Published`), `HistoryStore.shared`, `AudioStore.shared` (сжатое аудио истории на диске), `TranscriptHistoryStore.shared` (библиотека транскрибаций файлов), `LibraryModel.shared` (состояние секции «Библиотека»), `RecordingPlayer.shared` (воспроизведение записей истории и библиотеки), `StatsStore.shared` (агрегаты статистики диктовки), `PermissionsManager.shared` (микрофон + Accessibility), `WindowManager.shared`.

**UI — два слоя**:
- Главное окно (`UI/WindowControllers.swift` + `UI/Main/`): ленивый NSWindow с SwiftUI `MainWindowView`, сайдбар с секциями (enum `MainSection`: home/dashboard/general/sound/hotkeys/dictionary/service/history/transcribe/library; группа сайдбара «Диктовка» — transcribe, library, history, dictionary). Внимание к названиям: `home` в UI называется «DOKA» (онбординг/готовность к диктовке), а `dashboard` в UI называется «Дашборд» — экран статистики диктовки (ключ `section.dashboard`). Окно переживает закрытие (`isReleasedWhenClosed = false`).
- Плавающая панель записи (`UI/RecorderPanel.swift`, контроллер `RecorderPanelController`): borderless non-activating `NSPanel`, никогда не становится key — фокус остаётся в целевом приложении. Шесть стилей (по умолчанию `classic`); порядок кейсов в `RecorderStyle` задаёт порядок карточек в пикере — `allCases` идёт прямо в сетку, поэтому переставлять их можно только осознанно, но ошибки показываются всегда; classic (и `hidden`, когда та показывает ошибку) рендерит `RecorderView.swift`, у остальных — свои файлы. **`aurora` и `mini` — одна и та же капелька** (`UI/DropRecorderView.swift`), отличаются габаритами (`DropGeometry.wide` 180×44 против `.compact` 90×63 — единственный источник размеров; во время распознавания каждая стягивается в круг ПО СВОЕЙ высоте, `DropGeometry.transcribing` вычисляется от `recording.height`, общая константа дала бы овал), флагом `DropGeometry.halo` (тёплый ореол за капелькой — только у «Авроры»; у «Мини» его убрали по решению пользователя, не возвращать без просьбы), графикой `DropGeometry.look` (`DropLook`: подложка `DS.Aurora.cosmic` против более глубокой `cosmicDeep`, палитрой целиком (`DropLook.wave`/`waveHighlight`/`rimTop`/`rimBottom`: «Мини» — ХОЛОДНАЯ тема на токенах `DS.Aurora.mini*` (ледяная ведущая нить, бирюза Тиффани, сине-фиолетовый хвост, тёмно-синяя подложка), тёплые `DS.accent`/`DS.glow` в неё не подмешивать — тёплое рядом с бирюзой спорило за внимание, пробовали дважды), ровная кромка против живой) и тем, поднимает ли контроллер панель со `ScreenGlowView`. Миниатюре в пикере `look` передаётся явно — иначе карточка покажет чужую капельку. Кому нужна подсветка всего экрана — берёт «Аврору», кому только капельку — «Мини». Прежний вид «Мини» (стеклянная пилюля с точкой записи) удалён. `notch` (`NotchRecorderView.swift`) — чёрная плашка-бровка, прирастающая к ВЕРХНЕЙ КРОМКЕ экрана (`position`: `y = frame.maxY - size.height`, отступ 0; высота — РОВНО `safeAreaInsets.top`, любая добавка свешивает плашку ниже кромки выреза) и с аппаратным вырезом, и без него (фейковый нотч, плоский верх + скруглённый низ); уровень окна `.statusBar` рисует поверх менюбара. Фон намеренно чисто чёрный (не стекло), панель пересоздаётся при каждом показе под геометрию экрана с курсором. `aurora` (`UI/DropRecorderView.swift`) — капелька 180×44 снизу плюс полноэкранная подсветка краёв: для неё контроллер поднимает ВТОРУЮ borderless-панель `glowPanel` с `ignoresMouseEvents = true` (клик-сквозной оверлей со `ScreenGlowView`), живущую отдельно от основной. Габариты собраны в `DropGeometry`. Содержимое — Metal-шейдеры (`Shaders/AuroraDrop.metal`, обёртка `DropShaders`): `dokaDropWave` при записи, `dokaDropDots` при распознавании и `dokaDropGlass` поверх обоих — стеклянная оболочка на `.layerEffect` (единственный способ дать шейдеру доступ к уже нарисованному содержимому): у кромки свет преломляется, по краю идёт ровный блик. После `layerEffect` обязателен ПОВТОРНЫЙ `clipShape(Capsule())` — преломление уводит сэмплы за границу, иначе вокруг капельки висит размытый ореол чужого цвета.

Ловушки этой панели, каждая оплачена переделкой:
- **Ширину капсулы нельзя менять в одиночку.** Фаза волны считается от ОПОРНОГО аспекта `kRefAspect = 90/63`, а не от фактического: иначе с ростом ширины волна уплотняется (больше колебаний на ту же капсулу) вместо того, чтобы растягиваться. Меняете ширину в `DropGeometry` — форма остаётся прежней, и это правильно; ровно поэтому «Мини» с её 90×63 получает ту же волну, просто сжатую.
- **Палитра волны — `accent` → `glow` → индиго**, ядро `waveHighlight`. Тёплый вариант (оранжевый/коралл/янтарь) с бегущим по кромке импульсом пробовали и откатили по решению пользователя: не заводить заново без явной просьбы.
- **Пружина ширины недодемпфирована** (жёсткость 400, демпфирование 18, ζ ≈ 0.45): при переходе к распознаванию капсула стягивается в круг по своей высоте (63 у «Мини», 44 у «Авроры») с отскоком. Появление — вторая пружина (`appear`, ζ ≈ 0.6, перелёт ~10%): капелька раздувается из точки, прозрачность набирается быстрее размера. Окно панели (260×119) держит запас под оба перелёта, а сдвиг рамки при показе для «Авроры» отключён — он спорил бы с ростом из точки.
- **Подсветка краёв «Авроры» приглушена намеренно** (`ScreenGlowView`): максимум по ЦЕНТРУ нижнего края, под капелькой, и пологим колоколом (маска `centerFalloff`, края — 0.64 от центра: углы приглушены, но не гаснут) спадает к левому и правому нижним углам — прежний вариант с доминантой в углах откачен по решению пользователя. Огибающая уровня здесь мягче, чем у капельки (attack 0.25): полноэкранный свет на резком подъёме читается как вспышка. Не возвращать яркость без просьбы.
- **Живая кромка — только у «Мини»** (`DropLook.mini`, параметры `bleed`/`tide`/`aberration` в `dokaDropGlass`): блик подхватывает цвет и яркость содержимого из-под себя (сэмпл ГЛУБЖЕ преломлённого), бежит вдоль кромки двумя приливами на фазе волны и расщепляет каналы R/B хроматической аберрацией. «Аврора» передаёт эти три параметра нулями и получает прежний ровный блик — отдельной функции шейдера для неё не нужно. Из-за аберрации и подкромочного сэмпла `maxSampleOffset` у `layerEffect` втрое от `refraction`, а не вдвое: с прежним запасом SwiftUI обрежет выборку.
- `DropMotion` — ССЫЛОЧНЫЙ тип намеренно: фаза, пружина и импульс считаются каждый кадр внутри `TimelineView`, а мутировать `@State`-значение прямо в `body` нельзя.

Текста в капельке нет вовсе, поэтому на `.error` стиль падает на классический вид — как `hidden`. Один и тот же `DropSurface` рисует живые панели обоих стилей и миниатюры в пикере (`DropPreview`). `studio` (`StudioRecorderView.swift`) — компактная стеклянная плашка внизу экрана (`glassSurface`, как у классической) с волной-спектром (`StudioWave` на `Canvas` + `TimelineView`: десятки столбиков с колоколообразной огибающей, двухслойный bloom, амплитуда и яркость растут от усиленного уровня микрофона — «драйва», ядро высветляется к белому), таймером по центру и подписью esc снизу.

**Дашборд** (`UI/Main/DashboardSectionView.swift`, секция `dashboard`) — статистика диктовки. Источник данных — `StatsStore` (синглтон, `stats.json` в Application Support/DOKA): lifetime-счётчики (слова, время, сессии) + посуточные бакеты; инкремент в `DictationController` сразу после `history.add`; при первом запуске — одноразовый backfill из истории (флаг `seededFromHistory`), т.к. история капается на 200 записей и lifetime-агрегаты по ней неполны. Чистые вычисления вынесены в `DashboardMetrics` (value-type, тестопригодно). «Скорость речи» и множитель считаются от **активной речи**, а не полной длительности записи: `AudioRecorder` накапливает время, когда уровень микрофона выше порога речи (`speechLevelThreshold`), и отдаёт его как `speechDuration`; `StatsStore` копит `totalSpeechWords`/`totalSpeechDuration`, по которым `DashboardMetrics.speechWPM` считает темп (фолбэк на полную длительность для старых записей без этих данных, чтобы не делить на ноль). `timeSaved` и `speedMultiplier` согласованы — оба от `speechWPM`. Геро-метрики (множитель «в N× быстрее», сэкономленное время) гейтятся тестом скорости печати: пока `SettingsStore.typingSpeedWPM == 0` — вместо них карточка-призыв пройти тест. 30-дневный график «слова в день» — `DailyWordsChart` на `Canvas` (без Swift Charts, как волны рекордера). Тест скорости печати — `TypingTestView` (модальный SwiftUI `.sheet` от дашборда; нужен фокус клавиатуры, поэтому именно `.sheet`, а не borderless `NSPanel`), фразы — `TypingPhrases` (RU/EN по языку интерфейса, без спецсимволов из-за смарт-замен `NSTextField`); измеряет скорость в словах/мин и сохраняет в `typingSpeedWPM`. Единый подсчёт слов и форматтер длительности — `Util/WordCount.swift` (`String.dokaWordCount`, `formatStatDuration`).

**Транскрибация файлов** (`UI/Main/TranscribeAudioSectionView.swift`, секция `transcribe`, в сайдбаре — в группе «Диктовка») — самостоятельная утилита: загрузка аудио/видеофайла (drag-and-drop через `.onDrop([.fileURL])` или `.fileImporter`) → транскрипция → показ сегментами с тайм-кодами и копирование. **Намеренно изолирована от пайплайна диктовки**: не пишет в `HistoryStore`/`StatsStore`, не вставляет текст (`Paster`) и по умолчанию не применяет `ReplacementEngine`. Исключение — тумблер «Применять словарь замен» (`SettingsStore.applyDictionaryToFiles`, по умолчанию ВЫКЛ; осознанно в `SettingsStore`, а не локально в контроллере: это пользовательская линза над выводом, а не параметр файла): замены накладывает выходной слой `Util/TranscriptOutput.swift` (`prepare` → `applyingDictionary`) на показ, «Скопировать» и «Сохранить как…». В фазе контроллера и в журнале всегда СЫРОЙ результат; результат `prepare` терминальный — его не хранят и не перенарезают (`withDetail` пересобирает текст из `rawSegments`/`words`, замены пропали бы), поэтому выключение тумблера мгновенно возвращает исходник. Свой стор — `TranscriptHistoryStore` (библиотека, см. ниже), сторы диктовки не трогает.
- **Сетевой слой** — ОТДЕЛЬНЫЙ `Network/FileTranscriptionClient.swift` (а не боевой `TranscriptionClient`, у которого `response_format` и Content-Type жёстко зашиты под WAV-диктовку): просит `verbose_json` (или `task=diarize` по тумблеру — разделение по спикерам, по умолчанию выкл, дороже, аудио от 3 с), отдельный `URLSession` с увеличенными таймаутами. Multipart-тело собирается во временном файле и уходит ПОТОКОВО (`upload(for:fromFile:)`, `writeMultipartBody`, файл кусками по 1 МБ) — память не зависит от размера файла, лимит 3 ГБ (`maxBytes`). Ловушки: MIME части файла — по явному белому списку Nexara (`mimeFallback`, НЕ `UTType`: системный отдаёт типы вне списка, напр. `.wav → audio/vnd.wave`, который сервер отклонит); декод — одной структурой с опциональным `speaker` (покрывает и verbose_json, и diarize, который игнорирует `response_format` и всегда возвращает свой JSON); деградация ответа (сегменты без тайм-кодов, ответ без сегментов, пустой llm_output) логируется NSLog с усечённым сырым JSON.
- **Состояние** — `FileTranscriptionController` (`@MainActor`, автомат idle→picked→transcribing→done/error, отмена через `Task.isCancelled`), **синглтон** (`shared`, `@ObservedObject`): результат и выбранный файл живут до закрытия приложения и переживают пересоздание вью при переключении секций (`MainWindowView` рендерит контент с `.id(section)`). ВСЕ настройки страницы (язык, диаризация, спикеры, роли, анализ) — локальные `@Published` контроллера, в `SettingsStore` НЕ пишутся: они привязаны к конкретному файлу, а не к пользователю. **Один файл за раз** (осознанно, без очереди/параллели): во время распознавания дропзона заблокирована (`controller.isTranscribing`), иначе новый файл через `accept()` отменил бы текущую задачу; прервать — «Отмена» в плашке прогресса. `transcribe()` ветвится: builtin — async-путь (`submitAsync` → персист job_id в журнал → `waitForResult`), кастомные — прежний sync `transcribeRich`; обе ветки пишут итог в `TranscriptHistoryStore`. Готовый результат — запись библиотеки (`.done(recordID:)`) в раскладке `.inline` компонента `TranscriptRecordView`; открыть запись из полосы «Недавние» — значит перейти в библиотеку (`LibraryNavigator.open`), на странице записи больше не восстанавливаются; `hideResult()` скрывает запись со страницы (крестик в её шапке; запись остаётся в библиотеке). Отмена async-задачи = перестать опрашивать: эндпоинта отмены у Nexara нет, сервер задачу дообработает и тарифицирует — запись честно остаётся «Отменена».
- **Результат** — `TranscriptResult` (карточка в UI называется «Транскрибация»): `segments` для показа, `rawSegments` + `words` для локальной перенарезки, `llmOutput`. «Скопировать» этой карточки кладёт в буфер чистый текст (rich-копия — только у карточки «Анализ»), а форматы (чистый текст / с тайм-кодами / SRT / VTT / по спикерам) идут через меню «Сохранить как…» (`NSSavePanel`) — все строятся ЛОКАЛЬНО из сегментов чистым `Util/TranscriptFormatter.swift` (тестопригоден, как `WordCount`), без доп. запросов к API. Тайм-коды: всегда запрашивается `timestamp_granularities[]=word` — в ОБОИХ режимах сервер отдаёт и сегменты, и пословный массив `words` одним запросом (проверено живыми вызовами; diarize к тому же кладёт `speaker` в сегменты). Имена спикеров — `Util/SpeakerName.swift` (`speaker_N` → «Спикер N+1», `unknown_N` → «Неизвестный N», имена ролей — как есть), имена, заданные пользователем, — поверх (см. «Спикеры и правка текста»); цвет бэйджа — `SpeakerName.colorIndices`: `speaker_N` по номеру, остальные по порядку первого появления в исходниках, пропуская номера `speaker_N` (НЕ hashValue — он рандомизирован на процесс).
- **Гейт builtin**: Nexara-специфичные параметры (`task=diarize`, `num_speakers`, `diarization_setting`, `roles`, `prompt`) попадают в multipart ТОЛЬКО при встроенном сервисе (`isBuiltinService`): у кастомных OpenAI-совместимых API этих полей нет, а `prompt` там значит другое — контекстную подсказку Whisper, LLM-инструкция молча исказила бы транскрипцию. В UI контролы при этом НЕ скрываются, а показываются неактивными (`.disabled` + `.opacity(0.5)`, сноска `transcribe.builtinOnly` в футере карточки): исчезающий контрол не отличить от несуществующей функции. Исключение — разделение по спикерам и подсказка «Спикеры»: они активны везде, вне Nexara их считает `LocalDiarizer` (`usesLocalDiarization`), модель качается сама при включении тумблера, а `canTranscribe` блокирует запуск, пока она не готова. Для кастомного сетевого сервиса запрос и локальная диаризация идут ПАРАЛЛЕЛЬНО (`async let`) — шкала времени общая, сервер распознаёт исходный файл, а декодирование её не сдвигает.
- **Ловушка неактивности**: `SettingsPopup`/`PopUpButton` и `TilePopUpOverlay` — это `NSViewRepresentable` поверх `NSPopUpButton`, а SwiftUI НЕ пробрасывает `.disabled` внутрь них сам. Без явного `button.isEnabled` (читается из `@Environment(\.isEnabled)`) заблокированный снаружи список продолжает раскрываться по клику — у плашек он вдобавок прозрачный и лежит поверх, то есть визуально «серая» плашка работала бы как обычная.
- **Качество диаризации** — под тумблером ряд равноширинных плашек `OptionTile` (`UI/Main/TranscriptionControls.swift` — общий файл контролов страницы и записи библиотеки; видимы при diarize), значения уходят только при diarize и только не-дефолтные: «Спикеры» (Авто/1–10 → `num_speakers`, подсказка серверу — главное лекарство от «вся запись speaker_0»), «Тип записи» (`diarization_setting`: ТОЛЬКО general («Стандартная») и telephonic — третьего значения в доке Nexara нет, не добавлять; для Zoom и звонков с перебиваниями Nexara рекомендует telephonic) и «Роли». Ловушка: SwiftUI `Menu` с кастомным лейблом на macOS схлопывает плашку в текст с шевроном и игнорирует `maxWidth`, поэтому плашка рисуется чистым SwiftUI, а клик ловит растянутый поверх невидимый `NSPopUpButton` (`TilePopUpOverlay`, `isTransparent` — не рисуется, но получает события; копия паттерна `PopUpButton` из SettingsForm).
- **Роли** (`roles`, только с diarize): Выкл / Авто / Свои роли (имена через запятую). Клиентская валидация — чистый `Util/SpeakerRolesParser.swift` (лимиты на число ролей и длину имени, дубли; ошибка блокирует запуск); имена кодируются ТОЛЬКО `JSONEncoder` (экранирование). Лишние говорящие приходят как `unknown_N`.
- **Детализация тайм-кодов** — `TranscriptSegmentSplitter.Config` (пресеты coarse/medium/fine) + enum `TimestampDetail` в том же файле. Нарезка ЛОКАЛЬНАЯ по границам предложений, поэтому смена уровня на готовом результате перенарезает его мгновенно и без нового запроса (`TranscriptResult.withDetail`, всегда от `rawSegments` + `words` с материализацией правок — идемпотентно). Выбор уровня — сессионный `LibraryModel.detail` (не настройка и не параметр запроса: в тело записи уходят только `rawSegments`/`words`, поэтому контроллер строит запрос с `.server`); попап — в шапке карточки «Транскрибация» у записи, в обеих раскладках.
- **LLM-анализ** (`prompt`, только builtin): пресеты либо свой промпт; тексты пресетов — ключи `transcribe.llm.prompt.*` в Localizable.strings (промпт следует языку интерфейса, включая язык ответа модели). Едет одним запросом с транскрипцией; ответ — конверт `{"transcription": {…verbose_json…}, "llm_output": строка|объект}`, декодер двухшаговый (`FileTranscriptionClient.decode` — internal, проверяется scratchpad-harness'ом на фикстурах; llm_output-объект от json_schema сериализуется в читаемый JSON, сам `json_schema` в UI не поддержан). Тело карточки рендерится нативно из Markdown (`UI/MarkdownView.swift`: `MarkdownView` + `MarkdownTableView` поверх чистого `Util/LightMarkdown.swift`; inline — через `AttributedString(markdown:.inlineOnlyPreservingWhitespace)`), без сырых `#`/`**`/`-`/`|`; `---` рендерится как отступ, а не линия. Ловушка таблиц: `Grid` в горизонтальном ScrollView не переносит текст и налезает строками — поэтому ручная вёрстка VStack/HStack с колонками фиксированной ширины; тот же недомер высоты ловит и `Text` — на КАЖДОЙ ячейке обязателен `.fixedSize(horizontal: false, vertical: true)` (fixedSize только на ScrollView не спасает, строки снова налезут). Вертикальные линии колонок — ОДНИМ оверлеем на всю высоту таблицы по известным ширинам (Divider внутри строки тянется только на высоту своей строки и до низа не доходит). Таблица уже карточки растягивается до её ширины (`fittedWidths` + `WidthReader` — GeometryReader фоном, не влияет на интринсик-высоту), шире — скроллится. Контейнер таблицы — серый тинт (`quinarySystemFill`, шапка — `quaternarySystemFill`) + скругление `DS.Radius.badge` на viewport (не на контенте — иначе углы уезжают при скролле). В чистый текст таблица уходит таб-разделённой. «Скопировать» кладёт в буфер ТРИ представления (`ClipboardManager.setRichText`): plain (`LightMarkdown.plainText` — общий источник с форматом «Обычный текст») + HTML (`LightMarkdown.html` — чистая функция, полный документ с `<body>`, проверена harness'ом) + RTF (best-effort конверсия из того же HTML через `NSAttributedString(html:)` — для NSTextView-полей, которые HTML из буфера игнорируют): приложения с rich-вставкой получают таблицы таблицами и списки списками. `<br>` от модели (перенос в ячейках GFM-таблиц) обрабатывается в `LightMarkdown`: рендер → `\n`, plain → пробел, html → настоящий тег. «Сохранить как…» — Markdown (.md, сырой `llm_output`) или .txt (`AnalysisSaveFormat`; PDF сознательно отложен). «Анализ» и «Транскрибация» сворачиваются общим `CollapsibleReveal` (`UI/Components.swift`). Повторного анализа на готовом результате НЕТ (осознанно убран): у API нет анализа готового текста, повторный запрос гонял бы файл целиком с повторной тарификацией — анализ выбирается только до запуска транскрибации.
- **Async-режим (только builtin)** — те же методы `FileTranscriptionClient`: `submitAsync` (тот же multipart на `{endpoint}/async`, сразу возвращает `job_id`), `fetchJobStatus`/`decodeAsyncStatus` (конверт `{job_id, status, created_at, completed_at, result, error}`; при `complete` поддерево `result` ре-сериализуется и уходит в общий `decode` — llm-конверт лежит ВНУТРИ `result`, проверено живыми вызовами), `waitForResult` (опрос раз в 4 с; сеть/429/5xx транзиентны — интервал растёт до 30 с и опрос переживает обрыв и сон Mac; 401/402/404/`status:"error"`/`badResponse` фатальны; дедлайн — постановка + 12 ч, `TranscriptHistoryStore.serverResultLifetime`). Результат на сервере живёт 12 ч; 404 опроса (`{"detail":"Job not found"}`) → `jobNotFound`. Особенность паритета: при `prompt` (LLM-анализ) сервер НЕ отдаёт `words` — в обоих режимах, sync и async (проверено живьём), это не регрессия. Битый файл отклоняется синхронно на сабмите (HTTP 400), до статуса `error` дело не доходит.
- **Библиотека транскрибаций** (бывшие «Недавние») — стор `Storage/TranscriptHistoryStore.swift` (синглтон, имя сохранено) поверх файлового слоя `Storage/TranscriptLibraryFiles.swift`, модели — `Storage/TranscriptLibraryModels.swift`. Раскладка в `AppDataFolder.currentURL/transcripts/` (переезжает с «Папкой данных» без правок `migrateToTarget`): `<id>/meta.json` — запись `FileTranscriptRecord`, **источник правды**; `index.json` — лишь КЭШ списка; `<id>/transcript.json` — `TranscriptBody` (машинный `StoredTranscript` не мутируется + `analyses` + `edits`); `<id>/text.txt` — плоский текст для поиска; `<id>/audio.m4a` — архив звука. Ловушки, каждая — про потерю данных: (1) пропавший/битый индекс ВОССТАНАВЛИВАЕТСЯ сканированием `meta.json` (битый сохраняется как `index.corrupt-*`), а не становится «пустой библиотекой»; sweep трогает только корзину `*.deleting-*`, `*.part` и папки без meta — папки с телами автоматически не удаляются никогда; (2) удаление — сначала rename папки в корзину, потом индекс; (3) у незавершённых записей индекса meta перечитывается на старте (крэш между записью meta и индекса); (4) весь дисковый I/O — одна последовательная очередь (порядок чтения после записи); `exit()` её не ждёт, поэтому `applicationWillTerminate` зовёт `flush()`; удаление = rename в корзину → индекс → `emptyTrash()` отдельным блоком; после переноса «Папки данных» — `freeze()` до перезапуска: стор (`isFrozen`) отклоняет новые транскрибации, удаления, архивацию, переименование и «Стереть всё аудио» (последние два когда-то меняли только память: запись пропускалась, и после перезапуска возвращались старые заголовки и целое аудио) (синхронное создание папки архива иначе воскресило бы стёртую старую папку, и возврат на путь по умолчанию упал бы с `targetNotEmpty`); (5) миграция журнала v1 `transcripts.json` синхронна в `init` (до `prune`/`resumePendingJobs`), идемпотентна по флагу `migratedFromV1`, легаси переименовывается в `transcripts.v1.bak` (удаляется через 14 дней). Лимита 50 больше нет — остаётся только срок хранения. Источник правды анализа — `TranscriptBody.analyses` (анализ Nexara из запроса — первый элемент); `llmOutput` в результат подставляет `makeResult` из анализов, поэтому удалённый анализ не всплывает. Показанная запись — `TranscriptDocument` (`UI/Main/Library/`), фаза контроллера — `.done(recordID:)`: копии результата в фазе нет, вывод (нарезка + словарь для файлов) мемоизирован документом. Запуск — `FileTranscriptionController.start(source:params:target:)` на снимке `FileTranscriptionParams` (все Nexara-гейты — от его `providerID`, маршрут — `SettingsStore.resolveRoute(providerID:)`: удалённый пресет — ошибка, а не тихий уход на встроенный сервис); `jobID` персистится ДО проверки отмены (иначе оплаченная задача теряет id). Архив звука (`Audio/SourceAudioArchiver.swift`, AAC 24 кбит/с 16 кГц mono, у видео только звук; тумблер `saveTranscriptAudio`, по умолчанию ВКЛ) — задача стора, отмена распознавания её не убивает; фиксация `.part` → `audio.m4a` только если meta записи ещё на месте. Поиск — `Util/LibrarySearch.swift` (регистр и ё=е, но НЕ `diacriticInsensitive` — он склеил бы «й» и «и») + actor `Storage/TranscriptTextIndex.swift` (ленивые тексты из `text.txt`). События: `finished` (готово/ошибка, которую пользователь ждал; безнадёжные записи на старте — `notify: false`) и `bodyChanged`. Recovery — `resumePendingJobs()` один раз на старте (`AppDelegate`): sync-сироты кастомных сервисов → «прервано перезапуском», builtin старше 12 ч → «результат истёк» без сети, остальные добираются фоновыми Task со стаггером 0.5 с (лимит Nexara 10 rps); credentials ВСЕГДА builtin (незавершённая async-задача — нексаровская, даже если пользователь переключил сервис), результат — только в стор, фаза контроллера остаётся idle. UI — секция «Библиотека» (см. ниже). Срок хранения — `TranscriptRetention` (`Storage/Retention.swift`; 12/24/48/72 ч, 7/30 дней, всегда). Дефолт — «всегда» через `TranscriptRetention.resolve(stored:)`: ключ пишется только при явном выборе (`didSet`), поэтому его отсутствие = «не выбирал» (прежний дефолт 12 ч был согласован с жизнью результата на сервере, пока журнал был списком «недавних»; у библиотеки смысл другой). Сокращение срока в «Расширенных» подтверждается алертом, если под новый срок попадают записи (удаление безвозвратно, вместе с аудио и анализами); чистка завершённых записей — на старте и в `.onChange`. Готовность сервиса на странице «Транскрибация» мемоизирована (`@State hasKey`, чтение ключа `Task.detached` в `.task(id: providerID)`) — прежний вызов `isServiceReady` из тела читал Keychain синхронно на каждой перерисовке.
- **Спикеры и правка текста** (`Util/TranscriptEdits.swift`; UI — `UI/Main/Library/SpeakerEditingViews.swift` и `TranscriptSegmentsView`) — переименование и слияние спикеров, переназначение реплики (или её части), правка текста реплики с возвратом. Правки живут в `TranscriptBody.edits: TranscriptEdits?` поверх НЕмутируемого `transcript` (ручной декодер тела читает их через `try?`, внутри массивы — поэлементно `Lossy`, пересекающиеся якоря отбрасываются: битая правка не стоит расшифровки) и применяются ЕДИНСТВЕННОЙ точкой `TranscriptBody.makeResult` → `TranscriptResult.withEdits(_:detail:)` (через неё же `withDetail`): показ, копирование, экспорт (`LibraryModel.exportResult`), `text.txt`/поиск и сводка (`saveBody`), будущий вход анализа (`TranscriptFormatter.llmTranscript`) — обходить её нельзя. Якорь правки — `EditAnchor.words` (диапазон индексов ИСХОДНЫХ слов) или `.segment(i)` для бессловных результатов (Nexara с анализом ИИ): правка переживает любую детализацию, а «вернуть» = удалить правку. Правки материализуются ПОД сплиттером (`materialize` → `TranscriptSegmentSplitter.splitWithSources` → `targets`): слова раздаются исходным сегментам тем же `assignWordRanges`, правка текста подставляет свои токены (токенизация — тем же правилом, что `joinWords`; тайминги 1:1 при равном числе токенов, иначе пропорционально внутри отрезка), сегмент режется на куски по сменам спикера. Без правок — побитно прежний результат (страховка — старые тесты сплиттера). Непоправленный сегмент сохраняет серверный текст с пунктуацией; частичная правка сегмента собирает его текст из слов. Вью передаёт в правку `EditTarget` (адрес в исходниках + задетые правки), а не индекс строки: правка, задевшая чужую правку, ПОГЛОЩАЕТ её целиком (токены за границами строки — `prefix`/`suffix`), устаревший адрес отвергается `isValid`. Правка текста выравнивает переназначения внутри своего якоря под спикера первого слова (все её токены получают его — иначе спрятанное слиянием переназначение после «Отделить» лежало бы под правкой невидимым), а неприменимые к исходникам правки (битые данные: якорь через границу сегмента) документ отбрасывает перед валидацией (`sanitized`) — иначе они навсегда блокировали бы соседние реплики. Операции — только через `TranscriptDocument` (`renameSpeaker`/`mergeSpeaker`/`unmergeSpeaker`/`setSegmentText`/`revertSegmentText`/`reassignSegment`/`revertSegmentSpeaker`/`resetAllEdits`), сохранение — `store.saveBody` по Return или выбору в меню; счётчик `revision` растёт на каждую правку, включая сброс (для «анализ устарел»); при замороженной библиотеке (`isFrozen`) правки не принимаются. Слияния транзитивны без циклов (`merge` пишет только канонические id); имя влитого цель ПОКАЗЫВАЕТ, но не хранит (`label` берёт его из `mergedIDs`) — скопированное имя после «Отделить» осталось бы у обоих, и «по спикерам» склеило бы их снова; «по спикерам» группирует по ОТОБРАЖАЕМОМУ имени; цвет считается по исходным id, затем переназначения и цели слияний (слияние не перекрашивает цель); `SpeakerName.index(of:)` принимает только до 6 ASCII-цифр — битый id с диска («speaker_-1») иначе дал бы отрицательный индекс палитры (краш) или переполнение; «Новый спикер» — `SpeakerName.nextID` с учётом ключей слияний и имён (иначе новый спикер получил бы id влитого). Словарь для файлов применяется И к правленому тексту, а редактор правит текст ДО словаря (`TranscriptDocument.source(detail:)`). «Распознать заново» правки не переносит (новая запись, id диаризации не совпадают). Ловушки UI: `.textSelection(.enabled)` съедает двойной клик — у редактируемых строк её нет (копирование — «Скопировать реплику»); бэйдж спикера — `Button` + `.popover`, НЕ `Menu`; состояние редактора — у строки (`@State`: ввод не перерисовывает список), по потере фокуса, перенарезке и уходу строки из ленивой ленты правка СОХРАНЯЕТСЯ, пустое не сохраняется; кнопки редактора `.focusable(false)` — иначе при полном доступе с клавиатуры клик по «Отмена» забрал бы фокус у поля и сохранил; пока у строки открыт редактор или поповер спикера, клавиши плеера и Esc «назад» молчат, а лента НЕ следует за плеером (`segmentInteractions` у `TranscriptRecordView` → `suspendsFollow`): автопрокрутка выгрузила бы строку из ленивой ленты и сохранила недописанное; после Return/Esc фокус возвращается на корень записи; устаревший адрес при сохранении (реплику сбросили или вернули иначе, `EditOutcome.stale`) оставляет редактор открытым с черновиком; меню «⋯» строки создаётся с первого наведения и дальше живёт (лента страницы «Транскрибация» не ленивая — сотни AppKit-меню разом; убирать по уходу курсора нельзя — курсор уходит в открытое меню); контекстное меню строки перекрывает меню списка, поэтому в нём есть «Скопировать всё»; поповер спикера по клику мимо сохраняет имя, Esc — отмена; чтение тела с диска не затирает в кэше стора свежее тело, сохранённое, пока чтение стояло в очереди (`loadBody`).

- **Плеер** — общий `RecordingPlayer` (одна запись звучит на всё приложение): `play(url:recordID:from:)`, `ensureLoaded` (слайдер и ±5 с работают до первого Play), `skip(by:)`, `rate` — `enableRate` ДО `prepareToPlay`, иначе скорость молча не меняется; `toggle` истории сбрасывает скорость в 1. Ловушка тика 20 Гц: запись НЕ наблюдает плеер. Активный сегмент считает `SegmentFollower` (бинарный поиск `Util/SegmentTimeline.swift`, публикует только смену индекса) — он лежит у записи в `@State`, а не `@StateObject`, иначе вся запись перерисовывалась бы на каждую смену сегмента; наблюдают его только список сегментов (строки `Equatable`) и плеер-бар (отдельная вью). Автоследование — `ScrollViewReader` при `followPlayback && isPlaying`, Reduce Motion — без анимации; ручная прокрутка выключает его на macOS 15+ (`onScrollPhaseChange` под `#available`), на 14 — тумблер «Следовать». Звук останавливает сама запись в своём `onDisappear` (`stopIfCurrent`): безусловный `stop()` на корне секции гасил бы воспроизведение, уже запущенное в следующей секции (`onDisappear` уходящей вью приходит после вставки новой). Открытая запись, удалённая мимо детали (срок хранения), закрывается сама.
- **Клавиши детали** — `.focusable()` + `.focusEffectDisabled()` + `.onKeyPress` на корне (пробел, ←/→, Esc), ⌘[ — «назад», ⌘F — поиск (невидимая кнопка с сочетанием). НЕ скрытая кнопка с `.keyboardShortcut(" ")`: key equivalent перехватил бы пробел и в полях ввода. Переименование (строка списка и шапка записи): Enter и клик мимо — сохранить, Esc — отмена; выход единый, повторный вызов (фокус уходит вслед за Esc) ничего не сохраняет. Черновик строки списка — в `LibraryModel.renameDraft` (строка ленивой ленты пересоздаётся при прокрутке); начать переименование другой строки или открыть запись — значит сначала сохранить набранное (`beginRename`/`open` → `commitRename`): кнопки на macOS фокус у поля не забирают, и сохранение по потере фокуса туда не доходит. Шапка записи по той же причине сохраняет перед «назад» и при уходе из секции. Фокус корня детали ставится со следующего цикла (`onAppear` + `DispatchQueue.main.async`), иначе клавиши молчат до первого клика. Якорь автопрокрутки — свой тип `SegmentAnchor`, НЕ голый `Int`: у блоков Markdown анализа в том же ScrollView id — те же смещения 0…N.
- **Однократная плашка** «записи теперь хранятся всегда» — только если в библиотеке есть записи из журнала v1 (`store.hasRecordsFromV1` — у них нет `params`; флаг индекса `migratedFromV1` для этого НЕ годится: он ставится и на новой установке, где журнала не было), пока срок не выбран явно (`isTranscriptRetentionExplicit`) и плашку не закрыли (`libraryRetentionNoticeDismissed`); «Изменить срок» → `WindowManager.showAdvancedSettings()` (запрос забирает `GeneralSectionView.onAppear`, под-страница — её `@State`).
- **«Повторить»** (карточка ошибки/отмены, `RecordRetryRow`) — план выбирает чистый `Util/RetryPlanner.swift`, первое подошедшее правило: `repoll` (есть `jobID`, не старше 12 ч от `submittedAt ?? date`, неудача преходящая или её нет: `failure ∈ {nil, network, auth, noFunds}` — после 404, `status=error`, пустого или неразборчивого ответа опрос вернул бы то же самое, такие записи переотправляются, иначе «Повторить» зациклился бы) → `serviceUnavailable` (пресет удалён → шит «Распознать заново») → `rerunOriginal` → `rerunStoredAudio` → `needsFile` (`.fileImporter`; выбранный файл становится новым `sourcePath`). `store.canRepoll` делегирует планировщику — правило одно. Повтор НА МЕСТЕ (`target: .reuse(id, sourcePath:)`) по сохранённым `params` (у записей v1 — параметры страницы), глобальный сервис не переключается; сетевой повтор (`billed`) подтверждается алертом `RecordAlert.retryBilled`. Читаемость исходника проверяется по клику и ВНЕ главного потока (TCC «Рабочего стола» заблокировал бы UI); подпись кнопки строится только из метаданных записи. Повторный опрос — задача стора, мимо контроллера, поэтому доступен и во время чужой транскрибации; «Отмена» у такой записи — `store.cancelRecovery`, а опрос перед `markDone`/`markError` проверяет, что запись всё ещё `.inProgress` (отмена могла опередить регистрацию задачи).
- **«Распознать заново…»** (`RetranscribeSheet`, `.sheet` у детали) — сервис (по умолчанию текущий), язык, диаризация с плашками; без анализа ИИ (`withoutLLM`); ключ — `Task.detached` в `.task(id: providerID)`, не `isServiceReady` в теле. Результат — НОВАЯ запись (`target: .new(parentID:title:sourcePath:)`) с заголовком исходной, правки не переносятся; источник — оригинал, если читается, иначе архив; звук — копия архива исходной (`store.inheritAudio`, задача стора, без перекодирования AAC → AAC; только при `saveTranscriptAudio`). Шит и `.fileImporter` повтора висят только на раскладке `.full`: у страницы «Транскрибация» свой `.fileImporter`, вложенные SwiftUI обслуживает ненадёжно.
- `FileTranscriptionController.start` возвращает `StartOutcome` (`started`/`busy`/`rejected`) и при отказе фазу НЕ трогает: повтор из библиотеки показывает причину у своей кнопки, а `transcribe()` страницы переводит отказ в `.error`. Запуск из библиотеки (`Target.isFromLibrary`) на время работы показывает на странице свой прогресс (дропзона — имя того, что распознаётся, `runningSource`), а по окончании — успех, ошибка, отмена — возвращает страницу к фазе до запуска (`pagePhaseBeforeRun`): итог виден в самой записи, выбранный на странице файл и показанный результат не затираются.
- Фоновые задачи стора (`audioTasks`, `recoveryTasks`): регистрацию отменённой задачи убирает ОТМЕНИВШИЙ (удаление, стирание аудио, «Отмена», повторный опрос, заморозка), поэтому задача в конце чистит реестр только если сама не отменена — иначе затёрла бы новую. Вторая архивация поверх идущей не стартует: два кодировщика в один `.part` стёрли бы друг другу файл. Опрос после чтения ключа берёт только записи, всё ещё ждущие результата (отмена или удаление могли прийти, пока висел диалог Keychain).
- На странице «Транскрибация» вместо списка — `LibraryRecentStrip` (3 последние записи и «Вся библиотека»); удаление, поиск и экспорт живут только в библиотеке.

**Локальный ИИ-анализ** (`Local/LocalLLMEngine.swift`, `Util/{TranscriptLLMInput,LLMChunker,AnalysisPromptBuilder,AnalysisTemplate,LLMText,TimestampLinker}.swift`, `UI/Main/Analysis*.swift`) — отчёт по готовой расшифровке пишет языковая модель на этом Mac. От сервиса распознавания НЕ зависит: анализировать можно записи любого происхождения, в том числе расшифровки Nexara. Анализ Nexara, заказанный вместе с распознаванием (`prompt` в запросе), остался как был — это отдельная функция, просто её результат лежит в том же списке `TranscriptBody.analyses`.
- **Сборка.** llama.cpp подключён `binaryTarget`'ом с пином на КОНКРЕТНЫЙ релиз (`b10909`, url + checksum в `Package.swift`; `Package.resolved` бинарные таргеты не хранит, поэтому ключ кэша SwiftPM в CI включает и `Package.swift`). Релизы llama.cpp выходят по нескольку раз в день и меняют C-API без semver — обновление пина это осознанное действие с прогоном `./build.sh` и smoke анализа. Срез macOS обязан быть `macos-arm64_x86_64`: иначе `--arch x86_64` не слинкуется; guard `lipo` в `build.sh` роняет сборку сразу. `llama.framework` — ДИНАМИЧЕСКИЙ фреймворк с install name `@rpath/…`, поэтому: rpath `@executable_path/../Frameworks` в `linkerSettings` таргета DOKA (`unsafeFlags` допустимы — DOKA корневой пакет), `cp -RX` из `.build/artifacts` в `Contents/Frameworks` ДО `xattr -cr`, вырезание `Headers`/`Modules` ВМЕСТЕ с симлинками верхнего уровня (висячий симлинк роняет `codesign --strict`) и подпись фреймворка ПЕРЕД подписью приложения (у ggml-org он linker-signed, а x86_64-срез вовсе без подписи). Metal-кернелы встроены в бинарник (`GGML_METAL_EMBED_LIBRARY`), докладывать в бандл нечего. Ловушка `build.sh`: `otool -l | grep -q` под `pipefail` даёт ЛОЖНЫЙ отрицательный ответ — grep закрывает пайп на первом совпадении, otool получает SIGPIPE; нужен `grep … >/dev/null`.
- **Модель** — `Local/LLMModelSpec.swift`, единственный источник ссылки, размера, sha256, окна контекста и семплинга: смена модели = смена `LLMModelSpec.current` (файл прошлой подчистит sweep). Сейчас Qwen3.5-4B Q4_K_M (Apache-2.0, 2.7 ГБ, пин ревизии HF). Модель гибридная thinking — `assistantPrefill` дописывает ПУСТОЙ блок `<think>\n\n</think>\n\n` после открывающего тега ассистента: иначе она тратит минуты и сотни токенов на рассуждения, которые всё равно вырезаются. `n_ctx` = min(16384, обученное окно, политика ОЗУ): на маке с памятью < 15 ГиБ — 8192.
- **Скачивание** — `LocalAsset.llm` (НЕ `LocalModel`: в пикер «Сервис» и в `providerID` языковая модель попадать не должна) плюс свой `Local/HTTPModelDownloader.swift`: один файл по HTTPS с пином ревизии, докачка по `resumeData` (5 попыток с растущими паузами), потоковый SHA-256 кусками по 8 МБ, атомарная установка через `.incoming-<uuid>.part`. Хэш проверяется ОДИН раз, при установке; `isOnDisk(.llm)` — дешёвый stat по размеру. `requiresAppleSilicon = true`: официальный x86_64-срез llama.cpp собран без AVX/AVX2/FMA, и Q4_K-матмулы 4B-модели на голом SSE — это десятки минут на получасовую запись; барьер, как у Parakeet, в `LocalModelStore.download`, в UI контрол виден, но неактивен. Ловушка sweep: `sweepLLMFolder` (огрызки `.incoming-*` и файл ПРОШЛОЙ модели) отсекает файлы свежее старта процесса — фоновая задача из `init` иначе снесла бы закачку, начатую пользователем сразу после запуска.
- **Движок** — `actor LocalLLMEngine` со СВОИМ последовательным исполнителем на `DispatchSerialQueue`: `llama_decode` — это секунды синхронной работы Metal внутри одного вызова, в кооперативном пуле он занимал бы чужой поток. `import llama` заперт в этом файле (как WhisperKit и FluidAudio в своих). Только не-deprecated API (`llama_model_n_ctx_train`, `llama_vocab_is_eog`, `llama_init_from_model` — гейт предупреждений); `llama_sampler_sample` сам принимает токен, отдельный `accept` не нужен; prefill батчами по 512 с `Task.checkCancellation` между ними (отмена срабатывает за доли секунды). Ловушка лога: фильтр `level >= GGML_LOG_LEVEL_WARN` НЕ годится — за `ERROR`(4) идёт `CONT`(5), которым печатаются точки прогресса загрузки, и лог забивался бы сотнями строк «.»; сравнивать надо ровно с `WARN` и `ERROR`. Бан CJK-токенов считается один раз при загрузке проходом по словарю и включается, когда язык ответа не zh/ja/ko: Qwen на длинном русском контексте сваливается в китайский.
- **Владелец** — тот же `LocalEngineManager`, но со СВОИМ таймером простоя (3 мин) и НЕ в `unloadNow()`: его зовут смена речевой модели и `didSet providerID`, и языковая модель не должна умирать от смены сервиса распознавания. На маке с ОЗУ < 15 ГиБ загрузка LLM сначала освобождает речевой движок, а старт диктовки на ЛОКАЛЬНОМ сервисе отменяет идущий анализ («Анализ прерван диктовкой») — диктовка важнее. Удаление модели гасит анализ и выгружает движок.
- **Вход модели** — `TranscriptLLMInput`: строки «[м:сс] Имя: текст» тем же форматом, что экспорт «тайм-коды + спикеры» (`TranscriptFormatter.llmTranscript`), его же разбирает `TimestampLinker`. Детализация входа ФИКСИРОВАННАЯ (`TranscriptLLMInput.detail == .medium`), а не пользовательская: иначе смена детализации меняла бы отпечаток и все анализы разом становились «устаревшими»; `.server` не годится — Parakeet отдаёт один сегмент на всю запись, и нарезать такую строку нечем. Подряд идущие реплики одного спикера склеиваются до 45 с. Из текста вырезаются `<|` и `|>`: токенизация идёт с `parse_special`, и расшифровка, где кто-то произнёс «<|im_start|>», подменила бы роль в промпте. Словарь замен к входу применяется (тот же выходной слой, что у показа), а отпечаток считается от текста БЕЗ словаря: словарь — линза пользователя, его тумблер не должен объявлять анализы устаревшими.
- **Длинные записи** — `LLMChunker`: план частей по токенам с перекрытием ~200, строки НЕ режутся (строка = реплика), план всегда движется вперёд, потолок 40 частей. Map (конспект части, резерв ответа 640) → reduce (сведение, резерв 1536). Глубже одного уровня сведения не идём — это пересказ пересказа; не влезло — `analysis.error.tooLong`.
- **Шаблоны** — `AnalysisTemplate` + `BuiltinAnalysisTemplate` (резюме, протокол встречи, задачи, конспект лекции, интервью, главы). Встроенные НЕ хранятся на диске: структура (формат раздела, колонки таблицы, нужны ли тайм-коды) в коде, тексты — в `.strings`, поэтому они следуют языку интерфейса. Один анализ на приложение; стадии `loadingModel/reading/part/combining/writing`; живой текст публикуется не чаще раза в 120 мс (разбор Markdown на каждый токен съел бы больше, чем сама генерация); отмена НИЧЕГО не сохраняет. `update(recordID:)` пишет фазу, только если идёт анализ той же записи, — отменённый анализ не воскресает запоздавшим событием движка. Взаимоисключение — только с ЛОКАЛЬНЫМ распознаванием (конкуренция за ускоритель); сетевое распознавание и диктовка анализу не мешают.

**Уведомления о файлах** (`Managers/FileTranscriptionNotifier.swift`) — «Транскрибация готова» / «не удалась» по `TranscriptHistoryStore.finished` (эмитят `markDone` и `markError(notify: true)`: путь контроллера, добор, повторный опрос; безнадёжные на старте — `notify: false`, отмена — не событие). `install()` — в `applicationWillFinishLaunching`: делегат обязан стоять до завершения запуска (клик при незапущенном приложении), а события `resumePendingJobs` должны застать подписку. `UNUserNotificationCenter` — только за `isSupported` (собранный `.app`; у голого бинаря и xctest `current()` бросает исключение); методы делегата `nonisolated` и в completion-варианте (у async-перевода системный completion зовётся вне главного потока), через границу акторов идёт только UUID. Разрешение спрашивается лениво — в `start()` и при включении тумблера `SettingsStore.notifyFileTranscription` (карточка «Библиотека транскрибаций» в «Расширенных»; при запрете — «Открыть настройки»), на старте никогда. **История** (`UI/Main/HistorySectionView.swift`, секция `history`) — журнал распознанных диктовок поверх `HistoryStore`. Запись (`TranscriptionRecord`) кроме базовых полей (`id/text/date/duration/language` — их трогать нельзя, читает бэкфилл `StatsStore`) несёт **опциональные** метаданные новых записей (`speechDuration`, `model`, `provider`, `microphone`, `transcriptionTime`, `audioFileName`); у старых записей они `nil`, UI и метрики деградируют мягко (`decodeIfPresent`).
- **Аудио истории** — `Storage/AudioStore.swift` (синглтон): после распознавания `DictationController` кодирует исходный WAV в AAC/m4a (`audio/<record-id>.m4a` в Application Support/DOKA, ~24 кбит/с) ДО удаления временного WAV — **но только если включён тоггл `SettingsStore.saveAudio` (по умолчанию ВЫКЛ)**; иначе `audioFileName == nil`. `id` записи фиксируется заранее, поэтому имя файла и `audioFileName` гарантированно совпадают. Намеренно **не** `@MainActor` (`@unchecked Sendable`): кодирование — тяжёлая CPU-работа вне главного потока. Жизненный цикл файлов привязан к `HistoryStore`: удаление записи / `clear` / вытеснение за лимит 200 убирают и аудио, а `pruneOrphans` при загрузке подчищает файлы, осиротевшие после крашей между кодированием и сохранением json. URL файла записи — хелпер `TranscriptionRecord.audioURL` (проверяет наличие на диске).
- **Настройки хранения** — карточка «Данные» в разделе «Основные» (`GeneralSectionView`): тоггл `saveAudio`, срок хранения `AudioRetention` (`Storage/Retention.swift`; 1/3/7/14/30 дней / всегда) и кнопка «Стереть всё аудио» (`AudioStore.removeAll()`, с подтверждающим `.alert`, повешенным на карточку — иначе конфликт со вторым `.alert` смены языка на корне формы). Просроченное аудио чистит `HistoryStore.pruneAudio(olderThan:)` — на старте (`AppDelegate`) и при смене срока (`onChange`); удаляются только m4a, тексты записей остаются. В истории плеер и кнопка «Показать в Finder» гейтятся `saveAudio` (выключен или стёрто → аудио в карточках не показывается, кнопка Finder пропадает).
- **Воспроизведение** — `Audio/RecordingPlayer.swift` (синглтон, `@MainActor` `ObservableObject` поверх `AVAudioPlayer`): один активный плеер на приложение (разворачивание другой карточки останавливает предыдущую), двусторонняя привязка к слайдеру — флаг `isScrubbing` не даёт тикеру перетереть позицию во время перетаскивания.
- **Карточка, инспектор, мультивыбор** — карточка раскрывается в `HistoryDetailInspector` (метаданные записи + «Показать в Finder»); режим выбора даёт пакетные удаление / экспорт / анализ.
- **Лента карточек** — карточки на `glassSurface(forceMaterial: true)`: Liquid Glass у пачки glassEffect-вью внутри ScrollView (macOS 26) рисует под ними общий серый бэкдроп на весь viewport с резкими углами — в светлой теме это заметная плита, не возвращать. Лента тянется до самой нижней кромки окна (обрезка краем окна, а не «в воздухе»), сверху карточки при прокрутке растворяются градиентной маской высотой `topFade` с таким же top-inset контента (в покое первая карточка под маску не попадает). Ловушка: системный `scrollEdgeEffectStyle(.soft)` здесь не работает — без настоящего safe-area-бара над скроллом эффект не рисуется вовсе, а `safeAreaPadding(.top)` опускает overlay-скроллбар «в воздух». Скроллбар выключен совсем (`scrollIndicators(.never)`; `.hidden` недостаточно — при прокрутке колесом система его всё равно показывает).
- **Экспорт** — `Util/HistoryExport.swift` (чистые функции, тестопригодны): CSV по RFC 4180 (по мотивам VoiceInk; имена колонок машинные — это data-формат, не локализуются) и объединённый плоский текст.
- **Анализ производительности** — модальный `UI/Main/PerformanceAnalysisView.swift` (`.sheet`) по выбранным записям: сводные плитки, System Information (`SystemInfo` через `sysctl`) и разбивка по моделям/провайдерам с метрикой «во сколько раз быстрее реального времени» (= суммарное аудио / суммарное время распознавания). Чистые агрегаты — `PerformanceMetrics` (value-type, как `DashboardMetrics`); «анализируемыми» считаются только записи с `transcriptionTime > 0` и `duration > 0`, старые без latency сюда не попадают.

**Сервис** (`UI/Main/ServiceSectionView.swift`, секция `service`) — выбор активного сервиса, поля адреса/модели (только у кастомных пресетов) и ключ. Ключ попадает в Keychain ТОЛЬКО после успешной проверки живым запросом (`TranscriptionClient.validateKey`); единственное исключение — ошибка `.noFunds`: ключ верный, поэтому сохраняется, но статус показывает предупреждение о балансе.

**Словарь** (`UI/Main/DictionarySectionView.swift`, секция `dictionary`) — список правил `ReplacementRule` (`from` → `to`, флаги `enabled` и `matchInsideWords`) поверх `SettingsStore`. Применение — `ReplacementEngine.apply` (`Text/ReplacementEngine.swift`, чистый): регистронезависимо, длинные шаблоны первыми (иначе короткие разорвут длинные), строка пересобирается без переиспользования индексов — вставленный текст повторно не сканируется, поэтому нет ни крашей на устаревших индексах, ни зацикливания при `to ⊇ from`. **Совпадение — по целому слову** (прежняя подстрока превращала «документ» в «DOKAмент» на примере из самого UI): символ слова — `isLetter || isNumber` любой письменности, граница проверяется только с той стороны, где шаблон начинается/кончается символом слова (у «э-э, » или «:)» на пунктуационном краю ограничения нет); при неудачной границе поиск продолжается с `index(after: lowerBound)`, а не с конца совпадения — иначе пропустится перекрывающееся («дада да»). С границами правила идемпотентны («ai» → «OpenAI» не пожирает свой результат) — это важно для словаря на выходном слое файлов, который применяется на каждом рендере. `matchInsideWords` (кнопка «Внутри слов» в строке правила) возвращает поиск подстроки для правил-нормализаторов вроде «ё» → «е». Ловушка Codable: у `ReplacementRule` РУЧНОЙ `init(from:)` с `decodeIfPresent` — синтезированный декодер не подставляет дефолт для отсутствующего ключа, и старый словарь без `matchInsideWords` уронил бы `try?` в `SettingsStore.init`, молча обнулив все правила; декодер живёт в расширении, чтобы сохранился memberwise-init.

Уровень микрофона для ВСЕХ панелей (`AudioRecorder`) считается НЕ по dB: логарифмическая шкала сжимает обычную речь в узкий диапазон и панели выглядят вялыми. Уровень строится по линейным RMS и пику с узкими рабочими окнами плюс гамма 0.72, сглаживание асимметричное (быстрый подъём, медленный спад), буфер тапа 1024 кадра (~21 мс) — реакция за доли секунды. ЛОВУШКА: `speechTime` для дашборда считается по СТАРОЙ dB-кривой (`speechLevel`) — её порог `speechLevelThreshold` калиброван именно под неё, и если увести статистику на новую кривую, поедут «Скорость речи», сэкономленное время и множитель. Панели поверх этого применяют общую огибающую `Float.envelope(toward:attack:release:)` (`Util/Smoothing.swift`) — симметричная EMA либо съедает пики голоса, либо дёргается на паузах. Амплитуда в `WaveformBars` идёт через `drive` и колебание с ненулевым полом: при `wave` от нуля половина хода теряется и полоски дрожат у пола.

**Звук** (`UI/Main/SoundSectionView.swift`, секция `sound`, в сайдбаре — в группе «Настройки»): буст громкости микрофона на время записи — `Audio/MicrophoneVolumeBooster.swift` (CoreAudio HAL, только системное устройство по умолчанию, best-effort — устройства без записываемого volume молча пропускаются; `beginBoost` после старта записи, `endBoost` — в `DictationController.transition` при уходе из `.recording`, одна точка покрывает стоп/отмену/ошибку/смену устройства); удаление тишины — `Audio/SilenceRemover.swift` (чистая пост-обработка WAV: окна 20 мс, порог −40 дБ, паддинг 0.24 с, guards «результат < 0.4 с или выигрыш < 10% → оригинал»; режется ТОЛЬКО копия для API — история, статистика и m4a работают с оригиналом); громкость сигналов — `SettingsStore.soundVolume`, `SoundPlayer` обязан держать ссылку на играющий `NSSound` (иначе ARC освободит до конца проигрывания).

**Расширенные настройки** (`UI/Main/AdvancedSettingsView.swift`) — под-страница «Общих»: drill-in через `@State showAdvanced` с МГНОВЕННОЙ сменой экрана (без слайдов; NavigationStack в проекте не используется). Внутри: «Показывать иконку в Dock» (`showDockIcon` — `NSApp.setActivationPolicy` на лету в didSet + `WindowManager.refocusMain()`, старт читает настройку в `main.swift`), «Открывать окно при запуске» (`openWindowAtLaunch`, по умолчанию вкл), «Папка данных» — `Storage/AppDataFolder.swift`: ЕДИНСТВЕННЫЙ источник пути данных для всех сторов (кастомный путь в UserDefaults `dataFolderPath` читается напрямую, без SettingsStore); перенос — copy→switch→delete с откатом, применение ТОЛЬКО через перезапуск (`Util/AppRelaunch.swift`, общий с restart-алертом смены языка). Ловушка путей: `standardizedFileURL`/`resolvingSymlinksInPath` НЕ срезают `/private` у несуществующих путей — сравнение существующего источника с несуществующей целью слепнет, поэтому в `AppDataFolder.canonicalPath` резолвится самый глубокий существующий предок. Карточка «Библиотека транскрибаций» — срок хранения (`transcriptRetention`, сокращение подтверждается алертом), «Сохранять аудио файлов», «Уведомлять о готовности», занятое место, «Показать в Finder» и «Стереть всё аудио транскрибаций»; отдельного переноса у библиотеки нет — она живёт в «Папке данных». Cmd+W/Cmd+M работают только благодаря пунктам меню «Окно» в `AppDelegate.installEditMenu` (без пунктов меню такие клавиши в macOS не работают вовсе); `WindowManager.showMain` делает `deminiaturize` — иначе свёрнутое окно не вернуть из меню-бара.

**Клавиши** (`UI/Main/HotkeysSectionView.swift`): кроме toggle/paste — push-to-talk (`onKeyDown`/`onKeyUp`, методы `pushToTalkDown/Up` контроллера), глобальные `openMainWindow`/`openHistoryWindow` — намеренно БЕЗ дефолтов (глобальный Cmd+, отобрал бы «Настройки» у всех приложений системы); пункты меню-бара отражают их автоматически через `NSMenuItem.setShortcut(for:)`. Кнопка мыши: `SettingsStore.mouseShortcutButton` (−1 — выкл), NSEvent-мониторы `.otherMouseDown` в `HotkeyManager` (только кнопки ≥ 2 — левую/правую не трогать), на время захвата в рекордере глобальный обработчик глушится флагом `MouseShortcutCapture.isCapturing`. Рекордер мыши — нативный `NSSearchField`, как внутри KeyboardShortcuts (только так совпадает вид); ловушка: `isEditable = false` делает подложку поля бледнее — поле остаётся editable, ввод блокируется `acceptsFirstResponder=false` + `refusesFirstResponder`.

**Дизайн-система** (`UI/DesignSystem/`): токены `DS` (`DesignTokens.swift` — акцент, радиусы, отступы, анимации, палитра mesh-фона, плюс палитры `Aurora` индиго/космос, `ScreenGlow` свечения краёв и `coral`) — единственный источник правды, новый UI не хардкодит цвета/числа. Всё «стекло» — через модификатор `glassSurface()` (`GlassSurface.swift`): macOS 26 — Liquid Glass, 14/15 — материал со светящейся кромкой, Reduce Transparency — непрозрачный фон; `forceMaterial` — страховка для контекстов, где glassEffect ведёт себя плохо (borderless NSPanel). Там же `MeshBackground`, `ButtonStyles`, `SettingsForm` и `DokaLogoView` (`DokaPetalsShape` — фирменный логотип-крест, контур перенесён 1:1 из векторного исходника `DOKA_LOGO/Vector_DOKA.svg`). Анимации — токены `DS.Anim` (`section`/`hover`/`control` + длительности `panelShow`/`panelHide`); per-style spring рекордеров намеренно остаются литералами. Общие переиспользуемые элементы вне DesignSystem: `CopyButton`, `EscKeyCap`, `CollapsibleReveal` (сворачивание длинного контента с затуханием, `UI/Components.swift`), `LocalAssetStatusView(asset:name:)` (весь ряд состояний скачиваемого локального ресурса — кнопка, прогресс с отменой, «Подготовка модели…», удаление с подтверждением; `name` подменяет слово-статус именем ресурса и по умолчанию `nil`, поэтому «Сервис» и строка диаризатора остаются со словами статуса) и `HelpBubble` («вопросик» с поповером, `SettingsForm.swift`); контролы расшифровки — `OptionTile`/`SaveAsMenu`/`SaveFormat`/`TextFileSaver`/`SpeakerPalette` (`UI/Main/TranscriptionControls.swift`, общие у страницы «Транскрибация» и записи библиотеки); EMA-сглаживание уровня микрофона — единый хелпер `Float.smoothed(toward:response:)` (`Util/Smoothing.swift`) для всех панелей; формат таймера/плеера mm:ss — `clockMMSS` (`Util/TimeFormat.swift`; не путать с `formatStatDuration` для дашборда и `TranscriptFormatter.clock` для тайм-кодов расшифровок).

**Онбординг** — это секция `home` («DOKA») главного окна. Показывается при старте, пока не выданы оба разрешения и не готов сервис (`SettingsStore.isServiceReady`). Третий шаг — выбор сервиса распознавания сеткой из трёх плиток (`ServiceChoice` / `ServiceChoiceTile`, файловый уровень `HomeSectionView.swift`): облачный (поле ключа, прежний блок) и две локальные модели, у которых прямо в шаге стоит `LocalAssetStatusView(asset: .speech(model), name: model.plainTitle)` — скачивание проходится целиком внутри онбординга, без похода в раздел «Сервис». Имена моделей: `LocalModel.plainTitle` («Whisper Large v3 Turbo», без «(Local)») для строки статуса, `shortTitle` («Whisper») для узкой плитки; `title` выводится из `plainTitle` и остаётся прежней строкой — она пишется в историю через `providerTagForHistory`. Пресеты «своего сервиса» отдельной плитки не имеют: они подсвечивают облачный вариант, а клик по уже выбранной облачной плитке гейтится `guard settings.isLocalService` — иначе выбранный пресет молча сменился бы на встроенный сервис. Эмбиент-фон секции — `FloatingWordsView` (всплывающие слова-приветствия на разных языках; намеренно НЕ локализуются — многоязычность и есть смысл).

### Неочевидные инварианты

- Глобальный Esc (`cancelRecording`) включается только на время записи/распознавания через `HotkeyManager.setEscapeEnabled` — иначе DOKA перехватит Esc во всей системе.
- **Перенос «Папки данных» останавливает ВЕСЬ пайплайн, а не только библиотеку.** У
  `HistoryStore`, `StatsStore` и `AudioStore` своей заморозки нет: путь они фиксируют
  один раз в `init` и создаются ДО переноса, поэтому продолжали бы писать в старую
  папку. Закрыто флагом `AppDataFolder.needsRestart` (ставится после успешного
  переноса): `DictationController.startRecording` отказывает с
  `transcribe.error.restartRequired`. Нет записи — нет и записей в историю,
  статистику и аудио. Гейт самого переноса (`AdvancedSettingsView.migrate`) ждёт
  покоя от четверых: файловой транскрибации, диктовки (`DictationController.isActive`),
  ИИ-анализа (`AnalysisController.isRunning`) и фоновых задач библиотеки.
- **Взаимоисключение «анализ ↔ локальное распознавание» — по маршруту ИДУЩЕГО
  прогона** (`FileTranscriptionController.runningUsesLocalEngine`), а не по глобальному
  `providerID`: запуск из библиотеки идёт по снимку `params.providerID`, и глобальная
  настройка к нему отношения не имеет. Гейт двусторонний: анализ не стартует поверх
  локального распознавания, локальное распознавание — поверх анализа. Сетевому
  распознаванию анализ не мешает, и наоборот.
- **Ленивая загрузка локальных движков: три инварианта на каждый слот.** (1) параллельные
  вызовы ждут ОДНУ задачу; (2) `defer` снимает регистрацию только СВОЕЙ задачи
  (`if loading?.task == task`) — безусловный сброс затирал запись другого запроса;
  (3) после `await` обязателен `guard`, что слот всё ещё ждёт именно эту задачу, иначе
  движок выгружается и бросается `CancellationError`. Третий пункт — не перестраховка:
  у `load()` WhisperKit, FluidAudio и llama.cpp кооперативных точек отмены НЕТ, задача
  доходит до конца, и без guard'а в памяти оставался бы движок удалённой модели.
  `unloadNow`/`unloadDiarizer`/`unloadLLM` обязаны отменять незавершённую загрузку, а
  `unloadIfCurrent` — смотреть и на `engine`, и на `loading` (во время загрузки `engine`
  ещё nil, и удаление модели в этот момент было полным no-op).
- **Ключ сервиса сохраняется по адресату, снятому ДО сетевой проверки**
  (`ServiceSectionView.KeyDestination`). Проверка идёт секунды, за это время можно
  переключить сервис — и ключ уезжал в аккаунт того сервиса, который оказался выбран
  к моменту ответа, вплоть до затирания ключа встроенного (платного) сервиса.
- **`keyUp` синтетической вставки уходит всегда.** Пауза между `keyDown` и `keyUp` —
  `try?`, а не `try await`: отмена между событиями оставляла клавишу V «зажатой» на
  уровне HID для ВСЕЙ системы. Отменённая вставка допустима, залипшая клавиша — нет.
- `Paster` перед синтетическим Cmd+V ждёт отпускания физических модификаторов хоткея (до 0.5 с) и проверяет secure input (поля паролей) — там вставка невозможна, текст остаётся в буфере. Восстановление прежнего буфера происходит через ~0.9 с и только если буфер никто не менял (`changeCount`); снапшот/восстановление всех типов данных буфера — `Paste/ClipboardManager.swift`.
- `AppDelegate.installEditMenu()` создаёт невидимое меню «Правка»: без него Cmd+C/V/X/A не работают в текстовых полях меню-бар-приложения.
- `LegacyMigration` — одноразовый перенос из старого приложения Whisper (`com.pitenin.whisper`): UserDefaults (включая хоткеи), ключ Keychain, история. Копирует, а не переносит.
- Анимации уважают Reduce Motion: в SwiftUI — через `accessibilityReduceMotion`, а `NSAnimationContext` сам его НЕ уважает — длительность вручную умножается на 0 (см. `RecorderPanel.animationDurationScale`).
- У вью плавающих панелей НЕ должно быть внешних теней/свечений (`.shadow` на корне): окно панели размером ровно с плашку и обрезает их своей квадратной границей — тёмные углы в светлой теме (уже ловили на «Студии» и «Авроре»).
- Пояснения к настройкам — через `SettingsRow(help:)` («вопросик» с поповером), а не `subtitle`: подписи под тогглами захламляют форму (конвенция пользователя). Тот же «вопросик» вне форм — переиспользуемый `HelpBubble` (`SettingsForm.swift`; `SettingsRow` рендерит подсказку им же).
- Синхронное чтение Keychain в пути запуска (`applicationDidFinishLaunching`) ЗАМОРАЖИВАЕТ всё приложение, если macOS показывает диалог подтверждения доступа к ключу (случается после пересборки бинарника): `SecItemCopyMatching` блокирует главный поток до ответа пользователя. Поэтому `resumePendingJobs` читает ключ лениво через `Task.detached`. Такое же синхронное чтение осталось в `AppDelegate` (`SettingsStore.currentAPIKey` при старте) — известное место: при висящем диалоге запуск блокируется там. По той же причине `isServiceReady` НЕЛЬЗЯ звать из тела SwiftUI-вью для сетевого сервиса (у него внутри `currentAPIKey`): онбординг мемоизирует результат в `@State keyStatus` и обновляет его по событию (`syncServiceState()` из `onAppear` и `onChange(of: providerID)`), а из тела спрашивает `isServiceReady` только для локального сервиса — там Keychain не участвует. Тело `HomeSectionView` перерисовывается на каждый процент скачивания модели, и прямой вызов дал бы сотню `SecItemCopyMatching` за загрузку.
- Чистую логику удобно верифицировать вне приложения: scratchpad-harness компилирует РЕАЛЬНЫЕ исходники (`swiftc main.swift <файлы из Sources>` + шим `L()`), так проверялись `SilenceRemover`, `TranscriptSegmentSplitter`, `MicrophoneVolumeBooster`, `AppDataFolder`, `decodeAsyncStatus`/`StoredTranscript` (фикстуры живых async-ответов) и живые ответы Nexara. Для UI есть стенд с рендером окна в PNG (`NSView.cacheDisplay`) — годится для геометрии и масок, но НЕ для стекла: glassEffect и материалы композитит оконный сервер, в офскрине они не рендерятся (серую плиту Liquid Glass так не увидеть), а `screencapture` из агентской сессии недоступен (нет TCC-права записи экрана) — живой вид проверяет только пользователь.
