# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

DOKA (Dock Operations Kit for Apple) — меню-бар-приложение macOS для голосовой диктовки: глобальный хоткей → запись с микрофона → транскрипция через OpenAI-совместимый API → автозамены по словарю → вставка текста в активное приложение. Бывшее имя проекта — Whisper (осталась миграция данных).

Репозиторий — `ippitenin/DOKA-macOS` (до переименования `ippitenin/DOKA`, GitHub перенаправляет старые URL): это версия для Mac. iOS-версия — отдельный репозиторий `DOKA-iOS`, общего кода с этим нет. Суффикс `-macOS` относится только к репозиторию: имя продукта остаётся «DOKA», и `DOKA.app`, bundle id, таргет `DOKA`, `Application Support/DOKA`, аккаунты Keychain, `DOKA.dmg` под имя репозитория НЕ переименовывать — пользователи потеряют данные, TCC-разрешения и ключи.

Структура корня:
- `DOKA-app/` — само приложение (SPM executable, macOS 15+, AppKit + SwiftUI; зависимости — KeyboardShortcuts, WhisperKit из argmax-oss-swift и FluidAudio, две последние — для локальных моделей распознавания).
- `DOKA_LOGO/` — исходники фирменного логотипа (`Vector_DOKA.svg/.pdf`); из `Vector_DOKA.svg` 1:1 перенесён контур `DokaPetalsShape` (см. дизайн-систему). `media/` — картинки для README.
- `README.md` / `README.ru.md`, `CONTRIBUTING.md` / `CONTRIBUTING.ru.md` — документация на двух языках; при правке одной версии обязательно править парную. `LICENSE` — GPL-3.0.

Локальные материалы вне репозитория (лежат на диске, перечислены в `.gitignore` — проект открыт, и в публичную историю они не попадают):
- `DOCS/NEXARA/` — локальная копия документации API Nexara: снимок docs.nexara.ru из дампа `llms-full.txt`, по странице на файл `GUIDES/<slug>.md`; дата дампа, способ регенерации и список пустых страниц — в `DOCS/NEXARA/README.md`. Не публикуется: это дословный чужой контент. `DOCS/superpowers/` — спеки и планы фич.
- `HISTORY-ARCHIVE/` — приватная история разработки до открытия исходников (58 коммитов: развёрнутый git-репозиторий плюс бандл `DOKA-history-backup.bundle` на случай восстановления). В публичную историю не переносится и в репозиторий не входит.
- Черновики соседних продуктов в корне (PRD и HTML-прототип) к коду DOKA-app отношения не имеют и в репозиторий не входят.

Язык кода и комментариев — русский. Строки интерфейса — только через `L("ключ")` (хелпер в `Sources/DOKA/Localization.swift`); каждый ключ обязан присутствовать в обоих файлах `Sources/DOKA/Resources/{ru,en}.lproj/Localizable.strings`. Второй слой локализации — `DOKA-app/Resources/{ru,en}.lproj/InfoPlist.strings` (тексты системных запросов разрешений): эти файлы `swift build` вообще не видит, в бандл их кладёт `build.sh`. Внимание: `swift build` НЕ валидирует синтаксис `.strings` — после правок прогонять `plutil -lint`. Язык интерфейса переключается настройкой `SettingsStore.appLanguage` (механизм `AppleLanguages`, применяется после перезапуска); названия языков в `AppLanguage.title` намеренно не локализуются — каждое на своём языке.

## Команды

Все команды выполняются из `DOKA-app/`:

```bash
swift build        # быстрая проверка компиляции (debug, только нативная архитектура)
./build.sh         # release-сборка (только arm64), подпись, установка в ~/Applications/DOKA.app
./build.sh --dmg   # то же + сборка DOKA.dmg в корне репозитория (hdiutil, UDZO): образ с приложением
                   # и симлинком на /Applications — установка перетаскиванием (артефакт в .gitignore)
./run.sh           # build.sh + запуск приложения

scripts/make-appicon.sh [исходник.png]   # перегенерация Resources/AppIcon.icns
                                         # (по умолчанию из Resources/AppIcon.png; поля по сетке macOS)
```

Коммиты — conventional commits с описанием на русском: `feat:` / `fix:` / `docs:` / `chore:` (см. `git log`).

### Гейты верификации

Тесты чистой логики — `Tests/DOKATests` (XCTest, ~891 проверка плюс 6 живых `LiveSmokeTests`, по умолчанию пропущенных — см. ниже; прогон `swift test` несколько секунд; класс назван по типу, который проверяет, — полный список даёт `ls Tests/DOKATests`). **Сплит на `DOKACore` НЕ нужен и не планируется**: SPM тестирует executable-таргет напрямую через `@testable import DOKA`, несмотря на top-level код в `main.swift` (прежняя запись про необходимость сплита была неверна — проверено). Покрытие по областям:
- **Текст и экспорт**: словарь замен, форматтеры и нарезка сегментов (+ идемпотентность `withDetail`), Markdown, экспорт истории и библиотеки, имена и роли спикеров, сшивка локальной диаризации со словами, слой правок `TranscriptEdits` (имена, слияния, переназначения, правка текста, `splitWithSources`), фильтр галлюцинаций, PDF анализа (`AnalysisPDFTests`: ширины колонок, сборка документа и настоящий файл — A4, номера страниц, кириллица извлекается без «ĸ»).
- **Диктовка и звук**: гейт тишины (`DictationGateTests` — уйдёт ли запись на платное распознавание, по всем исходам и с выключенным гейтом), пороги тихого режима (`SpeechMeterTests` на синтетическом шуме — тем же `SpeechMeter.classify`, что считает запись), удаление тишины (фикстуры — синтетический WAV через `WavWriter`), метки записи для губ (начало речи без сигнала «Pop», дрейф хост-часов).
- **Сеть и библиотека**: декодеры ответов Nexara (`decode`/`decodeAsyncStatus`), стор и файлы библиотеки, поиск и ленивый индекс текстов (`TranscriptTextIndexTests` живёт в `LibrarySearchTests.swift`), группы, `SegmentTimeline`, план «Повторить» (`RetryPlanner`), `FailureKind.classify`, срок хранения, устойчивость декодеров тела, словарь для файлов как ЛИНЗА (`TranscriptOutputTests`: исходные `rawSegments`/`words` обязаны остаться нетронутыми), архив исходного звука вместе с регрессией `AudioFileDecoder.decodeToWav` (они делят выбор дорожки через `makePCMReader`).
- **Локальные модели и ИИ-анализ**: пути и идентификаторы локальных ресурсов (в т.ч. имя папки Parakeet), аккаунты Keychain (включая историческое `nexara-api-key`), сборка UTF-8 при каждом разрезе байтового потока, фильтр размышлений, детектор зацикливания, вход модели и отпечаток, чанкер, промпты, шаблоны и их импорт/экспорт (в т.ч. формат Memento — на синтетических фикстурах, пачка файлов `importFiles`, все встроенные — туда и обратно), `TimestampLinker`.
- **Система и панели**: `ShaderLibraryTests` (наличие metallib, имена функций и — главное — зашитая в его заголовок минимальная версия macOS), `SystemInfoTests` (тесты идут под arm64 — страховка от возврата x86_64; имя процессора — имя чипа Apple, а не кластера ядер «Super»), плечи `EdgeFlowShape`, метрики дашборда и производительности, общие хелперы (`DiskTrash`, `Percentile`), хоткеи (`HotkeyNamesTests`: сочетания по умолчанию и строки, сохранённые прошлой версией KeyboardShortcuts, — с любым порядком ключей JSON, стёртое `false` остаётся стёртым), центровка полей без лупы (`CenteredSearchFieldCellTests`, в т.ч. что `RecorderCocoa` берёт ячейку из `cellClass`).
- **«Губы»** — всё, кроме самой камеры: прогрев экспозиции, шкала WAV и расписание CFR, кроп, вердикт по каждой причине и `faceGaps`, видимость губ (`LipVisibilityTests`: ладонь, губы за краем кадра, поворот головы закрытым ртом не считается, гистерезис; закрытые губы доходят до журнала, маски и `faceGaps`), ЗАМОРОЖЕННАЯ фикстура `meta.json` v1 (договор с WISLIP, ISO-даты), файлы и хранилище («Удалить всё» не трогает корень и посреди обработки ничего не воскрешает; пара целиком на синтетическом дубле — заказ и сырьё камеры в обоих порядках → клип 512×512 со звуком и `meta.json` у тренировки и у диктовки; сбой фиксации публикует «данные потеряны»; синтетика — общий хелпер `LipSyntheticTake`), кодировщик (синтетическое сырое видео → ровно N кадров 512×512 + AAC, каждый выходной кадр — именно свой исходный), движок камеры без камеры (события дубля, Vision на каждом кадре, журнал через кадр, рендер того же буфера, что у Vision), One Euro (золотой вектор стенда), сетка, пути и слои маски, камера зеркала, рендерер, ящик кадров и конвейер. «Тренировка»: фразы (`LipTrainingPhrasesTests` — история режется на годные предложения без цифр и латиницы, готовый список целиком проходит ту же планку и без повторов), очередь (`LipTrainingQueueTests`: чередование пулов, записанное не повторяется, отброшенное возвращается), решение до фиксации и момент подсказки (`LipTrainingCheckTests`), учёт сеанса (`LipTrainingSessionTests`: отложенная фраза, «в обработке», «Переписать», возврат отброшенной, счётчик только при открытом окне, чужие исходы, повторное открытие), вторая ЗАМОРОЖЕННАЯ фикстура meta — пары тренировки (`source: training`, `mode: silent`, без `historyID`), `job.json` прошлой версии без новых полей читается диктовкой, исходы обработки стора.

**Ловушка, стоившая отдельного теста.** `TranscriptionProvider.openai` и `.groq` выглядят мёртвыми (в пикере их нет), но `HistorySectionView`, `TranscriptionControls` и `PerformanceAnalysisView` разбирают ими поле `provider` СТАРЫХ записей истории через `TranscriptionProvider(rawValue:)?.title ?? raw`. Удалить кейсы — показать людям сырые строки вместо названий сервисов. То же с `RecordSummary.preview` и `FileTranscriptRecord.updatedAt`: читателей в UI нет, но они ПЕРСИСТЯТСЯ в `meta.json`, и удаление не-опционального поля сделало бы новый файл нечитаемым для предыдущей версии приложения.

Ловушка тестов локализации: `SpeakerName.displayName` и сообщения `SpeakerRolesParser.RolesError` идут через `L()`, то есть зависят от языка бандла — проверять в них надо номер или структуру, а не конкретный перевод.

**Живой smoke локальных моделей** — `LiveSmokeTests`: по умолчанию `XCTSkip`, запуск `DOKA_SMOKE=1 swift test --scratch-path /tmp/doka-build --filter LiveSmokeTests` (~40 с на M5 Pro). Речь синтезирует `say` (Milena — русский, Eddy — английский), звук идёт настоящим `AudioFileDecoder.decodeToWav`; модели — из `Application Support/DOKA/Models` по статическим путям `LocalModelStore` (синглтон НЕ создаётся: у него на старте sweep папки моделей), языковая — `DOKA_SMOKE_LLM` (путь к GGUF) или `LocalModelStore.llmFile`; нет модели — пропуск с причиной. В стор и настройки ничего не пишет, артефакты (WAV, отчёт, PDF) — в `$TMPDIR/doka-smoke`. Покрывает: Whisper «Авто» (русская речь остаётся русской, английская — английской, `language` файла), слова Parakeet и нарезку по предложениям, Parakeet + локальная диаризация на диалоге двух голосов (каждый голос — ровно один спикер, подсказка «2», все детализации, экспорты), ИИ-анализ по импортированному шаблону Memento → PDF (A4, кириллица извлекается) плюс прогон частями на окне 4k, импорт всех установленных шаблонов Memento, «Угадать имена» настоящей моделью по готовой расшифровке (представление, обращения с ответом, упомянутый третий человек, разрезанный посреди фразы спикер). Проверен мутацией: с откатом #26 (`detectLanguage`) и #28 (слова Parakeet) тесты падают. Гонять после любой правки движков `Local/` и обновления WhisperKit/FluidAudio/llama.cpp — ДО ручного smoke. Поведение моделей, а не баг: Parakeet пишет английскую реплику посреди русской речи кириллицей («Гудморнин»); конспект части на окне 4k упирается в резерв 640 (задача «качество анализа через части»).

Вне покрытия принципиально: запись звука, вставка через CGEvent, Keychain, панели рекордера, сетевые запросы — им нужен живой Mac с разрешениями. Поэтому гейты остаются:

1. `swift build` — без предупреждений, затем `swift test` — все зелёные. **Автоматизировано** в CI (`.github/workflows/build.yml`): гейт предупреждений грепает лог по `Sources/DOKA/`, потому что `-warnings-as-errors` применился бы и к FluidAudio, у которой три своих предупреждения.
2. **Шейдеры**: после правки любого `Shaders/*.metal` — `scripts/build-shaders.sh`. SwiftPM `.metal` НЕ компилирует, поэтому голый `swift build` соберёт приложение со старым шейдером (или вовсе без него — капелька «Авроры» останется пустой, в лог уйдёт предупреждение). `build.sh` зовёт скрипт сам, в CI это отдельный шаг, а `ShaderLibraryTests` проверяет и наличие `default.metallib` в бандле, и имена функций — но только на ЧИСТОЙ сборке: на грязном `.build` старый metallib остаётся лежать в бандле и тест зеленеет вхолостую.
3. `plutil -lint` обоих `Localizable.strings` (при их правке — и обоих `InfoPlist.strings`): `swift build` синтаксис `.strings` НЕ проверяет. **Автоматизирован** там же, вместе со `scripts/check-localization.sh` — он сверяет парность ключей ru/en, дубли, плейсхолдеры, наличие ключей из `L(...)` и отсутствие мёртвых строк. В `DYNAMIC_PREFIXES` скрипта десять записей. Восемь — настоящая интерполяция `\(rawValue)`: `transcribe.roles.`, `transcribe.llm.preset.`, `transcribe.llm.prompt.`, `transcribe.detail.`, `transcribe.diarizeSetting.`, `transcriptRetention.`, `analysis.template.`, `analysis.format.`. Ещё `sidebar.group.` собирается из массива в `SidebarView`, а `analysis.prompt.format.` вписан с запасом — эти ключи в `AnalysisPromptBuilder` пока литеральные, и скрипт нашёл бы их и без префикса. При добавлении новых динамических ключей список `DYNAMIC_PREFIXES` надо пополнять, иначе строки будут объявлены мёртвыми.
4. `./build.sh` — release + подпись. В CI выполняется только по тегу (`.github/workflows/release.yml`) и уходит в ad-hoc-ветку подписи: сертификата «DOKA Dev» на раннере нет. **Отдельно для llama.framework** (движок ИИ-анализа): `lipo -archs .../Contents/Frameworks/llama.framework/Versions/A/llama` — обязан быть ровно `arm64`; `otool -L .../MacOS/DOKA | grep llama.framework` и `otool -l ... | grep '@executable_path/../Frameworks'`; `codesign --verify --deep --strict`. Те же проверки (плюс `lipo -archs` самого бинарника) стоят шагом в `release.yml`; сам `build.sh` вырезает из фреймворка x86_64 (`lipo -thin arm64`) и роняет сборку guard'ом `lipo`, если бинарник или фреймворк не ровно `arm64`.
5. Ручной smoke по затронутым областям (движки локальных моделей сначала прогоняет `LiveSmokeTests` — руками остаются интерфейс и железо: нажатие хоткея, микрофон, вставка, вид панелей):
   - **Диктовка**: end-to-end при `saveAudio` вкл/выкл, отмена Esc во время записи и во время распознавания, все стили панели, копирование. Гейт тишины: 2 с молчания → «Речь не услышана», в истории и на дашборде пусто, короткое «да» проходит, тумблер «Не отправлять запись без речи» выкл → тишина снова уходит в API; отсеянная запись длиннее секунды появляется в меню «Повторить неудачную диктовку». Повтор: Wi-Fi выкл → ошибка → пункт в меню-баре → Wi-Fi вкл → «Повторить» вставляет в то же приложение; переключение в другое приложение во время повтора → текст в буфере с сообщением; Esc во время повтора — пункт возвращается; ошибка вставки (поле пароля) пункт НЕ создаёт; успешная новая диктовка убирает пункт; после выхода/запуска пункта и временных `doka-*.wav` нет.
   - **Словарь**: «документ дока, привет» с правилом «дока» → «DOKA» даёт «документ DOKA, привет»; «Внутри слов» у «ё» → «е» меняет букву внутри слова; словарь, сохранённый прошлой версией, после обновления на месте. Тумблер «Применять словарь замен» на «Транскрибации»: показ, «Скопировать» и все форматы «Сохранить как…» с заменами, смена детализации их сохраняет, выключение сразу возвращает исходник. Для «Авроры» отдельно: волна реагирует на голос, после отпускания хоткея сменяется кольцом капель, на ошибке показывается классическая плашка, ореол не обрезан кромкой окна.
   - **Дашборд**: тест скорости печати, геро-метрики.
   - **История**: воспроизведение/экспорт записей, срок хранения, «Стереть всё аудио», экран анализа производительности.
   - **Звук**: буст микрофона с возвратом громкости, удаление тишины, громкость сигналов.

### Особенности сборки — не «чинить»

- **iCloud**: проект лежит на Рабочем столе, синхронизируемом iCloud. FileProvider вешает на файлы xattr, из-за которых `codesign` падает («detritus not allowed»). Поэтому `build.sh` собирает бандл во временной папке в `/tmp` и копирует с `cp -X`. Не пытаться подписывать бандл внутри папки проекта.
- **Подпись**: нужен самоподписанный сертификат «DOKA Dev» (инструкция — `DOKA-app/scripts/make-dev-cert.md`). При ad-hoc подписи macOS сбрасывает TCC-разрешения (микрофон, Accessibility) на каждой пересборке.
- **Шейдеры и SPM**: `default.metallib` собирается ОТДЕЛЬНЫМ скриптом и лежит в `Sources/DOKA/Resources` (в `.gitignore` — артефакт сборки), откуда `.process("Resources")` кладёт его в `DOKA_DOKA.bundle`, а `build.sh` забирает бандл своим циклом `*.bundle` — правок в копировании не нужно. Build-tool-плагин SwiftPM когда-то отвергли: на мультиарх-сборке `--arch arm64 --arch x86_64` он падал с «Unable to resolve build file … missing target» (воспроизводилось на пустом пакете). Сейчас сборка только arm64, и эта причина снята, но рабочий скрипт на непроверенный плагин менять незачем. Исходники шейдеров лежат в `DOKA-app/Shaders/`, а не в `Sources/`, тоже намеренно: `.metal` внутри таргета даёт предупреждение «found 1 file(s) which are unhandled», которое уронит гейт предупреждений.
- **Только Apple Silicon (arm64)**: release собирается `swift build -c release --arch arm64`; Intel не поддерживается (решение пользователя, 23.09.2026: Parakeet и ИИ-анализ на Intel не работали вовсе, universal-сборка зажимала зависимости пинами и вдвое раздувала бандл — 62 → 32 МБ после отказа). Каталог продуктов `build.sh` спрашивает у SwiftPM (`--show-bin-path`), а не хардкодит: он зависит от версии swift-build (`.build/release`, `.build/out/Products/Release`, у мультиарх — `.build/apple/Products/Release`). Intel-веток в коде нет: arm64-бинарник на Intel-маке просто не запускается, поэтому `#if arch`, барьеры скачивания и Intel-предупреждения удалены — не возвращать.
- **Debug-сборка в папке проекта на macOS 27** падает на подписи ресурсных бандлов («detritus not allowed» — та же iCloud-ловушка): новый swift-build подписывает и debug-бандлы. Проверять компиляцию и тесты с build-папкой вне iCloud: `swift build --scratch-path /tmp/doka-build` (и `swift test` с тем же флагом). Release-сборка `build.sh` в папке проекта при этом проходит.
- **Пометка SDK в бинарнике (`LC_BUILD_VERSION`) переписывается `vtool` в `build.sh`.** SwiftPM пишет туда `sdk` = deployment target (15.0), хотя собирает SDK Xcode, а AppKit по этой пометке («linked-on SDK») решает, давать ли приложению новый дизайн: «собранному под 15» на macOS 26/27 достаются СТАРЫЕ кнопки окна (светофор), тумблеры, списки и ползунки — при том что явный `glassEffect` работает. `build.sh` ставит `sdk` = `xcrun --show-sdk-version`, `minos` — `MIN_MACOS` из `scripts/build-shaders.sh`, и роняет сборку, если пометка не совпала; та же проверка — в `release.yml`. Голые `swift build`/`swift run` по-прежнему дают `sdk 15.0`: вид контролов проверять только на бандле из `build.sh`.
- `build.sh` убивает запущенный процесс DOKA перед заменой бандла.
- **Минимум — macOS 15, и это не косметика.** Подняли с 14 из-за бага Apple
  (FluidAudio #878): на macOS 14 офлайновая диаризация роняет приложение —
  `EXC_BAD_ACCESS` в `libBNNS` (`BNNSGraphContextExecute_v2` → `_platform_memmove`).
  Матрица upstream: macos-14 — 1200/1200 крэшей, macos-15 и 26 — ноль на том же
  коде. Библиотечного обхода нет, починено в самой macOS 15; в 0.15.6 добавлено
  только предупреждение в лог. Понижать `platforms` обратно нельзя.
- **Шейдеры собираются с `-mmacosx-version-min`.** Компилятор Metal зашивает
  минимальную версию ОС в заголовок metallib и без флага берёт её из SDK
  сборочной машины: на Xcode 26 это давало «нужна macOS 26», и на всех
  системах ниже `makeLibrary(URL:)` молча отказывался грузить библиотеку —
  «Аврора» и «Мини» показывали пустую капельку. Ни сборка, ни CI этого не
  ловили (оба на macOS 26). `MIN_MACOS` в `scripts/build-shaders.sh` обязан
  совпадать с `platforms` в `Package.swift`; `ShaderLibraryTests` сверяет
  зашитую версию, читая байт по смещению 12 в заголовке (0x0f = 15).

## Архитектура

Точка входа `main.swift`: `LegacyMigration.run()` (обязательно до первого чтения настроек) → `AppDelegate`. Приложение — `.accessory` / `LSUIElement`: только меню-бар, без Dock.

**Центр всего — `DictationController`** (`Sources/DOKA/DictationController.swift`): конечный автомат `idle → recording → transcribing → idle` плюс состояние `error`. Счётчик поколений `generation` инвалидирует устаревшие задачи транскрипции: любая смена состояния увеличивает его, и задача со старым значением не имеет права трогать автомат или вставлять текст. Любое изменение жизненного цикла диктовки проходит через `transition(to:)`.

**Владение объектами**: `AppDelegate` владеет всеми верхнеуровневыми объектами (DictationController, HotkeyManager, MenuBarManager, RecorderPanelController); остальные держат `weak`-ссылки. Весь код `@MainActor`.

**Поток данных диктовки**:
`HotkeyManager` (KeyboardShortcuts) → `DictationController` → `AudioRecorder` (WAV во временный файл) → `TranscriptionClient` (multipart POST на `/audio/transcriptions`) → `ReplacementEngine` (правила словаря) → `HistoryStore` (JSON в Application Support/DOKA, максимум 200 записей; метаданные — всегда, сжатое m4a-аудио — только если включён тоггл `SettingsStore.saveAudio`, по умолчанию ВЫКЛ; см. раздел «История») и `StatsStore` (lifetime-агрегаты для дашборда) → `Paster` (буфер обмена + синтетический Cmd+V через CGEvent). Кодирование m4a — ещё один `await` в пайплайне (между распознаванием и вставкой), поэтому при выключенном `saveAudio` его пропускают целиком и вставка быстрее; после кодирования автомат повторно проверяет `generation` (отменённая диктовка не пишется в историю и не вставляется). Ключевые переходы автомата озвучиваются системными звуками macOS через `SoundPlayer` (`Audio/SoundPlayer.swift`: старт/стоп/отмена/ошибка), гейтится настройкой `SettingsStore.soundsEnabled`.

**Гейт тишины и повтор диктовки.** Решение «отправлять ли запись» — чистый `Audio/DictationGate.swift` (`minDuration 0.4` с — случайное нажатие; `minSpeechDuration 0.25` с активной речи по `AudioRecorder.speechDuration`, т.е. по СТАРОЙ dB-кривой — сам порог `speechLevelThreshold` не трогать). Запись без речи не уходит ни в API, ни в историю/статистику (`error.noSpeech` через обычный канал `.error`, звук `.cancel`); гейт выключается тумблером `SettingsStore.skipSilentRecordings` («Звук») для тихих голосов. Слот повтора `DictationController.lastFailedDictation` (один, только в памяти, WAV во временной папке): заполняется при ошибке ДО `history.add` (маршрут, распознавание, движок) и отсеянной гейтом записью длиннее `retryableMinDuration` 1 с — «распознать всё равно». Приоритет слота: отсеянная тишина (`FailedDictation.gated`) НЕ вытесняет настоящую неудачу — иначе случайное нажатие хоткея после сбоя сети стёрло бы реальную диктовку; такая тишина просто выбрасывается. Ошибка ВСТАВКИ слот не заполняет: текст уже в истории и в буфере, повтор задублировал бы запись. Судьбу WAV решает одно место — `settle(outcome)` в `defer` `transcribeAndPaste`: он не трогает автомат, а `outcome = .failed` выставляется только при `generation == gen`, поэтому устаревшая задача слот не перезапишет; Esc во время ПОВТОРА возвращает исходник в слот, Esc живой диктовки выбрасывает запись. Пункт меню-бара «Повторить неудачную диктовку (0:12)» (`isHidden` по `CombineLatest(state, slot)` — `isEnabled` перетёр бы `autoenablesItems`) распознаёт запись текущим сервисом в обход гейта; результат вставляется, только если frontmost PID не сменился с момента клика, иначе — буфер обмена и сообщение. Слот чистится успешной новой диктовкой и в `applicationWillTerminate`; сироты `doka-*.wav|tmp` прошлых запусков подчищает фоновый sweep на старте (`sweepOrphanedTempFiles`, только файлы старше запуска).

**Тихий режим (шёпот).** `SettingsStore.quietMode`: тумблер в «Звуке», пункт с галочкой в меню-баре, глобальная клавиша `toggleQuietMode` без дефолта (по клавише и пункту меню в покое панель коротко называет новый режим — `DictationController.toggleQuietMode`). Замер на реальных записях: шёпот — медиана −45,6, p90 −42 дБFS, почти целиком ниже обычного порога −40 (гейт насчитал 0,15 с речи на 38 с шёпота — любая шёпотная диктовка была «Речь не услышана»), а Whisper large-v3-turbo распознаёт такой шёпот с ~4 % ошибок, Parakeet — ~7 %. Поэтому модель не меняется, меняется только гейт: `AudioRecorder` ВСЕГДА копит второй счётчик `quietSpeechTime` по `SpeechMeter.quietThresholdDb` (−48; тишина комнаты на нём дала 0,19 с из 26), а `speechLevelThreshold` и старая кривая не тронуты. Режим снимается на старте записи (`RecordedDictation.quiet`: переключение посреди записи не смешивает пороги и переживает слот повтора), гейт берёт `gateSpeechDuration`. В тихом режиме не работает `SilenceRemover` (отдельные согласные шёпота перешагивают его −40, и от фразы остались бы клочки), уровень панелей поднят на `SpeechMeter.quietDisplayGain` (+12 дБ — пол кривой панелей ~−41 дБFS выше шёпота), а время речи в историю и `StatsStore` НЕ пишется (`statsSpeechDuration == nil` → `record(speechDuration: 0)` не трогает агрегаты скорости): время над тихим порогом — лишь доля шёпота, и «Скорость речи» взлетела бы в разы. Буст микрофона режим не форсирует — он поднял бы и шум к порогу. Порог подобран в одной комнате: при жалобах «тишина проходит гейт» смотреть NSLog гейта (в тихом режиме он помечен) и фон помещения.

**Галлюцинации на тишине — фильтр по содержанию, а не по громкости.** Whisper на почти тишине ВСЕГДА выдаёт дежурную фразу субтитров YouTube (замер: 1 с тишины → «Продолжение следует...» при `language=ru`, «You» в автоопределении), и сам ставит ей `no_speech_prob` 0.0 — по его оценке не отсеять. В тихом режиме короткая пустая запись с шорохом прошла гейт и вставила «Thank you.» сразу за предыдущей фразой («в конце добавляется спасибо»). Ужесточить тихий гейт НЕЛЬЗЯ: у настоящих шёпотных фраз над −48 бывает 0,21–0,34 с, у шороха — 0,06–0,23 с, а иногда и больше секунды; распределения пересекаются. Поэтому чистый `Text/HallucinationFilter.swift` отсекает результат, который ЦЕЛИКОМ (или повтором) равен дежурной фразе: субтитровые артефакты («Продолжение следует», «Субтитры сделал DimaTorzok», «Спасибо за просмотр»…) — в любом режиме, короткие «Спасибо» / «Thank you» / «You» — только в тихом (днём одно «Спасибо» вслух — нормальная диктовка). Срабатывает только на живой диктовке, сразу после распознавания и до словаря; итог `Outcome.gated` ведёт себя как отсев гейта (`error.noSpeech`, запись от 1 с — в слот повтора с `gated: true`), а «Повторить неудачную диктовку» фильтр обходит — там пользователь сам просит распознать. Стартовый сигнал «Pop» играет, когда микрофон уже пишет, но сам гейт не проходит (замер: 0,06–0,13 с над −48); сигнал остановки играет после `recorder.stop()` и в запись не попадает.

**Сервисы транскрипции** (`Network/TranscriptionProvider.swift`, маршрут и фасад — `Network/ServiceRoute.swift`): в UI `builtin` (Nexara), две локальные модели (см. «Локальные модели») и пользовательские пресеты `CustomService` (список в UserDefaults, у каждого свой ключ в Keychain под аккаунтом `custom-<uuid>`); `SettingsStore.providerID` — `"builtin"`, `"custom:<uuid>"` либо `"local:whisper"`/`"local:parakeet"`. Доступ к активному сервису — ТОЛЬКО через фасады `SettingsStore.currentAPIKey / currentKeychainAccount / providerConfig / providerTagForHistory / selectedLocalModel / isLocalService / isServiceReady / resolveRoute` (не через Keychain напрямую). `isServiceReady` — единая проверка готовности (локальный: модель скачана; сетевой: разбирается конфиг И сохранён ключ) — именно её используют гейты диктовки, онбординга и транскрибации файлов, других редакций этой проверки не заводить; `providerConfig` и `currentAPIKey` для локального сервиса возвращают `nil` (ключа нет, Keychain не трогается). `resolveRoute()` отдаёт enum `ServiceRoute` (`local(LocalModel)` / `remote(apiKey:config:)`, свойство `modelTag` для метаданных истории) — ЕДИНСТВЕННАЯ форма ветвления «локальный/сетевой» в контроллерах (`DictationController` и `FileTranscriptionController` свитчатся по нему); бросает `ClientError.notConfigured`/`.noAPIKey`, читает Keychain — не звать синхронно в пути запуска. Enum `TranscriptionProvider` остался ради keychain-имён и `normalizeEndpoint`; у `builtin` историческое имя аккаунта `nexara-api-key` — не менять, потеряются ключи пользователей. Прежние openai/groq/custom один раз мигрируются в пресеты (`migrateLegacyServices`, флаг `servicesMigrated`; префикс `local:` проходит через его `default: return` нетронутым). Пикер в `ServiceSectionView` построен на enum `ServiceMenuItem: Equatable` (builtin → локальные → пресеты → «Новый сервис…»; пресет несёт сам `CustomService`, выбор — `firstIndex(of: currentItem)`) — не возвращать ни позиционную арифметику индексов, ни индексы внутри case'ов.

**Локальные модели** (`Sources/DOKA/Local/`) — распознавание on-device, без сети и ключа: «Whisper Large v3 Turbo (Local)» = openai whisper large-v3-turbo через WhisperKit (вариант `openai_whisper-large-v3-v20240930`, ~1.6 ГБ) и «Parakeet TDT 0.6B v3 (Local)» = NVIDIA parakeet-tdt-0.6b-v3 через FluidAudio (~700 МБ, int8-энкодер). Названия в UI (`LocalModel.title`) соответствуют фактическим моделям: «Turbo» — у Whisper (v20240930 и есть turbo-релиз), у Parakeet никакого «Turbo» нет. Оба — CoreML (ANE/GPU/CPU), русский поддержан обоими.
- **Зависимости** (сверка с апстримом 6.10.2026: KeyboardShortcuts 3.1.0, WhisperKit 1.1.0, FluidAudio 0.17.5 и транзитивный swift-argument-parser 1.8.2 — последние версии; пин llama.cpp — в «Локальном ИИ-анализе»): WhisperKit пинится линией `.upToNextMinor(from: "1.1.0")` (обновлён с 0.18 5.10.2026). Долгий пин на 0.18 — из-за universal-сборки: в 1.x два executable-продукта (`argmax-cli`/`whisperkit-cli`) делят таргет `ArgmaxCLI`, и `--arch arm64 --arch x86_64` падала с «duplicate key found»; с переходом на arm64 причина снята. С 1.0 Hub/Tokenizers из swift-transformers ВСТРОЕНЫ в ArgmaxCore — вместе с 0.18 из дерева ушли swift-transformers, swift-jinja, swift-crypto, swift-asn1, swift-collections и yyjson (и их NOTICE в `THIRD_PARTY_LICENSES.md`). Раскладка закачки и токенайзера та же (`whisper/models/<репозиторий>`): уже скачанная модель и закэшированный токенайзер подхватываются без сети. Минорную версию поднимать отдельной правкой: release-сборка и smoke локальных моделей. FluidAudio пинится ТОЧНО (`exact: "0.17.5"`, обновлён с 0.15.5 5.10.2026; «патч» у FluidAudio не означает патч: между 0.15.5 и 0.15.7 — 237 файлов и +28 000 строк, `.upToNextMinor` от этого не защищает). Старый пин 0.15.5 держался из-за universal-сборки: с 0.15.7 мультиарх-путь SwiftPM падал на `-ltext_processing_rs`; с переходом на arm64 причина снята. С 0.15.7 у FluidAudio бинарный таргет `NemoTextProcessing` (готовая СТАТИЧЕСКАЯ Rust-библиотека text-processing-rs — FST-нормализация NeMo для TTS и ITN, +10 МБ бинарника) — он выключен трейтом: `.package(..., exact: "0.17.5", traits: [])`; DOKA им не пользуется (текст Parakeet с ним и без него одинаков), `otool -L` чистый, в бандл докладывать нечего. Отключить трейт может ТОЛЬКО манифест на swift-tools 6.2+ (на 6.1 синтаксис принимается, но бинарь всё равно линкуется) — поэтому `Package.swift` на 6.2 со `swiftLanguageModes: [.v5]` (язык Swift 5: Swift 6 включил бы строгую конкурентность на всё приложение). Ловушка резолва: проверка трейтов идёт по СОСТОЯНИЮ рабочей области — если в `--scratch-path` записан старый FluidAudio без трейтов, резолв падает «declares no traits»; лечится свежим scratch-каталогом. Модели диаризатора 0.17.x берёт с закреплённой ревизии: первая загрузка после обновления один раз докачивает ~22 МБ в `Models/diarizer` (маркер `.fluidaudio-revision`), без сети диаризация этой попытки не удастся (расшифровка останется без спикеров); 0.15.5 эти файлы тоже читает. Ресурсные бандлы зависимостей, если появятся, `build.sh` подхватывает своим циклом `*.bundle`. **Тулчейн сборки: Xcode 26+** — код использует SDK macOS 26 (Liquid Glass: `glassEffect` в `GlassSurface`, сайдбаре), а KeyboardShortcuts 3.x объявлена на `swift-tools-version: 6.2` (прежняя такая же причина — `swift-collections` — ушла вместе с WhisperKit 0.18); deployment target при этом — macOS 15 (`.macOS(.v15)`; манифест на tools-version 6.2 — ради трейта FluidAudio, см. выше).
- **Хранение** — `LocalModelStore` (синглтон, `@Published` состояние notDownloaded/downloading/preparing/ready/failed). Ключ состояния — `LocalAsset` (`.speech(LocalModel)` / `.diarizer`), а НЕ `LocalModel`: диаризатор — не сервис, в `providerID` и в пикер «Сервис» он попадать не должен, а `LocalModel.allCases` как раз строит меню сервисов; общий у них только механизм скачивания. Для существующих вызовов оставлены тонкие перегрузки с `LocalModel`. Ловушка путей FluidAudio: у ASR (`AsrModels.download/load/modelsExist`) переданный путь теряет последний компонент и получает вместо него имя репозитория — поэтому `parakeetFolder` обязан называться `Models/parakeet-tdt-0.6b-v3` (пока он назывался `Models/parakeet`, папка не существовала: размер модели показывался нулевым, а «Удалить модель» было no-op); у офлайнового диаризатора наоборот — путь идёт как есть, а репозиторий создаётся ВНУТРИ (`Models/diarizer/speaker-diarization`). Модели живут в ФИКСИРОВАННОЙ `AppDataFolder.modelsURL` (`Application Support/DOKA/Models`), за кастомной «Папкой данных» НЕ следуют — это перекачиваемый кеш, а перенос 1.5+ ГБ сделал бы миграцию блокирующей. `AppDataFolder.migrateToTarget` копирует и удаляет по элементам, пропуская фиксированные папки (`AppDataFolder.fixedFolderNames` — `Models` и `LipData`) в обе стороны, и не считает их «непустотой» цели при возврате на дефолт (`blocksMigration`). Скачивание — API самих SDK с прогресс-колбэками через общий `ProgressSink` (квантование до целого процента: URLSession шлёт колбэки на каждый чанк, без квантования SwiftUI перерисовывался бы сотни раз в секунду); отмена и провал подчищают частично скачанное (иначе огрызок притворится готовой моделью). Размер папки модели считается ФОНОМ (`refreshSize`, до подсчёта показывается `approxDownloadBytes`): рекурсивный stat 1.6-ГБ дерева в `init` синхронно блокировал бы запуск приложения, а `markPreparing(false)` берёт закешированный `knownSizes` — без пересчёта в критическом пути диктовки. Удаление модели — мгновенный rename в `*.deleting-<uuid>` + фоновое стирание (`removePartial`; осиротевшие после kill папки подчищает `sweepDeleteLeftovers` на старте). Корзина и подсчёт размера дерева — общие `Storage/DiskTrash.swift` (`DiskTrash.move`/`empty`/`isTrash`, `FileManager.allocatedSize(of:)`, `URL.contentModificationDate`) у моделей, библиотеки и «Губ»: свою копию rename-логики не заводить.
- **Движки** — протокол `LocalTranscriptionEngine` (`transcribeDictation` → чистый текст, `transcribeFile` → `LocalFileTranscription` с сегментами/словами в типах DOKA) и реализации `WhisperLocalEngine`/`ParakeetLocalEngine`; импорты WhisperKit/FluidAudio намеренно заперты в файлах движков `Local/` (у пакетов свои `TranscriptionResult`/`TranscriptionSegment`/`Language`). Ловушка WhisperKit: язык «Авто» (`language: nil`) — это автоопределение ТОЛЬКО вместе с `detectLanguage: true`; без флага при включённом по умолчанию префилле подставляется английский, и русская речь выходила английским ПЕРЕВОДОМ (диктовка с языком «Авто» и файлы; проверено синтезом `say` на 0.18 и 1.1). Владелец загруженного движка — `LocalEngineManager`: один движок на приложение, загрузка через общую задачу `loading` (кортеж модель+задача; прогрев и диктовка не грузят модель дважды), выгрузка после 5 минут простоя (`idleUnloadDelay`, модель держит ~2 ГБ ОЗУ), при смене сервиса (didSet `providerID`) и при удалении модели. Прогрев (`prewarm`) стартует сразу после скачивания: первая CoreML-компиляция под чип (минуты) уходит в статус «Подготовка модели…», заодно WhisperKit кэширует токенайзер с HuggingFace (сеть нужна ровно один раз — сразу после скачивания она есть).
- **Локальная диаризация** (`Local/LocalDiarizer.swift`) — разделение по спикерам на этом Mac поверх ОФЛАЙНОВОГО (VBx) диаризатора FluidAudio: `OfflineDiarizerModels.load` + `OfflineDiarizerManager.process(url)`, модели pyannote community-1 + WeSpeaker, **всего ~22 МБ** (CC-BY-4.0, см. `THIRD_PARTY_LICENSES.md`), ~12× быстрее реального времени на M-чипе. Онлайновый `DiarizerManager` НЕ использовать: его `DiarizerConfig.numClusters` («ожидаемое число спикеров») не читается ни одной строкой пайплайна (0.15.5; в 0.17.5 перепроверено — поле только объявлено) — подсказки о числе спикеров у него фактически нет, плюс сегменты могут перекрываться. У офлайнового подсказка настоящая (`config.withSpeakers(exactly:)`), сегменты неперекрывающиеся; проверено стендом: принудительная единица схлопывает диалог в одного спикера, а лишних спикеров подсказка не выдумывает. Менеджер создаётся на КАЖДЫЙ прогон (число спикеров живёт в конфиге, а не в вызове), тяжёлые модели переиспользуются. Идентификаторы `S1`/`S2` ремапятся в формат Nexara `speaker_0`/`speaker_1` по порядку первого появления — иначе `SpeakerName` и все экспорты покажут сырой id. Владелец — тот же `LocalEngineManager` (диаризатор живёт РЯДОМ с речевым движком, та же выгрузка по простою). Сшивка со словами — чистый `Util/SpeakerAssignment.swift`: сегмент целиком внутри одной реплики сохраняет исходный текст, сегмент со сменой говорящего режется по словам; без слов спикер берётся по наибольшему перекрытию. Ошибка диаризации (в т.ч. `noSpeechDetected` на записи короче секунды и на тишине) НЕ роняет расшифровку — результат просто остаётся без спикеров.
- **Диктовка**: ветка в `DictationController.transcribeAndPaste` (switch по `SettingsStore.resolveRoute()`) — те же 4 проверки `generation == gen` плюс одна после загрузки движка; WAV диктовки уже 16 кГц mono, конвертация не нужна. Отмена по Esc кооперативная: у Whisper колбэк декодера возвращает `false`, у Parakeet — `Task.checkCancellation` после инференса.
- **Файлы**: ветка `case .local` в `FileTranscriptionController.transcribe()` (мимо async/sync сетевых) — `AudioFileDecoder` (AVAssetReader → WAV 16 кГц mono, единый вход и для аудио, и для видео: сами SDK видеоконтейнеры не читают; работа в detached-задаче с пробросом отмены) → `engine.transcribeFile` → `TranscriptResult` (`llmOutput = nil`), дальше общий путь; загрузка движка перекрывается с декодированием (`async let`) — холодный старт не ждёт сумму двух операций: перенарезка `withDetail`, все экспорты, библиотека. Parakeet предложений не делит — отдаётся один сегмент на всю запись + пословные тайм-коды, красивую нарезку делает `TranscriptSegmentSplitter`. Ловушка слов Parakeet: FluidAudio отдаёт токены уже ДЕКОДИРОВАННЫМИ — начало слова помечено пробелом («␣При», «вет»), а не «▁»; при проверке одного «▁» весь файл склеивался в ОДНО слово (запись не резалась по предложениям, спикеры сшивались только по перекрытию). Сборка слов — чистая `ParakeetLocalEngine.words(from:)` (`ParakeetWordsTests`). При включённой диаризации тот же временный WAV идёт в `LocalDiarizer` ДО `defer`-удаления файла, спикеры сшиваются `SpeakerAssignment`. Роли и LLM-анализ для локальных недоступны (гейт `isBuiltinService`); recovery на старте помечает локальных сирот «прервано перезапуском» (ветка `jobID == nil`).

**Синглтоны**: `SettingsStore.shared` (обёртка над UserDefaults, все настройки `@Published`), `HistoryStore.shared`, `AudioStore.shared` (сжатое аудио истории на диске), `TranscriptHistoryStore.shared` (библиотека транскрибаций файлов), `LibraryModel.shared` (состояние секции «Библиотека»), `RecordingPlayer.shared` (воспроизведение записей истории и библиотеки), `StatsStore.shared` (агрегаты статистики диктовки), `PermissionsManager.shared` (микрофон + Accessibility; камера — отдельно, в `allGranted` не входит), `WindowManager.shared`, `LipCapture.shared` (камера эксперимента «Губы»), `LipDataStore.shared` (пары «губы + текст»), `LipTrainingController.shared` (окно «Тренировка»).

**UI — два слоя**:
- Главное окно (`UI/WindowControllers.swift` + `UI/Main/`): ленивый NSWindow с SwiftUI `MainWindowView`, сайдбар с секциями (enum `MainSection`: home/dashboard/general/sound/hotkeys/dictionary/service/history/transcribe/library; группа сайдбара «Диктовка» — transcribe, library, history, dictionary). Внимание к названиям: `home` в UI называется «DOKA» (онбординг/готовность к диктовке), а `dashboard` в UI называется «Дашборд» — экран статистики диктовки (ключ `section.dashboard`). Окно переживает закрытие (`isReleasedWhenClosed = false`).
- Плавающая панель записи (`UI/RecorderPanel.swift`, контроллер `RecorderPanelController`): borderless non-activating `NSPanel`, никогда не становится key — фокус остаётся в целевом приложении. Шесть стилей (по умолчанию `classic`); порядок кейсов в `RecorderStyle` задаёт порядок карточек в пикере — `allCases` идёт прямо в сетку, поэтому переставлять их можно только осознанно, но ошибки показываются всегда; classic (и `hidden`, когда та показывает ошибку) рендерит `RecorderView.swift`, у остальных — свои файлы. **`aurora` и `mini` — одна и та же капелька** (`UI/DropRecorderView.swift`), отличаются габаритами (`DropGeometry.wide` 180×44 против `.compact` 90×63 — единственный источник размеров; во время распознавания каждая стягивается в круг ПО СВОЕЙ высоте, `DropGeometry.transcribing` вычисляется от `recording.height`, общая константа дала бы овал), флагом `DropGeometry.halo` (тёплый ореол за капелькой — только у «Авроры»; у «Мини» его убрали по решению пользователя, не возвращать без просьбы), графикой `DropGeometry.look` (`DropLook`: подложка `DS.Aurora.cosmic` против более глубокой `cosmicDeep`, палитрой целиком (`DropLook.wave`/`waveHighlight`/`rimTop`/`rimBottom`: «Мини» — ХОЛОДНАЯ тема на токенах `DS.Aurora.mini*` (ледяная ведущая нить, бирюза Тиффани, сине-фиолетовый хвост, тёмно-синяя подложка), тёплые `DS.accent`/`DS.glow` в неё не подмешивать — тёплое рядом с бирюзой спорило за внимание, пробовали дважды), ровная кромка против живой) и тем, поднимает ли контроллер панель со `ScreenGlowView`. Миниатюре в пикере `look` передаётся явно — иначе карточка покажет чужую капельку. Кому нужна подсветка всего экрана — берёт «Аврору», кому только капельку — «Мини». Прежний вид «Мини» (стеклянная пилюля с точкой записи) удалён. `notch` (`NotchRecorderView.swift`) — чёрная плашка-бровка, прирастающая к ВЕРХНЕЙ КРОМКЕ экрана (`RecorderPanelController.notchFrame`: `y = frame.maxY - size.height`, отступ 0 — та же рамка у зеркала губ, которое продолжает плашку; высота — РОВНО `safeAreaInsets.top`, любая добавка свешивает плашку ниже кромки выреза) и с аппаратным вырезом, и без него (фейковый нотч, плоский верх + скруглённый низ); верх вытекает из кромки вогнутыми «плечами» — `EdgeFlowShape` (`UI/DesignSystem/`, общая с зеркалом губ, плечо — `DS.EdgePlate.shoulder`), поэтому окно шире тела плашки на два плеча (`notchGeometry`), а контент раскладывается по ширине тела; уровень окна `.statusBar` рисует поверх менюбара. Фон намеренно чисто чёрный (не стекло), панель пересоздаётся при каждом показе под геометрию экрана с курсором. `aurora` (`UI/DropRecorderView.swift`) — капелька 180×44 снизу плюс полноэкранная подсветка краёв: для неё контроллер поднимает ВТОРУЮ borderless-панель `glowPanel` с `ignoresMouseEvents = true` (клик-сквозной оверлей со `ScreenGlowView`), живущую отдельно от основной. Габариты собраны в `DropGeometry`. Содержимое — Metal-шейдеры (`Shaders/AuroraDrop.metal`, обёртка `DropShaders`): `dokaDropWave` при записи, `dokaDropDots` при распознавании и `dokaDropGlass` поверх обоих — стеклянная оболочка на `.layerEffect` (единственный способ дать шейдеру доступ к уже нарисованному содержимому): у кромки свет преломляется, по краю идёт ровный блик. После `layerEffect` обязателен ПОВТОРНЫЙ `clipShape(Capsule())` — преломление уводит сэмплы за границу, иначе вокруг капельки висит размытый ореол чужого цвета.

Ловушки этой панели, каждая оплачена переделкой:
- **Ширину капсулы нельзя менять в одиночку.** Фаза волны считается от ОПОРНОГО аспекта `kRefAspect = 90/63`, а не от фактического: иначе с ростом ширины волна уплотняется (больше колебаний на ту же капсулу) вместо того, чтобы растягиваться. Меняете ширину в `DropGeometry` — форма остаётся прежней, и это правильно; ровно поэтому «Мини» с её 90×63 получает ту же волну, просто сжатую.
- **Палитра волны — `accent` → `glow` → индиго**, ядро `waveHighlight`. Тёплый вариант (оранжевый/коралл/янтарь) с бегущим по кромке импульсом пробовали и откатили по решению пользователя: не заводить заново без явной просьбы.
- **Пружина ширины недодемпфирована** (жёсткость 400, демпфирование 18, ζ ≈ 0.45): при переходе к распознаванию капсула стягивается в круг по своей высоте (63 у «Мини», 44 у «Авроры») с отскоком. Появление — вторая пружина (`appear`, ζ ≈ 0.6, перелёт ~10%): капелька раздувается из точки, прозрачность набирается быстрее размера. Окно панели держит запас под оба перелёта и задаётся в том же `DropGeometry` отдельно для каждого стиля (260×119 у «Авроры» под ореол, 170×119 у «Мини» без него), а сдвиг рамки при показе для «Авроры» отключён — он спорил бы с ростом из точки.
- **Подсветка краёв «Авроры» приглушена намеренно** (`ScreenGlowView`): максимум по ЦЕНТРУ нижнего края, под капелькой, и пологим колоколом (маска `centerFalloff`, края — 0.64 от центра: углы приглушены, но не гаснут) спадает к левому и правому нижним углам — прежний вариант с доминантой в углах откачен по решению пользователя. Огибающая уровня здесь мягче, чем у капельки (attack 0.25): полноэкранный свет на резком подъёме читается как вспышка. Не возвращать яркость без просьбы.
- **Живая кромка — только у «Мини»** (`DropLook.mini`, параметры `bleed`/`tide`/`aberration` в `dokaDropGlass`): блик подхватывает цвет и яркость содержимого из-под себя (сэмпл ГЛУБЖЕ преломлённого), бежит вдоль кромки двумя приливами на фазе волны и расщепляет каналы R/B хроматической аберрацией. «Аврора» передаёт эти три параметра нулями и получает прежний ровный блик — отдельной функции шейдера для неё не нужно. Из-за аберрации и подкромочного сэмпла `maxSampleOffset` у `layerEffect` втрое от `refraction`, а не вдвое: с прежним запасом SwiftUI обрежет выборку.
- `DropMotion` — ССЫЛОЧНЫЙ тип намеренно: фаза, пружина и импульс считаются каждый кадр внутри `TimelineView`, а мутировать `@State`-значение прямо в `body` нельзя.

Текста в капельке нет вовсе, поэтому на `.error` стиль падает на классический вид — как `hidden`. Один и тот же `DropSurface` рисует живые панели обоих стилей и миниатюры в пикере (`DropPreview`). `studio` (`StudioRecorderView.swift`) — компактная стеклянная плашка внизу экрана (`glassSurface`, как у классической) с волной-спектром (`StudioWave` на `Canvas` + `TimelineView`: десятки столбиков с колоколообразной огибающей, двухслойный bloom, амплитуда и яркость растут от усиленного уровня микрофона — «драйва», ядро высветляется к белому), таймером по центру и подписью esc снизу.

**Дашборд** (`UI/Main/DashboardSectionView.swift`, секция `dashboard`) — статистика диктовки. Источник данных — `StatsStore` (синглтон, `stats.json` в Application Support/DOKA): lifetime-счётчики (слова, время, сессии) + посуточные бакеты; инкремент в `DictationController` сразу после `history.add`; при первом запуске — одноразовый backfill из истории (флаг `seededFromHistory`), т.к. история капается на 200 записей и lifetime-агрегаты по ней неполны. Чистые вычисления вынесены в `DashboardMetrics` (value-type, тестопригодно). «Скорость речи» и множитель считаются от **активной речи**, а не полной длительности записи: `AudioRecorder` накапливает время, когда уровень микрофона выше порога речи (`speechLevelThreshold`), и отдаёт его как `speechDuration`; `StatsStore` копит `totalSpeechWords`/`totalSpeechDuration`, по которым `DashboardMetrics.speechWPM` считает темп (фолбэк на полную длительность для старых записей без этих данных, чтобы не делить на ноль). `timeSaved` и `speedMultiplier` согласованы — оба от `speechWPM`. Геро-метрики (множитель «в N× быстрее», сэкономленное время) гейтятся тестом скорости печати: пока `SettingsStore.typingSpeedWPM == 0` — вместо них карточка-призыв пройти тест. 30-дневный график «слова в день» — `DailyWordsChart` на `Canvas` (без Swift Charts, как волны рекордера). Тест скорости печати — `TypingTestView` (модальный SwiftUI `.sheet` от дашборда; нужен фокус клавиатуры, поэтому именно `.sheet`, а не borderless `NSPanel`), фразы — `TypingPhrases` (RU/EN по языку интерфейса, без спецсимволов из-за смарт-замен `NSTextField`); измеряет скорость в словах/мин и сохраняет в `typingSpeedWPM`. Единый подсчёт слов и форматтер длительности — `Util/WordCount.swift` (`String.dokaWordCount`, `formatStatDuration`).

**Транскрибация файлов** (`UI/Main/TranscribeAudioSectionView.swift`, секция `transcribe`, в сайдбаре — в группе «Диктовка») — самостоятельная утилита: загрузка аудио/видеофайла (drag-and-drop через `.onDrop([.fileURL])` или `.fileImporter`) → транскрипция → показ сегментами с тайм-кодами и копирование. **Намеренно изолирована от пайплайна диктовки**: не пишет в `HistoryStore`/`StatsStore`, не вставляет текст (`Paster`) и по умолчанию не применяет `ReplacementEngine`. Исключение — тумблер «Применять словарь замен» (`SettingsStore.applyDictionaryToFiles`, по умолчанию ВЫКЛ; осознанно в `SettingsStore`, а не локально в контроллере: это пользовательская линза над выводом, а не параметр файла): замены накладывает выходной слой `Util/TranscriptOutput.swift` (`prepare` → `applyingDictionary`) на показ, «Скопировать» и «Сохранить как…». В фазе контроллера и в журнале всегда СЫРОЙ результат; результат `prepare` терминальный — его не хранят и не перенарезают (`withDetail` пересобирает текст из `rawSegments`/`words`, замены пропали бы), поэтому выключение тумблера мгновенно возвращает исходник. Свой стор — `TranscriptHistoryStore` (библиотека, см. ниже), сторы диктовки не трогает.
- **Сетевой слой** — ОТДЕЛЬНЫЙ `Network/FileTranscriptionClient.swift` (а не боевой `TranscriptionClient`, у которого `response_format` и Content-Type жёстко зашиты под WAV-диктовку): просит `verbose_json` (или `task=diarize` по тумблеру — разделение по спикерам, по умолчанию выкл, дороже, аудио от 3 с), отдельный `URLSession` с увеличенными таймаутами. Multipart-тело собирается во временном файле и уходит ПОТОКОВО (`upload(for:fromFile:)`, `writeMultipartBody`, файл кусками по 1 МБ) — память не зависит от размера файла, лимит 3 ГБ (`maxBytes`). Ловушки: MIME части файла — по явному белому списку Nexara (`mimeFallback`, НЕ `UTType`: системный отдаёт типы вне списка, напр. `.wav → audio/vnd.wave`, который сервер отклонит); декод — одной структурой с опциональным `speaker` (покрывает и verbose_json, и diarize, который игнорирует `response_format` и всегда возвращает свой JSON); деградация ответа (сегменты без тайм-кодов, ответ без сегментов, пустой llm_output) логируется NSLog с усечённым сырым JSON.
- **Состояние** — `FileTranscriptionController` (`@MainActor`, автомат idle→picked→transcribing→done/error, отмена через `Task.isCancelled`), **синглтон** (`shared`, `@ObservedObject`): результат и выбранный файл живут до закрытия приложения и переживают пересоздание вью при переключении секций (`MainWindowView` рендерит контент с `.id(section)`). ВСЕ настройки страницы (язык, диаризация, спикеры, роли, анализ) — локальные `@Published` контроллера, в `SettingsStore` НЕ пишутся: они привязаны к конкретному файлу, а не к пользователю. **Один файл за раз** (осознанно, без очереди/параллели): во время распознавания дропзона заблокирована (`controller.isTranscribing`), иначе новый файл через `accept()` отменил бы текущую задачу; прервать — «Отмена» в плашке прогресса. `transcribe()` ветвится: builtin — async-путь (`submitAsync` → персист job_id в журнал → `waitForResult`), кастомные — прежний sync `transcribeRich`; обе ветки пишут итог в `TranscriptHistoryStore`. Готовый результат — запись библиотеки (`.done(recordID:)`) в раскладке `.inline` компонента `TranscriptRecordView`; открыть запись из полосы «Недавние» — значит перейти в библиотеку (`LibraryNavigator.open`), на странице записи больше не восстанавливаются; `hideResult()` скрывает запись со страницы (крестик в её шапке; запись остаётся в библиотеке). Отмена async-задачи = перестать опрашивать: эндпоинта отмены у Nexara нет, сервер задачу дообработает и тарифицирует — запись честно остаётся «Отменена».
- **Результат** — `TranscriptResult` (карточка в UI называется «Транскрибация»): `segments` для показа, `rawSegments` + `words` для локальной перенарезки, `llmOutput`. «Скопировать» этой карточки кладёт в буфер чистый текст (rich-копия — только у карточки «Анализ»), а форматы (чистый текст / с тайм-кодами / SRT / VTT / по спикерам) идут через меню «Сохранить как…» (`NSSavePanel`) — все строятся ЛОКАЛЬНО из сегментов чистым `Util/TranscriptFormatter.swift` (тестопригоден, как `WordCount`), без доп. запросов к API. Тайм-коды: всегда запрашивается `timestamp_granularities[]=word` — в ОБОИХ режимах сервер отдаёт и сегменты, и пословный массив `words` одним запросом (проверено живыми вызовами; diarize к тому же кладёт `speaker` в сегменты). Имена спикеров — `Util/SpeakerName.swift` (`speaker_N` → «Спикер N+1», `unknown_N` → «Неизвестный N», имена ролей — как есть), имена, заданные пользователем, — поверх (см. «Спикеры и правка текста»); цвет бэйджа — `SpeakerName.colorIndices`: `speaker_N` по номеру, остальные по порядку первого появления в исходниках, пропуская номера `speaker_N` (НЕ hashValue — он рандомизирован на процесс).
- **Гейт builtin**: Nexara-специфичные параметры (`task=diarize`, `num_speakers`, `diarization_setting`, `roles`, `prompt`) попадают в multipart ТОЛЬКО при встроенном сервисе (`isBuiltinService`): у кастомных OpenAI-совместимых API этих полей нет, а `prompt` там значит другое — контекстную подсказку Whisper, LLM-инструкция молча исказила бы транскрипцию. В UI контролы при этом НЕ скрываются, а показываются неактивными (`.disabled` + `.opacity(0.5)`, сноска `transcribe.builtinOnly` в футере карточки): исчезающий контрол не отличить от несуществующей функции. Исключение — разделение по спикерам и подсказка «Спикеры»: они активны везде, вне Nexara их считает `LocalDiarizer` (`usesLocalDiarization`), модель качается сама при включении тумблера, а `canTranscribe` блокирует запуск, пока она не готова. Для кастомного сетевого сервиса запрос и локальная диаризация идут ПАРАЛЛЕЛЬНО (`async let`) — шкала времени общая, сервер распознаёт исходный файл, а декодирование её не сдвигает.
- **Ловушка неактивности**: `SettingsPopup`/`PopUpButton` и `TilePopUpOverlay` — это `NSViewRepresentable` поверх `NSPopUpButton`, а SwiftUI НЕ пробрасывает `.disabled` внутрь них сам. Без явного `button.isEnabled` (читается из `@Environment(\.isEnabled)`) заблокированный снаружи список продолжает раскрываться по клику — у плашек он вдобавок прозрачный и лежит поверх, то есть визуально «серая» плашка работала бы как обычная.
- **Качество диаризации** — под тумблером ряд равноширинных плашек `OptionTile` (`UI/Main/TranscriptionControls.swift` — общий файл контролов страницы и записи библиотеки; видимы при diarize), значения уходят только при diarize и только не-дефолтные: «Спикеры» (Авто/1–10 → `num_speakers`, подсказка серверу — главное лекарство от «вся запись speaker_0»), «Тип записи» (`diarization_setting`: ТОЛЬКО general («Стандартная») и telephonic — третьего значения в доке Nexara нет, не добавлять; для Zoom и звонков с перебиваниями Nexara рекомендует telephonic) и «Роли». Ловушка: SwiftUI `Menu` с кастомным лейблом на macOS схлопывает плашку в текст с шевроном и игнорирует `maxWidth`, поэтому плашка рисуется чистым SwiftUI, а клик ловит растянутый поверх невидимый `NSPopUpButton` (`TilePopUpOverlay`, `isTransparent` — не рисуется, но получает события; копия паттерна `PopUpButton` из SettingsForm).
- **Роли** (`roles`, только с diarize): Выкл / Авто / Свои роли (имена через запятую). Клиентская валидация — чистый `Util/SpeakerRolesParser.swift` (лимиты на число ролей и длину имени, дубли; ошибка блокирует запуск); имена кодируются ТОЛЬКО `JSONEncoder` (экранирование). Лишние говорящие приходят как `unknown_N`.
- **Детализация тайм-кодов** — `TranscriptSegmentSplitter.Config` (пресеты coarse/medium/fine) + enum `TimestampDetail` в том же файле. Нарезка ЛОКАЛЬНАЯ по границам предложений, поэтому смена уровня на готовом результате перенарезает его мгновенно и без нового запроса (`TranscriptResult.withDetail`, всегда от `rawSegments` + `words` с материализацией правок — идемпотентно). Выбор уровня — сессионный `LibraryModel.detail` (не настройка и не параметр запроса: в тело записи уходят только `rawSegments`/`words`, поэтому контроллер строит запрос с `.server`); попап — в шапке карточки «Транскрибация» у записи, в обеих раскладках.
- **LLM-анализ**: список «Анализ ИИ» работает на ЛЮБОМ сервисе, под ним — «Где анализировать»: «На этом Mac» (по умолчанию — в облако расшифровка уходит только по явному выбору; `FileTranscriptionParams.llmLocal`, `effectiveLLMPrompt` тогда nil, после `markDone` контроллер запускает `AnalysisController` по `params.localAnalysisKind(templates:)` — поэтому и «Повторить» снова анализирует локально; заказ страницы важнее глобального автоанализа; нет модели — плашка `LocalAssetStatusView(asset: .llm)` и заблокированный запуск, `isLLMModelMissing`) или «В облаке» (LLM Nexara через `prompt`, только builtin, вне Nexara попап закреплён на локальном). Поля анализа снимка собирает чистая `FileTranscriptionParams.llmFields(preset:customPrompt:template:local:languageName:)` (тесты — `FileTranscriptionParamsTests`): локальный шаблон — только id и имя, облачный — снимок промпта, удалённый шаблон — `off`; контроллер лишь передаёт в неё состояние страницы. Признак «локально» в `pageParams` считается от `providerID` напрямую — `analyzesLocally` там звать нельзя, он через `isBuiltinService` сам читает `pageParams` (рекурсия). Полный список шаблонов (встроенные, затем свои) — единственный `SettingsStore.allAnalysisTemplates`. У записей до флага `llmLocal` = false — они были облачными. Облачный вариант: список — Выкл · шаблоны из «Шаблонов анализа» (встроенные, затем свои) · свой запрос. Промпт шаблона собирает `AnalysisPromptBuilder.nexaraPrompt` (системная инструкция + разделы, БЕЗ текста расшифровки — его подставляет сервер — и без просьбы о тайм-кодах: формат расшифровки для модели Nexara неизвестен); язык ответа — язык записи, иначе интерфейса. В `FileTranscriptionParams` уходит СНИМОК промпта (`llmPreset = template`, текст в `llmCustomPrompt`, плюс `llmTemplateID`/`llmTemplateTitle` — заголовок анализа): «Повторить» отправит ровно его, даже если шаблон изменят или удалят. Прежние пресеты `meetingMinutes`/`summary`/`actionItems` (ключи `transcribe.llm.prompt.*`) из UI убраны, но остаются в enum — старые записи библиотеки декодируются и повторяются ими. Едет одним запросом с транскрипцией; ответ — конверт `{"transcription": {…verbose_json…}, "llm_output": строка|объект}`, декодер двухшаговый (`FileTranscriptionClient.decode` — internal, проверяется scratchpad-harness'ом на фикстурах; llm_output-объект от json_schema сериализуется в читаемый JSON, сам `json_schema` в UI не поддержан). Тело карточки рендерится нативно из Markdown (`UI/MarkdownView.swift`: `MarkdownView` + `MarkdownTableView` поверх чистого `Util/LightMarkdown.swift`; inline — через `AttributedString(markdown:.inlineOnlyPreservingWhitespace)`), без сырых `#`/`**`/`-`/`|`; `---` рендерится как отступ, а не линия. Ловушка таблиц: `Grid` в горизонтальном ScrollView не переносит текст и налезает строками — поэтому ручная вёрстка VStack/HStack с колонками фиксированной ширины; тот же недомер высоты ловит и `Text` — на КАЖДОЙ ячейке обязателен `.fixedSize(horizontal: false, vertical: true)` (fixedSize только на ScrollView не спасает, строки снова налезут). Вертикальные линии колонок — ОДНИМ оверлеем на всю высоту таблицы по известным ширинам (Divider внутри строки тянется только на высоту своей строки и до низа не доходит). Таблица уже карточки растягивается до её ширины (`fittedWidths` + `WidthReader` — GeometryReader фоном, не влияет на интринсик-высоту), шире — скроллится. Контейнер таблицы — серый тинт (`quinarySystemFill`, шапка — `quaternarySystemFill`) + скругление `DS.Radius.badge` на viewport (не на контенте — иначе углы уезжают при скролле). В чистый текст таблица уходит таб-разделённой. «Скопировать» кладёт в буфер ТРИ представления (`ClipboardManager.setRichText`): plain (`LightMarkdown.plainText` — общий источник с форматом «Обычный текст») + HTML (`LightMarkdown.html` — чистая функция, полный документ с `<body>`, проверена harness'ом) + RTF (best-effort конверсия из того же HTML через `NSAttributedString(html:)` — для NSTextView-полей, которые HTML из буфера игнорируют): приложения с rich-вставкой получают таблицы таблицами и списки списками. `<br>` от модели (перенос в ячейках GFM-таблиц) обрабатывается в `LightMarkdown`: рендер → `\n`, plain → пробел, html → настоящий тег. «Сохранить как…» — Markdown (.md, сырой `llm_output`), .txt (`AnalysisSaveFormat`) или PDF (`UI/AnalysisPDF.swift`: A4 с полями 2 см всегда — «как в системе» на маке с регионом США дало бы Letter; шапка — название записи, название анализа, «Запись: дата», «Анализ: модель, дата»; внизу «N / M»; тайм-коды — текстом). Ловушки PDF, каждая замерена по файлу: (1) документ собирается НАТИВНО из блоков `LightMarkdown` (`NSTextTable` с ширинами колонок от чистого `PDFTableLayout`: узкие колонки — в одну строку, остаток делят длинные), а не `NSAttributedString(html:)` — импорт HTML сжимал короткие колонки до буквы в строке («С/р/о/к») и терял точки нумерации; (2) шрифт — Helvetica Neue и Menlo, НЕ системный: у SF Pro кириллическая «к» — общий глиф с латинской «ĸ» (kra), и из PDF копировалось «Теĸст»; (3) у `NSTextTable` нельзя ставить `margin` — он вычитается из ширины таблицы, воздух над ней — пустой строкой нужной высоты; (4) `NSTextView` только TextKit 1 (`usingTextLayoutManager: false`) — таблицы TextKit 2 не рисует; (5) цвета фиксированные: `labelColor` в тёмной теме белый. Проверять вид — растеризацией PDF в стенде (PDFKit → bitmap), а не на глаз по превью. «Анализ» и «Транскрибация» сворачиваются общим `CollapsibleReveal` (`UI/Components.swift`). Повторного ОБЛАЧНОГО анализа на готовом результате НЕТ (осознанно убран; локальный — см. «Локальный ИИ-анализ»): у API нет анализа готового текста, повторный запрос гонял бы файл целиком с повторной тарификацией — анализ выбирается только до запуска транскрибации.
- **Async-режим (только builtin)** — те же методы `FileTranscriptionClient`: `submitAsync` (тот же multipart на `{endpoint}/async`, сразу возвращает `job_id`), `fetchJobStatus`/`decodeAsyncStatus` (конверт `{job_id, status, created_at, completed_at, result, error}`; при `complete` поддерево `result` ре-сериализуется и уходит в общий `decode` — llm-конверт лежит ВНУТРИ `result`, проверено живыми вызовами), `waitForResult` (опрос раз в 4 с; сеть/429/5xx транзиентны — интервал растёт до 30 с и опрос переживает обрыв и сон Mac; 401/402/404/`status:"error"`/`badResponse` фатальны; дедлайн — постановка + 12 ч, `TranscriptHistoryStore.serverResultLifetime`). Результат на сервере живёт 12 ч; 404 опроса (`{"detail":"Job not found"}`) → `jobNotFound`. Особенность паритета: при `prompt` (LLM-анализ) сервер НЕ отдаёт `words` — в обоих режимах, sync и async (проверено живьём), это не регрессия. Битый файл отклоняется синхронно на сабмите (HTTP 400), до статуса `error` дело не доходит.
- **Библиотека транскрибаций** (бывшие «Недавние») — стор `Storage/TranscriptHistoryStore.swift` (синглтон, имя сохранено) поверх файлового слоя `Storage/TranscriptLibraryFiles.swift`, модели — `Storage/TranscriptLibraryModels.swift`. Раскладка в `AppDataFolder.currentURL/transcripts/` (переезжает с «Папкой данных» без правок `migrateToTarget`): `<id>/meta.json` — запись `FileTranscriptRecord`, **источник правды**; `index.json` — лишь КЭШ списка; `<id>/transcript.json` — `TranscriptBody` (машинный `StoredTranscript` не мутируется + `analyses` + `edits`); `<id>/text.txt` — плоский текст для поиска; `<id>/audio.m4a` — архив звука. Ловушки, каждая — про потерю данных: (1) пропавший/битый индекс ВОССТАНАВЛИВАЕТСЯ сканированием `meta.json` (битый сохраняется как `index.corrupt-*`), а не становится «пустой библиотекой»; sweep трогает только корзину `*.deleting-*`, `*.part` и папки без meta — папки с телами автоматически не удаляются никогда; (2) удаление — сначала rename папки в корзину, потом индекс; (3) у незавершённых записей индекса meta перечитывается на старте (крэш между записью meta и индекса); (4) весь дисковый I/O — одна последовательная очередь (порядок чтения после записи); `exit()` её не ждёт, поэтому `applicationWillTerminate` зовёт `flush()`; удаление = rename в корзину → индекс → `emptyTrash()` отдельным блоком; после переноса «Папки данных» — `freeze()` до перезапуска: стор (`isFrozen`) отклоняет новые транскрибации, удаления, архивацию, переименование и «Стереть всё аудио» (последние два когда-то меняли только память: запись пропускалась, и после перезапуска возвращались старые заголовки и целое аудио) (синхронное создание папки архива иначе воскресило бы стёртую старую папку, и возврат на путь по умолчанию упал бы с `targetNotEmpty`); (5) миграция журнала v1 `transcripts.json` синхронна в `init` (до `prune`/`resumePendingJobs`), идемпотентна по флагу `migratedFromV1`, легаси переименовывается в `transcripts.v1.bak` (удаляется через 14 дней). Лимита 50 больше нет — остаётся только срок хранения. Источник правды анализа — `TranscriptBody.analyses` (анализ Nexara из запроса — первый элемент); `llmOutput` в результат подставляет `makeResult` из анализов, поэтому удалённый анализ не всплывает. Показанная запись — `TranscriptDocument` (`UI/Main/Library/`), фаза контроллера — `.done(recordID:)`: копии результата в фазе нет, вывод (нарезка + словарь для файлов) мемоизирован документом. Запуск — `FileTranscriptionController.start(source:params:target:)` на снимке `FileTranscriptionParams` (все Nexara-гейты — от его `providerID`, маршрут — `SettingsStore.resolveRoute(providerID:)`: удалённый пресет — ошибка, а не тихий уход на встроенный сервис); `jobID` персистится ДО проверки отмены (иначе оплаченная задача теряет id). Архив звука (`Audio/SourceAudioArchiver.swift`, AAC 24 кбит/с 16 кГц mono, у видео только звук; тумблер `saveTranscriptAudio`, по умолчанию ВКЛ) — задача стора, отмена распознавания её не убивает; фиксация `.part` → `audio.m4a` только если meta записи ещё на месте. Поиск — `Util/LibrarySearch.swift` (регистр и ё=е, но НЕ `diacriticInsensitive` — он склеил бы «й» и «и») + actor `Storage/TranscriptTextIndex.swift` (ленивые тексты из `text.txt`). События: `finished` (готово/ошибка, которую пользователь ждал; безнадёжные записи на старте — `notify: false`) и `bodyChanged`. Recovery — `resumePendingJobs()` один раз на старте (`AppDelegate`): sync-сироты кастомных сервисов → «прервано перезапуском», builtin старше 12 ч → «результат истёк» без сети, остальные добираются фоновыми Task со стаггером 0.5 с (лимит Nexara 10 rps); credentials ВСЕГДА builtin (незавершённая async-задача — нексаровская, даже если пользователь переключил сервис), результат — только в стор, фаза контроллера остаётся idle. UI — секция «Библиотека» (см. ниже). Срок хранения — `TranscriptRetention` (`Storage/Retention.swift`; 12/24/48/72 ч, 7/30 дней, всегда). Дефолт — «всегда» через `TranscriptRetention.resolve(stored:)`: ключ пишется только при явном выборе (`didSet`), поэтому его отсутствие = «не выбирал» (прежний дефолт 12 ч был согласован с жизнью результата на сервере, пока журнал был списком «недавних»; у библиотеки смысл другой). Сокращение срока в «Расширенных» подтверждается алертом, если под новый срок попадают записи (удаление безвозвратно, вместе с аудио и анализами); чистка завершённых записей — на старте и в `.onChange`. Готовность сервиса на странице «Транскрибация» мемоизирована (`@State hasKey`, чтение ключа `Task.detached` в `.task(id: providerID)`) — прежний вызов `isServiceReady` из тела читал Keychain синхронно на каждой перерисовке.
- **Спикеры и правка текста** (`Util/TranscriptEdits.swift`; UI — `UI/Main/Library/SpeakerEditingViews.swift` и `TranscriptSegmentsView`) — переименование и слияние спикеров, переназначение реплики (или её части), правка текста реплики с возвратом. Правки живут в `TranscriptBody.edits: TranscriptEdits?` поверх НЕмутируемого `transcript` (ручной декодер тела читает их через `try?`, внутри массивы — поэлементно `Lossy`, пересекающиеся якоря отбрасываются: битая правка не стоит расшифровки) и применяются ЕДИНСТВЕННОЙ точкой `TranscriptBody.makeResult` → `TranscriptResult.withEdits(_:detail:)` (через неё же `withDetail`): показ, копирование, экспорт (`LibraryModel.exportResult`), `text.txt`/поиск и сводка (`saveBody`), будущий вход анализа (`TranscriptFormatter.llmTranscript`) — обходить её нельзя. Якорь правки — `EditAnchor.words` (диапазон индексов ИСХОДНЫХ слов) или `.segment(i)` для бессловных результатов (Nexara с анализом ИИ): правка переживает любую детализацию, а «вернуть» = удалить правку. Правки материализуются ПОД сплиттером (`materialize` → `TranscriptSegmentSplitter.splitWithSources` → `targets`): слова раздаются исходным сегментам тем же `assignWordRanges`, правка текста подставляет свои токены (токенизация — тем же правилом, что `joinWords`; тайминги 1:1 при равном числе токенов, иначе пропорционально внутри отрезка), сегмент режется на куски по сменам спикера. Без правок — побитно прежний результат (страховка — старые тесты сплиттера). Непоправленный сегмент сохраняет серверный текст с пунктуацией; частичная правка сегмента собирает его текст из слов. Вью передаёт в правку `EditTarget` (адрес в исходниках + задетые правки), а не индекс строки: правка, задевшая чужую правку, ПОГЛОЩАЕТ её целиком (токены за границами строки — `prefix`/`suffix`), устаревший адрес отвергается `isValid`. Правка текста выравнивает переназначения внутри своего якоря под спикера первого слова (все её токены получают его — иначе спрятанное слиянием переназначение после «Отделить» лежало бы под правкой невидимым), а неприменимые к исходникам правки (битые данные: якорь через границу сегмента) документ отбрасывает перед валидацией (`sanitized`) — иначе они навсегда блокировали бы соседние реплики. Операции — только через `TranscriptDocument` (`renameSpeaker`/`mergeSpeaker`/`unmergeSpeaker`/`setSegmentText`/`revertSegmentText`/`reassignSegment`/`revertSegmentSpeaker`/`resetAllEdits`), сохранение — `store.saveBody` по Return или выбору в меню; счётчик `revision` растёт на каждую правку, включая сброс (для «анализ устарел»); при замороженной библиотеке (`isFrozen`) правки не принимаются. Слияния транзитивны без циклов (`merge` пишет только канонические id); имя влитого цель ПОКАЗЫВАЕТ, но не хранит (`label` берёт его из `mergedIDs`) — скопированное имя после «Отделить» осталось бы у обоих, и «по спикерам» склеило бы их снова; «по спикерам» группирует по ОТОБРАЖАЕМОМУ имени; цвет считается по исходным id, затем переназначения и цели слияний (слияние не перекрашивает цель); `SpeakerName.index(of:)` принимает только до 6 ASCII-цифр — битый id с диска («speaker_-1») иначе дал бы отрицательный индекс палитры (краш) или переполнение; «Новый спикер» — `SpeakerName.nextID` с учётом ключей слияний и имён (иначе новый спикер получил бы id влитого). Словарь для файлов применяется И к правленому тексту, а редактор правит текст ДО словаря (`TranscriptDocument.source(detail:)`). «Распознать заново» правки не переносит (новая запись, id диаризации не совпадают). Ловушки UI: `.textSelection(.enabled)` съедает двойной клик — у редактируемых строк её нет (копирование — «Скопировать реплику»); бэйдж спикера — `Button` + `.popover`, НЕ `Menu`; состояние редактора — у строки (`@State`: ввод не перерисовывает список), по потере фокуса, перенарезке и уходу строки из ленивой ленты правка СОХРАНЯЕТСЯ, пустое не сохраняется; кнопки редактора `.focusable(false)` — иначе при полном доступе с клавиатуры клик по «Отмена» забрал бы фокус у поля и сохранил; пока у строки открыт редактор или поповер спикера, клавиши плеера и Esc «назад» молчат, а лента НЕ следует за плеером (`segmentInteractions` у `TranscriptRecordView` → `suspendsFollow`): автопрокрутка выгрузила бы строку из ленивой ленты и сохранила недописанное; после Return/Esc фокус возвращается на корень записи; устаревший адрес при сохранении (реплику сбросили или вернули иначе, `EditOutcome.stale`) оставляет редактор открытым с черновиком; меню «⋯» строки создаётся с первого наведения и дальше живёт (лента страницы «Транскрибация» не ленивая — сотни AppKit-меню разом; убирать по уходу курсора нельзя — курсор уходит в открытое меню); контекстное меню строки перекрывает меню списка, поэтому в нём есть «Скопировать всё»; поповер спикера по клику мимо сохраняет имя, Esc — отмена; чтение тела с диска не затирает в кэше стора свежее тело, сохранённое, пока чтение стояло в очереди (`loadBody`).

Удаление модели гасит анализ и выгружает движок.
- **Вход модели** — `TranscriptLLMInput`: строки «[м:сс] Имя: текст» тем же форматом, что экспорт «тайм-коды + спикеры» (`TranscriptFormatter.llmTranscript`), его же разбирает `TimestampLinker`. Детализация входа ФИКСИРОВАННАЯ (`TranscriptLLMInput.detail == .medium`), а не пользовательская: иначе смена детализации меняла бы отпечаток и все анализы разом становились «устаревшими»; `.server` не годится — Parakeet отдаёт один сегмент на всю запись, и нарезать такую строку нечем. Подряд идущие реплики одного спикера склеиваются до 45 с. Из текста вырезаются `<|` и `|>`: токенизация идёт с `parse_special`, и расшифровка, где кто-то произнёс «<|im_start|>», подменила бы роль в промпте. Словарь замен к входу применяется (тот же выходной слой, что у показа), а отпечаток считается от текста БЕЗ словаря: словарь — линза пользователя, его тумблер не должен объявлять анализы устаревшими.
- **Длинные записи** — `LLMChunker`: план частей по токенам с перекрытием ~200, строки НЕ режутся (строка = реплика), план всегда движется вперёд, потолок 40 частей. Map (конспект части, резерв ответа 640) → reduce (сведение, резерв 1536). Глубже одного уровня сведения не идём — это пересказ пересказа; не влезло — `analysis.error.tooLong`. Известная слабость (замер 5.10.2026 на склейке лекции 84–126 мин): через части 4B-модель выдумывает участников из упомянутых в разговоре имён, ставит тайм-коды [0:00] и теряет решения и задачи; конспект части упирается в резерв 640 (сам по себе пишет 1 500–2 000 токенов на ~45 мин), но и с резервом 2048 итог не лучше — дело в промптах части и сведения. Переделка — отдельной задачей и только на настоящих записях 2+ ч с несколькими спикерами; один проход на 32k этой слабости не имеет.
- **Шаблоны** — `AnalysisTemplate` + `BuiltinAnalysisTemplate` (резюме, протокол встречи, задачи, конспект лекции, интервью, главы). Встроенные НЕ хранятся на диске: структура (формат раздела, колонки таблицы, нужны ли тайм-коды) в коде, тексты — в `.strings`, поэтому они следуют языку интерфейса. Свои — `SettingsStore.analysisTemplates` (JSON в UserDefaults, ручной `init(from:)` с `decodeIfPresent`, как у `ReplacementRule`). Импорт и экспорт — чистый `Util/AnalysisTemplateTransfer.swift` (пачку файлов разбирает `importFiles`: уникальные имена и отказы по файлам; вью только сохраняет итог и показывает алерт), кнопки «Импортировать…» (под «Новым шаблоном», несколько файлов сразу, `NSOpenPanel` — не `.fileImporter`, шит сам вложенный) и «Экспортировать…» (нижняя строка; у встроенного — его текст на языке интерфейса) в `AnalysisTemplatesSheet`. Экспорт — свой JSON без id; под Memento он НЕ подгоняется: своих шаблонов из файла Memento не читает (у него они в базе). Импорт понимает и свой формат, и Memento (`name/description/sections[{title, instruction, format, item_format?}]`): `string` → связный текст, `item_format` с шапкой таблицы Markdown → таблица с колонками из шапки без `**`, `pipeline` игнорируется (шаблон `custom_prompt_v1` — один раздел с длинной инструкцией). Id всегда новые (экспорт встроенного после импорта — свой шаблон), длинное имя обрезается, пустое — имя файла, остальное — `validationError` (отказ файла с причиной в алерте), совпавшее имя — « (2)» (`AnalysisTemplateNames`, без учёта регистра); импортированные сохраняются сразу. Живые шаблоны Memento (`/Applications/Memento.app/Contents/Resources/templates/*.json`) в репозиторий не класть — фикстуры тестов синтетические.
- **Контроллер** — `UI/Main/AnalysisController.swift`, синглтон (секции пересоздаются `.id(section)`, `@State` анализ бы не пережил). Один анализ на приложение; стадии `loadingModel/reading/part/combining/writing`; живой текст публикуется не чаще раза в 120 мс (разбор Markdown на каждый токен съел бы больше, чем сама генерация); отмена НИЧЕГО не сохраняет. `update(recordID:)` пишет фазу, только если идёт анализ той же записи, — отменённый анализ не воскресает запоздавшим событием движка. Тело перечитывается из стора ПЕРЕД сохранением анализа: за минуты работы правки пользователя могли уехать. Взаимоисключение — только с ЛОКАЛЬНЫМ распознаванием (конкуренция за ускоритель); сетевое распознавание и диктовка анализу не мешают.
- **Хранение** — `TranscriptBody.analyses` (поля `source`/`inputFingerprint`/`truncated`/`generationSeconds` были заведены ещё в Ф2), `store.addAnalysis`/`deleteAnalysis`, «устарел» — по расхождению `inputFingerprint` с текущим отпечатком (мемоизируется документом по версии тела). У анализа Nexara отпечатка нет, устаревшим он не помечается.
- **UI** — `AnalysisPanelView` в `TranscriptRecordView` (обе раскладки): список анализов попапом, метаданные, «Скопировать» (rich), «Сохранить как…», «Повторить», «Удалить» со своим `.alert` НА ПАНЕЛИ (у записи уже есть свой), ряд запуска (шаблон · язык ответа · «Проанализировать»), «Свой запрос» полем. Модели нет — `LocalAssetStatusView(asset: .llm)` прямо в панели. Тайм-коды кликабельны: `MarkdownView(_:seekDuration:)` прогоняет текст через `TimestampLinker` ТОЛЬКО при рендере — в хранимый markdown, копирование и экспорт ссылки не попадают. Редактор шаблонов — `AnalysisTemplatesSheet` (`.sheet`, нужен фокус клавиатуры). Карточка «Анализ ИИ на этом Mac» в «Сервисе» видна при любом сервисе: статус модели, автоанализ с выбором шаблона, «Шаблоны анализа…».
- **«Угадать имена»** (`Util/SpeakerNameSuggester.swift`, `UI/Main/SpeakerSuggestionController.swift`, `UI/Main/Library/SpeakerSuggestionViews.swift`) — кнопка в полосе спикеров записи (по мотивам Memento 1.1). Разделение труда — по замеру на Qwen3.5-4B: модель хорошо НАХОДИТ имена, но путает, КОМУ они принадлежат (отдала имя упомянутой третьей и пропустила обращение с ответом), а «дубликаты» предлагала склеить двух разных людей с разными именами. Поэтому модель только выписывает имена, прозвучавшие как представление или обращение (JSON, жадная генерация `LLMSampling.greedy`, ~1,7 с), а дальше всё решает чистый код: `attribute` — «меня зовут Х» (только точная форма; после «я»/«это» имя должно закрывать фразу или стоять перед запятой — «я Марину спросила», «это Марина сделала» не в счёт) голосует за говорящего, обращение в последней фразе реплики — за того, кто отвечает следом, в первой фразе ответа («Да, Анна.») — за того, кому отвечают, упоминание без запятой — никому, ничья — не угадываем; `continuationMerges` — пара спикеров, где реплика одного обрывается без точки, а следующая начинается со строчной буквы, если у них нет разных имён. Модель видит не id диаризации, а метки S1…Sn (строки — тем же `TranscriptLLMInput`); длинная запись режется по бюджету окна (`fittingLineCount`, пометка «смотрел первые N мин»). Предложения — только в памяти контроллера, применяются кнопкой через `renameSpeaker`/`mergeSpeaker` документа (откатываются «Сбросить правки»); спикер, переименованный вручную, подсказок не получает. Взаимоисключение: контекст модели один — анализ не стартует поверх подсказки (`Availability.busySpeakerNames`) и наоборот; локальное распознавание — так же, как с анализом; удаление модели и диктовка на маке с малой ОЗУ подсказку отменяют.
- **Автоанализ** — `SettingsStore.autoAnalysis`, по умолчанию ВЫКЛ (анализ идёт минутами и греет Mac). Запускается из `FileTranscriptionController` после `markDone` через тот же гейт `availability`, поэтому без модели и при занятом анализе молча не стартует.

**Губы (эксперимент)** (`Sources/DOKA/Lips/`, `Storage/LipData{Files,Store}.swift`, `UI/LipMirror*.swift`, `UI/Main/LipsSectionView.swift`) — сбор пар «видео губ + текст» во время обычной диктовки для отдельного проекта обучения чтению по губам (WISLIP, приватный, на Python): DOKA только собирает, учит WISLIP. Видимость — тумблер `SettingsStore.lipsExperiment` в «Расширенных» (по умолчанию ВЫКЛ): он добавляет `MainSection.lips` в конец группы «Диктовка» (`MainSection.sidebarGroups(lipsEnabled:)`; минимальная высота окна при этом 608 — `MainWindowLayout.minHeight`, общий источник для SwiftUI-рамки и `NSWindow.minSize`, который `WindowManager` ставит явно по подписке; замер: пунктам сайдбара нужно 602). Сбор — `lipsLearn` («Учить губы»); действует только `lipsCaptureEnabled = lipsExperiment && lipsLearn`.
- **Камера** — `LipCapture` (`@MainActor`-фасад, `Lips/LipCapture.swift`) + `LipCameraEngine` (`Lips/LipCameraEngine.swift`, там же выбор камеры и сводки лога; очереди `sessionQueue`/`videoQueue`/`visionQueue`/`renderQueue`). Работает ТОЛЬКО на время записи: `beginTake` в `startRecording` (раньше `recorder.start` — камера прогревается дольше), `abortTake` (= `stopCamera` + `discard`) в центральном хуке `transition` при уходе из `.recording`. Без разрешения или места (< 2 ГБ; значение — кэш `LipFreeSpace`, опрашиваемый фоном: запрос тома ~30 мс, на главном потоке при старте каждой диктовки нельзя) дубля нет, а без рабочей камеры он отбраковывается как «Сбой камеры» — диктовка от камеры не зависит никогда; спящая встроенная камера (крышка закрыта) пропускается (`LipCameraChooser`), настроенная сессия перенастраивается, если её камера уснула; разрешение запрашивается только кнопкой в разделе (`.notDetermined` → дубля нет, иначе системный запрос всплыл бы посреди диктовки). Ловушки: формат 1280×720 и 30 к/с держатся, только пока устройство залочено во время `startRunning` (на macOS нет пресета `inputPriority`; без лочки в темноте 15 к/с); Center Stage выключается (`centerStageControlMode = .app`) — он двигает кадр; Continuity Camera не используется (нужен свой ключ Info.plist); превью-слоя (`AVCaptureVideoPreviewLayer`) у сессии НЕТ и не возвращать — зеркало рисует кадры из `AVCaptureVideoDataOutput` (см. «Зеркало»), а слой, добавленный в работающую сессию, её переконфигурирует (разрыв кадров = ложная «смена сцены» у трекера WISLIP); соединения без зеркала — отражает только рендер зеркала; `NSCameraReactionEffectGesturesEnabledDefault = false` в Info.plist (фейерверки macOS по жестам испортили бы видео). `LipTakeRecorder` пишет сырой полнокадровый HEVC и `capture.json` (хост-время и яркость кадров, боксы лица Vision ≈ номинал/2, эффекты камеры).
- **Vision и журнал** — Vision (`LipFaceTracker`: явно revision 3 + `constellation76Points`, губы 14 + 6 точек, глаза — центроиды контуров, не зрачки: те неточны при моргании) идёт на КАЖДОМ кадре, который застал его свободным: флаг `visionGate` (`OSAllocatedUnfairLock`) берётся на `videoQueue` и снимается `defer` в блоке `visionQueue` даже при ошибке — на `videoQueue` только проба замка и `async`. Журнал лица в `capture.json` пишется прежним ритмом — `LipJournalCadence`: первый результат дубля или `host − last ≥ 1,5 × номинал кадра` (≈15 Гц при 30 к/с, 12,5 при 25), смысл `box`/`count` (бокс и число лиц ДЕТЕКТОРА) прежний — договор с WISLIP (`multiFaceFrames`, `faceCoverage`, кроп) не изменился. **Видны ли губы** решает `LipVisibility` (на `visionQueue`, сразу после Vision, — одно решение для журнала, фазы и маски): Vision на закрытом ладонью рте лицо НЕ теряет, а дорисовывает губы по форме лица, и маска ложилась на ладонь, а кадры уходили в WISLIP как хорошие. Улика — его же оценка неточности точек (`precisionEstimatesPerPoint`, есть только у созвездия 76): губы скрыты, если неточность внешнего контура > 0,0120 и больше, чем у глаз, в 1,04 раза (поворот головы поднимает неточность ВСЕХ точек — его отсекает сравнение с глазами), или если точка губ за краем кадра; гистерезис — выход ниже 0,0100 или когда глаза не точнее губ. Пороги — стенд 6.10.2026 на 42 дублях владельца: обычный рот при «губы хуже глаз» — не выше 0,0112, ладонь — не ниже 0,0137; палец у губ (≤ 0,0103) закрытым не считается. В журнал — `Face.lipsHidden` (пишется только `true`, старый журнал читается как «видны»), счётчик — в лог дубля. Если когда-нибудь трекать через `inputFaceObservations` — такие результаты в журнал не писать: Vision возвращает КОПИИ входа (бокс не обновляется, `count` = числу входов). Лог дубля (`NSLog` в `end()`) печатает Vision p50/p95, «обработано N из M», сбросы кадров по причинам, рендер и латентность зеркала (перцентили — `Util/Percentile.swift`, тот же ближайший ранг, что у кропа дубля). Ловушка: на macOS 27 текст NSLog DOKA в системном логе — `<private>`, через `log show` эти замеры не прочитать.
- **Синхронизация** — шкала клипа = шкала WAV: `AudioRecorder` отдаёт `RecordingTiming` (хост-время первого буфера из `AVAudioTime` tap, `presentationLatency` входа, начало речи `SpeechOnsetTracker` — первые 0,2 с и одиночные буферы не в счёт, иначе «речью» стал бы сигнал «Pop»; дрейф `HostClockDriftTracker` — потерю буферов движком). Кадры переводятся на шкалу WAV через `CMSyncConvertTime` и `LipSync.wavTimes`.
- **Судьба дубля — одним местом, как у WAV** (`DictationController.settle`): пара фиксируется только при `.succeeded` + `.live` по снимку подписи `lipCaption` (берётся на `outcome = .succeeded`, а НЕ сразу после фильтра — иначе Esc во время кодирования m4a сохранил бы пару по отменённой диктовке); иначе — `discard`. Подпись — `raw` ПОСЛЕ `HallucinationFilter` и ДО `ReplacementEngine` (нужно сказанное). Ветки гейта, Esc, ошибки — `discard`; в слот повтора уходит `withoutLipTake` (повтор пар не даёт); дубль, не забранный `finishRecording`, выбрасывает хук `transition`. Фиксация синхронно берёт жёсткую ссылку на WAV (его тут же удалит ветка `.succeeded`).
- **Хранилище** — `LipDataStore`: дубль уходит в обработку, когда сошлись ДВА события в любом порядке — камера дописала сырьё (`captureFinished`) и диктовка зафиксирована (`commit`, `job.json`); после перезапуска — по файлам (`sweep`). Обработка по одному дублю фоном: `LipTakePlanner` (прогрев экспозиции `LipSync.stableStart`, расписание CFR `LipSync.schedule`, ОДИН фиксированный кроп на дубль `LipCropPlanner` — квадрат ≥ 2,3 лица и ≥ 384 px, WISLIP сам ищет лицо и трекает; решение `LipTakeVerdict`) → `LipTakeEncoder` (512×512 H.264 постоянных 30 к/с + AAC из WAV ЦЕЛИКОМ — без звуковой дорожки препроцессинг WISLIP виснет; голова и хвост без камеры — повтор крайнего кадра, окно настоящего видео — `validFrom`/`validTo`). Камера холодная почти в каждом дубле, поэтому «камера проснулась после начала речи» — не отбраковка, а счётчик «Начало без видео». Отбраковка с причинами (`LipRejectReason`, счётчики в `stats.json`): пустой текст, сбой камеры, рассинхрон, < 24 к/с, слишком коротко (окно видео < 1,5 с — проверяется ДО губ, иначе пряталось бы за «губ не видно»), губ не видно (`noLips`; rawValue прежний `noFace` — ключ счётчика в `stats.json`), лицо мелкое, видео покрывает < 50 % речи, ошибка кодирования. Раскладка `LipData/` — ФИКСИРОВАННЫЙ путь рядом с `Models` (`AppDataFolder.lipDataURL`, за «Папкой данных» не следует: WISLIP читает по постоянному пути): `pending/<id>/{raw.mp4,capture.json,audio.wav,job.json}` → `takes/<id>/{clip.mp4,meta.json}` (meta пишется ПОСЛЕДНИМ, это источник правды), корзина `*.deleting-*` (`DiskTrash`). Имена — только из `LipDataLayout` (`Lips/LipTakeModels.swift`): их берут и `LipTake`, и `LipDataFiles`. `meta.json` v1 — договор с импортёром WISLIP (даты ISO 8601: умолчание `JSONEncoder` Python не прочтёт); менять поля — только с `schemaVersion` и импортёром. `faceCoverage`/`faceGaps` с 6.10.2026 считаются по ВИДИМЫМ губам (лицо найдено, губы в кадре и не закрыты), имена полей прежние: импортёр режет фразы «вне `faceGaps`», и закрытые ладонью куски выпадают так же, как пропуски лица; кроп — по-прежнему по всем боксам лица. «Удалить всё» не трогает сам корень `LipData`, на `ioQueue` только переименовывает в корзину (стирание — фоном: выход приложения ждёт `ioQueue`) и увеличивает эпоху данных — worker, начавший обработку раньше, после любого ожидания ничего не пишет. Второй проход ПАДАЕТ (→ «ошибка кодирования»), если кадра из журнала нет в сыром файле, ридер упал или звук короче видео — иначе пара сохранялась бы с застывшим кадром. События дубля для хранилища — «записан» и «выброшен» — идут из одной видео-очереди и на главный поток через FIFO `DispatchQueue.main`; «выброшен» шлётся только уже записанным, поэтому хранилище не держит id выброшенных дублей. Исход каждого дубля — `outcomes` (`.saved` / `.rejected(id, причина)`); сбой самой фиксации (не сохранился звук или `job.json`) — тоже исход, `.rejected(id, nil)` «данные потеряны»: иначе фраза тренировки навсегда висела бы «в обработке». Выброс такого дубля — замыканием `discardTake` из `init`, тесты не поднимают камеру. Ловушка ридера: без декодирования `AVAssetReader` отдаёт и служебные пустые буферы (`numSamples == 0`) — их пропускать. Ловушка меток: второй проход берёт исходный кадр с БЛИЖАЙШЕЙ меткой, а сырой файл пишется с масштабом времени 90 000 — при умолчании 1/600 и пороге «чуть раньше цели» видео уезжало на кадр вперёд звука, а число кадров оставалось верным (`testEachOutputFrameShowsItsScheduledSource`).
- **Зеркало** (`LipMirrorController`, `LipMirrorView`, `LipMirrorVideoNSView`) — чёрная плашка в духе NotchNook, вытекающая из кромки экрана вогнутыми «плечами». Главный принцип — **тот же кадр, те же точки**: картинка зеркала рендерится из ТОГО ЖЕ `CVPixelBuffer`, по которому Vision посчитал точки, и ставится вместе с маской в ОДНОЙ транзакции без анимаций (задержка зеркала ~1 кадр — решение владельца). Прежний вариант — живой превью-слой с неявной анимацией 1/15 с и маска по кадру 1–4 кадров давности — давал «рваную» маску: у `CAShapeLayer.path` неявной анимации НЕТ (`CAShapeLayer.h`), маска прыгала, а видео под ней доезжало. Конвейер в блоке `visionQueue`: `LipMirrorPipeline.region` (окно камеры после прошлого кадра) → на `renderQueue` ПАРАЛЛЕЛЬНО с Vision `LipMirrorRenderer` (`CIContext` на Metal, выход sRGB — НЕ NSNull-настройки кодера, там YUV→YUV без управления цветом; `clampedToExtent` → `LipMirrorGeometry.ciTransform` → `createCGImage(... deferred: false)`: отложенный CGImage держал бы буфер камеры и давил на пул захвата) → журнал → `LipMirrorPipeline.update` (One Euro точек `LipOneEuro.lips` 0.3 / 44 / 2 → `LipContours.vision` → `LipMesh` с `LipMeshCalibrator` → `LipMaskHold` → камера) → `LipMeshPaths` (готовые `CGPath` вне главного потока, через ТОТ ЖЕ регион, что и картинка) → `LipMirrorFeed` («последний побеждает»; кадр чужого дубля или чужого `LipMirrorTarget` отбрасывается; `attach` с владельцем — `detach` снимает только свою подписку) → вью (`picture.contents` + пути маски под `setDisableActions(true)`; маска прячется при фазе ≠ `.face`). Скрытые губы (`lipsHidden`) сетки не дают и в фильтр точек не идут — маска гаснет через `LipMaskHold`, а камера остаётся на рте: зеркало показывает ладонь, то есть ПОЧЕМУ губ не видно. Фаза `.noLips` («Губ не видно») — губ не видно дольше 0,5 с по любой причине: лица нет, губы за краем или закрыты. Буфер камеры держится max(Vision, рендер), `renderQueue` никогда не ждёт `visionQueue`. В буфер камеры НЕ рисовать — маска попала бы в `raw.mp4` и `clip.mp4`. **Контуры** — `LipContours`: таблица индексов Vision (14 точек: уголки 13 слева в кадре и 7 справа, стабильны на 100 % кадров; у созвездия 65 — 9/5) с проверкой правдоподобия, иначе запасной путь вдоль оси глаз. Внутренний контур Vision — 6 точек БЕЗ уголков («коробка вокруг зубов», ~44 % ширины рта): его проводят через ВНЕШНИЕ уголки — ошибка формы против MediaPipe 7,6 → 1,7 % межглазного; перекрещённый на сомкнутых губах схлопывается в линию. Адаптер `LipContours.mediaPipe` (4 кольца по 20 точек) — про запас, если владелец решит перейти на MediaPipe (рекомендация — CoreML-конвертация FaceMesh: годится и для будущей DOKA iOS). Узлы — по параметру индекса Vision с калибровкой долей дуги на первых 15 кадрах дубля (по длине дуги узлы скользили бы). **Камера** — `LipMirrorCamera`: масштаб `max(межглазное, κ·box.h)` (κ = 0,351 — p5 отношения, медиана раскачивала зум), окно `zoom` 2,7 × 0,836 × масштаб (2,7 — решение владельца, 2,2 было слишком близко), центр — середина уголков + 0,05 масштаба вниз; от речи не «дышит». В покое — One Euro по центру и ln W; въезд, выезд, повторный захват и скачок цели — глайд 0,35 с smoothstep с якорем (рот не уплывает от центра), скачок сравнивается с ПРОШЛОЙ целью, а не с отфильтрованной (иначе быстрый поворот головы запускал цепочку глайдов и рот уходил за край окна); потеря лица < `lostAfter` 0,5 с — удержание (на эту же константу ссылается `LipCapture.lipsLostAfter`), мигающее лицо камеру не «качает»; Reduce Motion — без глайдов. **Маска** — палитра «Авроры» (решение владельца): внешний контур `DS.glow`, к внутреннему кольца перетекают в `DS.Aurora.indigo` (`Color.mix`), точки — `DS.Aurora.waveHighlight`; только производные существующих токенов. Наложение «экран» (`compositingFilter = "screenBlendMode"` на каждом слое, 80 %) — маска осветляет губы, а не закрашивает; узлов сетки нет, свечение только у контуров и точек, пунктир ореола порезан на подпути по узлам (иначе штрихи ползут на речи). Маска — ТОЛЬКО картинка превью: информации для WISLIP в ней нет (он читает пиксели рта и сам берёт точки MediaPipe), в `clip.mp4` она не попадает. Решения о точках и параметрах приняты по стенду: Vision 65 / 76 / rev4 против MediaPipe на 48 роликах владельца из WISLIP (данные вне репозитория; rev4 macOS 27 хуже rev3/76, p95 Vision ~10 мс на 1280×720). SwiftUI перерисовывается только на смене фазы (`LipCapture.phase`). Размещение — `LipMirrorPlacement.resolve`: нижние стили и «Скрытая» → сверху из выреза; «Нотч» → настройка `lipsMirrorNotchVariant` (продолжение notch-плашки с перекрытием 2 pt без шва / «нижний вырез» у физической нижней кромки поверх Dock). Окно клик-сквозное, `sharingType = .none`, показывается только пока идёт запись И снимает камера (`RecorderPanelController.syncMirror`, в том числе из ветки `.hidden`).
- **Тренировка** (`Lips/LipTraining{Controller,Session,Phrases,Queue,Check}.swift`, `UI/LipTraining/LipTrainingView.swift`, окно — `WindowManager.showTraining`) — беззвучные фразы на экране: человек проговаривает фразу одними губами, и пара получает ТОЧНЫЙ текст (звук беззвучную пару не разметит). Дубль идёт тем же путём, что у диктовки (`LipCapture.beginTake(for: .training)` → `LipDataStore.commit`), но мимо `DictationController`: гейт тишины отбраковал бы беззвучную фразу. В заказе — `source: training`, `mode: silent`, `historyID` нет (`LipJob`/`LipCaption`; у диктовки эти ключи не пишутся, старый `job.json` читается диктовкой); meta остаётся схемой v1, `model` пары — источник фразы (`history`/`work`/`everyday`), `provider` — `training`. `speechOnset` пары — момент подсказки «Говорите губами» на шкале WAV; подсказка загорается через `cueDelay` 0,3 с после первого кадра с губами — иначе прогрев экспозиции превращал почти каждую фразу в «Начало без видео». Прошлая пара фиксируется только при старте следующей фразы, закрытии окна или выходе (`prepareForTermination` — ДО `LipDataStore.prepareForTermination`, тот ждёт очередь): до этого «Переписать прошлую» (R/К) — просто выброс. Исход обработки приходит из `LipDataStore.outcomes`: отброшенная фраза возвращается в очередь через три позиции. Весь этот учёт — очередь, отложенная фраза, фразы в обработке (переживают закрытие окна), «прошлая», счётчик «за сеанс» — чистый `LipTrainingSession`, а контроллер держит только камеру, микрофон, таймеры и стор; фраза встаёт в обработку ДО `commit` (`releaseHeld`), чтобы исход сбоя фиксации её нашёл. Кнопка доступа к камере — общая `CameraAccessButton` (`LipsSectionView.swift`) у раздела и окна. Диктовка важнее: её старт зовёт `interruptForDictation()`; тренировка во время диктовки не начинается. Фразы — история диктовок (предложения 3–12 слов, только кириллица: цифры и латиницу губами не прочесть) и готовый список `Resources/TrainingPhrases.ru.txt` (разделы `[work]` в стиле диктовок владельца и `[everyday]`, 421 фраза, только русский — модель губ WISLIP русская); пулы чередуются по кругу, записанное (`LipDataFiles.trainingTexts`, сравнение без регистра, «ё» и пунктуации) не предлагается. Фраз из наборов WISLIP (baseline, set2 — там контрольные) в списке НЕТ: при пополнении списка сверять с `~/VibeCode/WISLIP/wislip/phrases_*.txt` скриптом (равенство и почти-совпадения). Проверка до фиксации (`LipTrainingCheck`): < 1 с — «слишком коротко», > 0,7 с речи по ОБЫЧНОМУ порогу — «прозвучал голос». Замер 6.10.2026 на 240 клипах WISLIP (окна 21 мс, как у записи): вслух — от 1,02 с, беззвучно — до 0,51 с (один выброс — фраза вслух по ошибке), «Pop» добавляет до 0,13 с. Шёпот уровнем от беззвучного НЕ отличить: по тихому порогу −48 они перекрываются целиком (фон и усиление микрофона в сессиях разные) — от шёпота бережёт только подсказка «без голоса и без шёпота». Вью зеркала в окне живёт только во время фразы: ящик кадров отдаёт их последнему подписчику, и вечная подписка спорила бы с зеркалом панели записи. Автостоп — 13 с (лимит фразы WISLIP).

**Словарь** (`UI/Main/DictionarySectionView.swift`, секция `dictionary`) — список правил `ReplacementRule` (`from` → `to`, флаги `enabled` и `matchInsideWords`) поверх `SettingsStore`. Применение — `ReplacementEngine.apply` (`Text/ReplacementEngine.swift`, чистый): регистронезависимо, длинные шаблоны первыми (иначе короткие разорвут длинные), строка пересобирается без переиспользования индексов — вставленный текст повторно не сканируется, поэтому нет ни крашей на устаревших индексах, ни зацикливания при `to ⊇ from`. **Совпадение — по целому слову** (прежняя подстрока превращала «документ» в «DOKAмент» на примере из самого UI): символ слова — `isLetter || isNumber` любой письменности, граница проверяется только с той стороны, где шаблон начинается/кончается символом слова (у «э-э, » или «:)» на пунктуационном краю ограничения нет); при неудачной границе поиск продолжается с `index(after: lowerBound)`, а не с конца совпадения — иначе пропустится перекрывающееся («дада да»). С границами правила идемпотентны («ai» → «OpenAI» не пожирает свой результат) — это важно для словаря на выходном слое файлов, который применяется на каждом рендере. `matchInsideWords` (кнопка «Внутри слов» в строке правила) возвращает поиск подстроки для правил-нормализаторов вроде «ё» → «е». Ловушка Codable: у `ReplacementRule` РУЧНОЙ `init(from:)` с `decodeIfPresent` — синтезированный декодер не подставляет дефолт для отсутствующего ключа, и старый словарь без `matchInsideWords` уронил бы `try?` в `SettingsStore.init`, молча обнулив все правила; декодер живёт в расширении, чтобы сохранился memberwise-init.

Уровень микрофона для ВСЕХ панелей (`AudioRecorder`) считается НЕ по dB: логарифмическая шкала сжимает обычную речь в узкий диапазон и панели выглядят вялыми. Уровень строится по линейным RMS и пику с узкими рабочими окнами плюс гамма 0.72, сглаживание асимметричное (быстрый подъём, медленный спад), буфер тапа 1024 кадра (~21 мс) — реакция за доли секунды. ЛОВУШКА: `speechTime` для дашборда считается по СТАРОЙ dB-кривой (`speechLevel`) — её порог `speechLevelThreshold` калиброван именно под неё, и если увести статистику на новую кривую, поедут «Скорость речи», сэкономленное время и множитель. Расчёт «RMS буфера → речь / шёпот» один — `SpeechMeter.classify`: его зовут и запись, и `SpeechMeter.measure` в тестах. Панели поверх этого применяют общую огибающую `Float.envelope(toward:attack:release:)` (`Util/Smoothing.swift`) — симметричная EMA либо съедает пики голоса, либо дёргается на паузах. Амплитуда в `WaveformBars` идёт через `drive` и колебание с ненулевым полом: при `wave` от нуля половина хода теряется и полоски дрожат у пола.

**Звук** (`UI/Main/SoundSectionView.swift`, секция `sound`, в сайдбаре — в группе «Настройки»): буст громкости микрофона на время записи — `Audio/MicrophoneVolumeBooster.swift` (CoreAudio HAL, только системное устройство по умолчанию, best-effort — устройства без записываемого volume молча пропускаются; `beginBoost` после старта записи, `endBoost` — в `DictationController.transition` при уходе из `.recording`, одна точка покрывает стоп/отмену/ошибку/смену устройства); удаление тишины — `Audio/SilenceRemover.swift` (чистая пост-обработка WAV: окна 20 мс, порог −40 дБ, паддинг 0.24 с, guards «результат < 0.4 с или выигрыш < 10% → оригинал»; режется ТОЛЬКО копия для API — история, статистика и m4a работают с оригиналом); громкость сигналов — `SettingsStore.soundVolume`, `SoundPlayer` обязан держать ссылку на играющий `NSSound` (иначе ARC освободит до конца проигрывания).

**Расширенные настройки** (`UI/Main/AdvancedSettingsView.swift`) — под-страница «Общих»: drill-in через `@State showAdvanced` с МГНОВЕННОЙ сменой экрана (без слайдов; NavigationStack в проекте не используется). Внутри: «Показывать иконку в Dock» (`showDockIcon` — `NSApp.setActivationPolicy` на лету в didSet + `WindowManager.refocusMain()`, старт читает настройку в `main.swift`), «Открывать окно при запуске» (`openWindowAtLaunch`, по умолчанию вкл), карточка «Эксперименты» (тумблер `lipsExperiment` — показывает раздел «Губы», см. ниже), «Папка данных» — `Storage/AppDataFolder.swift`: ЕДИНСТВЕННЫЙ источник пути данных для всех сторов (кастомный путь в UserDefaults `dataFolderPath` читается напрямую, без SettingsStore); перенос — copy→switch→delete с откатом, применение ТОЛЬКО через перезапуск (`Util/AppRelaunch.swift`, общий с restart-алертом смены языка). Ловушка путей: `standardizedFileURL`/`resolvingSymlinksInPath` НЕ срезают `/private` у несуществующих путей — сравнение существующего источника с несуществующей целью слепнет, поэтому в `AppDataFolder.canonicalPath` резолвится самый глубокий существующий предок. Карточка «Библиотека транскрибаций» — срок хранения (`transcriptRetention`, сокращение подтверждается алертом), «Сохранять аудио файлов», «Уведомлять о готовности», занятое место, «Показать в Finder» и «Стереть всё аудио транскрибаций»; отдельного переноса у библиотеки нет — она живёт в «Папке данных». Cmd+W/Cmd+M работают только благодаря пунктам меню «Окно» в `AppDelegate.installEditMenu` (без пунктов меню такие клавиши в macOS не работают вовсе); `WindowManager.showMain` делает `deminiaturize` — иначе свёрнутое окно не вернуть из меню-бара.

**Клавиши** (`UI/Main/HotkeysSectionView.swift`): кроме toggle/paste — push-to-talk (`onKeyDown`/`onKeyUp`, методы `pushToTalkDown/Up` контроллера), глобальные `openMainWindow`/`openHistoryWindow` — намеренно БЕЗ дефолтов (глобальный Cmd+, отобрал бы «Настройки» у всех приложений системы); пункты меню-бара отражают их автоматически через `NSMenuItem.setShortcut(for:)`. Кнопка мыши: `SettingsStore.mouseShortcutButton` (−1 — выкл), NSEvent-мониторы `.otherMouseDown` в `HotkeyManager` (только кнопки ≥ 2 — левую/правую не трогать), на время захвата в рекордере глобальный обработчик глушится флагом `MouseShortcutCapture.isCapturing`. Рекордер мыши — нативный `NSSearchField`, как внутри KeyboardShortcuts (только так совпадает вид). Ловушка macOS 27: у поля поиска без лупы (`searchButtonCell = nil` — так делают оба рекордера) область текста начинается с −4 pt при полной ширине, и центрированный текст уезжает влево; лечит `CenteredSearchFieldCell` (`UI/DesignSystem/`), которую `AppDelegate` ставит всем `NSSearchField` через `cellClass` до создания первого поля — правка срабатывает только у полей без лупы и центрирует текст по ВСЕМУ полю (правый отступ крестика зеркалится слева). Так же с 3.1 центрирует сам `KeyboardShortcuts.RecorderCocoa` на macOS 27 (его `layout()` двигает подвью, только если справа отступ больше, чем слева, — после нашей ячейки правки не складываются); прежняя центровка «между левой кромкой и крестиком» развела бы рекордер мыши с рекордерами клавиш. KeyboardShortcuts 3.x: параметр дефолта у `Name` называется `initial:` (не `default:`); ловушка: `isEditable = false` делает подложку поля бледнее — поле остаётся editable, ввод блокируется `acceptsFirstResponder=false` + `refusesFirstResponder`.

**Дизайн-система** (`UI/DesignSystem/`): токены `DS` (`DesignTokens.swift` — акцент, радиусы, отступы, анимации, палитра mesh-фона, плюс палитры `Aurora` индиго/космос, `ScreenGlow` свечения краёв и `coral`) — единственный источник правды, новый UI не хардкодит цвета/числа. Всё «стекло» — через модификатор `glassSurface()` (`GlassSurface.swift`): macOS 26 — Liquid Glass, 15 — материал со светящейся кромкой, Reduce Transparency — непрозрачный фон; `forceMaterial` — страховка для контекстов, где glassEffect ведёт себя плохо (borderless NSPanel). Там же `MeshBackground`, `ButtonStyles`, `SettingsForm` (выпадающий список по enum — `SettingsPopup(selection:title:)`, без ручной арифметики `allCases.firstIndex(of:)`) и `DokaLogoView` (`DokaPetalsShape` — фирменный логотип-крест, контур перенесён 1:1 из векторного исходника `DOKA_LOGO/Vector_DOKA.svg`). Анимации — токены `DS.Anim` (`section`/`hover`/`control` + длительности `panelShow`/`panelHide`); per-style spring рекордеров намеренно остаются литералами. Общие переиспользуемые элементы вне DesignSystem: `CopyButton`, `KeyCapBadge` (бэйдж клавиши сочетания на онбординге; подпись «esc» в панелях записи — обычный `Text(L("recorder.escHint"))`, отдельного компонента у неё нет), `CollapsibleReveal` (сворачивание длинного контента с затуханием, `UI/Components.swift`), `LocalAssetStatusView(asset:name:)` (весь ряд состояний скачиваемого локального ресурса — кнопка, прогресс с отменой, «Подготовка модели…», удаление с подтверждением; `name` подменяет слово-статус именем ресурса и по умолчанию `nil`, поэтому «Сервис» и строка диаризатора остаются со словами статуса) и `HelpBubble` («вопросик» с поповером, `SettingsForm.swift`); контролы расшифровки — `OptionTile`/`SaveAsMenu`/`SaveFormat`/`TextFileSaver`/`SpeakerPalette` (`UI/Main/TranscriptionControls.swift`, общие у страницы «Транскрибация» и записи библиотеки); системный диалог «Сохранить» — только `SavePanel.chooseURL` (там же: история, библиотека, расшифровки, анализ и его PDF, шаблоны) — своих `NSSavePanel` не заводить; EMA-сглаживание уровня микрофона — единый хелпер `Float.smoothed(toward:response:)` (`Util/Smoothing.swift`) для всех панелей; формат таймера/плеера mm:ss — `clockMMSS` (`Util/TimeFormat.swift`; не путать с `formatStatDuration` для дашборда и `TranscriptFormatter.clock` для тайм-кодов расшифровок).

**Онбординг** — это секция `home` («DOKA») главного окна. Показывается при старте, пока не выданы оба разрешения и не готов сервис (`SettingsStore.isServiceReady`). Третий шаг — выбор сервиса распознавания сеткой из трёх плиток (`ServiceChoice` / `ServiceChoiceTile`, файловый уровень `HomeSectionView.swift`): облачный (поле ключа, прежний блок) и две локальные модели, у которых прямо в шаге стоит `LocalAssetStatusView(asset: .speech(model), name: model.plainTitle)` — скачивание проходится целиком внутри онбординга, без похода в раздел «Сервис». Имена моделей: `LocalModel.plainTitle` («Whisper Large v3 Turbo», без «(Local)») для строки статуса, `shortTitle` («Whisper») для узкой плитки; `title` выводится из `plainTitle` и остаётся прежней строкой — она пишется в историю через `providerTagForHistory`. Пресеты «своего сервиса» отдельной плитки не имеют: они подсвечивают облачный вариант, а клик по уже выбранной облачной плитке гейтится `guard settings.isLocalService` — иначе выбранный пресет молча сменился бы на встроенный сервис. Эмбиент-фон секции — `FloatingWordsView` (всплывающие слова-приветствия на разных языках; намеренно НЕ локализуются — многоязычность и есть смысл).

### Неочевидные инварианты

- Глобальный Esc (`cancelRecording`) включается только на время записи/распознавания через `HotkeyManager.setEscapeEnabled` — иначе DOKA перехватит Esc во всей системе.
- **Перенос «Папки данных» останавливает ВЕСЬ пайплайн, а не только библиотеку.** У
  `HistoryStore`, `StatsStore` и `AudioStore` своей заморозки нет: путь они фиксируют
  один раз в `init` и создаются ДО переноса, поэтому продолжали бы писать в старую
  папку. Закрыто флагом `AppDataFolder.needsRestart` (ставится после успешного
  переноса): `DictationController.startRecording` отказывает с
  `transcribe.error.restartRequired`. Нет записи — нет и записей в историю,
  статистику и аудио. Гейт самого переноса (`AdvancedSettingsView.migrate`) ждёт
  покоя от четверых: файловой транскрибации, диктовки (`DictationController.isActive`),
  ИИ-анализа (`AnalysisController.isRunning`) и фоновых задач библиотеки.
- **Взаимоисключение «анализ ↔ локальное распознавание» — по маршруту ИДУЩЕГО
  прогона** (`FileTranscriptionController.runningUsesLocalEngine`), а не по глобальному
  `providerID`: запуск из библиотеки идёт по снимку `params.providerID`, и глобальная
  настройка к нему отношения не имеет. Гейт двусторонний: анализ не стартует поверх
  локального распознавания, локальное распознавание — поверх анализа. Сетевому
  распознаванию анализ не мешает, и наоборот.
- **Ленивая загрузка локальных движков: три инварианта на каждый слот.** (1) параллельные
  вызовы ждут ОДНУ задачу; (2) `defer` снимает регистрацию только СВОЕЙ задачи
  (`if loading?.task == task`) — безусловный сброс затирал запись другого запроса;
  (3) после `await` обязателен `guard`, что слот всё ещё ждёт именно эту задачу, иначе
  движок выгружается и бросается `CancellationError`. Третий пункт — не перестраховка:
  у `load()` WhisperKit, FluidAudio и llama.cpp кооперативных точек отмены НЕТ, задача
  доходит до конца, и без guard'а в памяти оставался бы движок удалённой модели.
  `unloadNow`/`unloadDiarizer`/`unloadLLM` обязаны отменять незавершённую загрузку, а
  `unloadIfCurrent` — смотреть и на `engine`, и на `loading` (во время загрузки `engine`
  ещё nil, и удаление модели в этот момент было полным no-op).
- **Ключ сервиса сохраняется по адресату, снятому ДО сетевой проверки**
  (`ServiceSectionView.KeyDestination`). Проверка идёт секунды, за это время можно
  переключить сервис — и ключ уезжал в аккаунт того сервиса, который оказался выбран
  к моменту ответа, вплоть до затирания ключа встроенного (платного) сервиса.
- **`keyUp` синтетической вставки уходит всегда.** Пауза между `keyDown` и `keyUp` —
  `try?`, а не `try await`: отмена между событиями оставляла клавишу V «зажатой» на
  уровне HID для ВСЕЙ системы. Отменённая вставка допустима, залипшая клавиша — нет.
- `Paster` перед синтетическим Cmd+V ждёт отпускания физических модификаторов хоткея (до 0.5 с) и проверяет secure input (поля паролей) — там вставка невозможна, текст остаётся в буфере. Восстановление прежнего буфера гейтится настройкой `SettingsStore.restoreClipboard` («Основные», по умолчанию ВКЛ), происходит через ~0.9 с и только если буфер никто не менял (`changeCount`); снапшот/восстановление всех типов данных буфера — `Paste/ClipboardManager.swift`.
- **Шиты главного окна встают по вертикальному центру** — делегат окна `MainWindowDelegate` (`UI/WindowControllers.swift`, `window(_:willPositionSheet:using:)`): система вешает шит сразу под тулбаром. Шит, которому по центру места не хватает, остаётся на системном месте. Высоту шита держать заметно ниже окна (640), иначе он упрётся в нижнюю кромку.
- **Данные для шита — через `.sheet(item:)`, не `@State`-массив + `.sheet(isPresented:)`**: значение, изменённое в том же такте, что и флаг, замыкание шита читает СТАРЫМ — «Анализ производительности» так открывался с нулями.
- `AppDelegate.installEditMenu()` создаёт невидимое меню «Правка»: без него Cmd+C/V/X/A не работают в текстовых полях меню-бар-приложения.
- `LegacyMigration` — одноразовый перенос из старого приложения Whisper (`com.pitenin.whisper`): UserDefaults (включая хоткеи), ключ Keychain, история. Копирует, а не переносит.
- Анимации уважают Reduce Motion: в SwiftUI — через `accessibilityReduceMotion`, а `NSAnimationContext` сам его НЕ уважает — длительность вручную умножается на 0 (`PanelFade.durationScale`). Показ и затухание плавающих окон (плашка записи, подсветка «Авроры», зеркало губ) — только через `UI/PanelFade.swift`, по экземпляру на окно: у затухания счётчик поколений, и любой показ отменяет запоздалый `orderOut` (у подсветки «Авроры» его когда-то не было, и запись, начатая во время затухания прошлой, шла без подсветки).
- Кромка-подсветка главного окна (`EdgeRim` в `MeshBackground.swift`) берёт форму угла у системы — `ConcentricRectangle` (macOS 26+; у macOS 15 — 10 pt). Радиус не зашивать числом: прежние 24 pt были подогнаны под macOS 26, в macOS 27 радиус окна сменился, и внутри угла вылезло второе скругление.
- Главная и вторичная кнопки (`dsProminentButton()` / `dsGlassButton()`) — ОДИН свой стиль `DSCapsuleButtonStyle` с общей метрикой (иначе в ряду «Отмена» · «Сохранить» кнопки разной высоты); главная — сплошная капсула `DS.accent`, НЕ `.glassProminent` + `.tint`: стекло подмешивало фон к оттенку, и коралл мутнел до горчичного, а на macOS 27 терялась капсула.
- Высокие Liquid Glass-карточки отражают у кромок соседей: у карточки «Панель записи» («Общие») линза тянула в себя пилюлю сайдбара, тумблер и текст карточки выше. Такие карточки — `SettingsCard(forceMaterial: true)` (материал с кромкой, отражений нет в принципе).
- У вью плавающих панелей НЕ должно быть внешних теней/свечений (`.shadow` на корне): окно панели размером ровно с плашку и обрезает их своей квадратной границей — тёмные углы в светлой теме (уже ловили на «Студии» и «Авроре»).
- Пояснения к настройкам — через `SettingsRow(help:)` («вопросик» с поповером), а не `subtitle`: подписи под тогглами захламляют форму (конвенция пользователя). Тот же «вопросик» вне форм — переиспользуемый `HelpBubble` (`SettingsForm.swift`; `SettingsRow` рендерит подсказку им же).
- Синхронное чтение Keychain в пути запуска (`applicationDidFinishLaunching`) ЗАМОРАЖИВАЕТ всё приложение, если macOS показывает диалог подтверждения доступа к ключу (случается после пересборки бинарника): `SecItemCopyMatching` блокирует главный поток до ответа пользователя. Поэтому `resumePendingJobs` читает ключ лениво через `Task.detached`. Такое же синхронное чтение осталось в `AppDelegate` (`SettingsStore.currentAPIKey` при старте) — известное место: при висящем диалоге запуск блокируется там. По той же причине `isServiceReady` НЕЛЬЗЯ звать из тела SwiftUI-вью для сетевого сервиса (у него внутри `currentAPIKey`): онбординг мемоизирует результат в `@State keyStatus` и обновляет его по событию (`syncServiceState()` из `onAppear` и `onChange(of: providerID)`), а из тела спрашивает `isServiceReady` только для локального сервиса — там Keychain не участвует. Тело `HomeSectionView` перерисовывается на каждый процент скачивания модели, и прямой вызов дал бы сотню `SecItemCopyMatching` за загрузку.
- Чистую логику удобно верифицировать вне приложения: scratchpad-harness компилирует РЕАЛЬНЫЕ исходники (`swiftc main.swift <файлы из Sources>` + шим `L()`), так проверялись `SilenceRemover`, `TranscriptSegmentSplitter`, `MicrophoneVolumeBooster`, `AppDataFolder`, `decodeAsyncStatus`/`StoredTranscript` (фикстуры живых async-ответов) и живые ответы Nexara. Для UI есть стенд с рендером окна в PNG (`NSView.cacheDisplay`) — годится для геометрии и масок, но НЕ для стекла: glassEffect и материалы композитит оконный сервер, в офскрине они не рендерятся (серую плиту Liquid Glass так не увидеть), а `screencapture` из агентской сессии недоступен (нет TCC-права записи экрана) — живой вид проверяет только пользователь.
