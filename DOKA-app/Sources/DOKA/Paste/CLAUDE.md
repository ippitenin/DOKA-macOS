# Вставка текста

Синтетический Cmd+V, буфер обмена и пробел между диктовками. Общие правила проекта, команды, гейты и сквозные инварианты — в корневом `CLAUDE.md`, там же карта всех документов; пути вида `Storage/CLAUDE.md` — от `DOKA-app/Sources/DOKA`.

- **`keyUp` синтетической вставки уходит всегда.** Пауза между `keyDown` и `keyUp` —
  `try?`, а не `try await`: отмена между событиями оставляла клавишу V «зажатой» на
  уровне HID для ВСЕЙ системы. Отменённая вставка допустима, залипшая клавиша — нет.
- `Paster` перед синтетическим Cmd+V ждёт отпускания физических модификаторов хоткея (до 0.5 с) и проверяет secure input (поля паролей) — там вставка невозможна, текст остаётся в буфере. Восстановление прежнего буфера гейтится настройкой `SettingsStore.restoreClipboard` («Основные», по умолчанию ВКЛ), происходит через ~0.9 с и только если буфер никто не менял (`changeCount`); снапшот/восстановление всех типов данных буфера — `Paste/ClipboardManager.swift`. Пробел между диктовками подряд (`SettingsStore.smartSpacing`, «Основные», по умолчанию ВКЛ): правила — чистая `Paste/PasteSpacing.swift` (окно 3 мин, то же приложение по PID, белый список начал), состояние «прошлая вставка» — у `Paster`; любая клавиша или клик после вставки её сбрасывают (глобальный монитор, ставится при первой вставке), а свой Cmd+V помечен `eventSourceUserData` и хоткеи DOKA (список `KeyboardShortcuts.Name.dokaShortcuts` рядом с их объявлением в `Managers/HotkeyManager.swift`) сравниваются с `KeyboardShortcuts.getShortcut` — иначе монитор сбрасывал бы прошлую вставку нашим же нажатием и пробел не ставился бы никогда. В буфер на случай отказа вставки кладётся текст без пробела, в историю — тоже.
