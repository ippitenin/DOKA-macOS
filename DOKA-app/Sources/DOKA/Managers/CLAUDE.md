# Клавиши и уведомления

Глобальные хоткеи и кнопка мыши (`HotkeyManager`, раздел «Клавиши»), уведомления о готовности транскрибации. Общие правила проекта, команды, гейты и сквозные инварианты — в корневом `CLAUDE.md`, там же карта всех документов; пути вида `Storage/CLAUDE.md` — от `DOKA-app/Sources/DOKA`.

**Клавиши** (`UI/Main/HotkeysSectionView.swift`): кроме toggle/paste — push-to-talk (`onKeyDown`/`onKeyUp`, методы `pushToTalkDown/Up` контроллера), глобальные `openMainWindow`/`openHistoryWindow` — намеренно БЕЗ дефолтов (глобальный Cmd+, отобрал бы «Настройки» у всех приложений системы); пункты меню-бара отражают их автоматически через `NSMenuItem.setShortcut(for:)`. Диктовка клавишей Fn (🌐) была (PR #36) и убрана по решению владельца 6.10.2026: 🌐 спорит с системными действиями (раскладка, эмодзи, диктовка macOS), а на части внешних клавиатур Fn до системы не доходит — не возвращать без просьбы. Кнопка мыши: `SettingsStore.mouseShortcutButton` (−1 — выкл), NSEvent-мониторы `.otherMouseDown` в `HotkeyManager` (только кнопки ≥ 2 — левую/правую не трогать), на время захвата в рекордере глобальный обработчик глушится флагом `MouseShortcutCapture.isCapturing`. Рекордер мыши — нативный `NSSearchField`, как внутри KeyboardShortcuts (только так совпадает вид). Ловушка macOS 27: у поля поиска без лупы (`searchButtonCell = nil` — так делают оба рекордера) область текста начинается с −4 pt при полной ширине, и центрированный текст уезжает влево; лечит `CenteredSearchFieldCell` (`UI/DesignSystem/`), которую `AppDelegate` ставит всем `NSSearchField` через `cellClass` до создания первого поля — правка срабатывает только у полей без лупы и центрирует текст по ВСЕМУ полю (правый отступ крестика зеркалится слева). Так же с 3.1 центрирует сам `KeyboardShortcuts.RecorderCocoa` на macOS 27 (его `layout()` двигает подвью, только если справа отступ больше, чем слева, — после нашей ячейки правки не складываются); прежняя центровка «между левой кромкой и крестиком» развела бы рекордер мыши с рекордерами клавиш. KeyboardShortcuts 3.x: параметр дефолта у `Name` называется `initial:` (не `default:`); ловушка: `isEditable = false` делает подложку поля бледнее — поле остаётся editable, ввод блокируется `acceptsFirstResponder=false` + `refusesFirstResponder`.

**Уведомления о файлах** (`Managers/FileTranscriptionNotifier.swift`) — «Транскрибация готова» / «не удалась» по `TranscriptHistoryStore.finished` (эмитят `markDone` и `markError(notify: true)`: путь контроллера, добор, повторный опрос; безнадёжные на старте — `notify: false`, отмена — не событие). `install()` — в `applicationWillFinishLaunching`: делегат обязан стоять до завершения запуска (клик при незапущенном приложении), а события `resumePendingJobs` должны застать подписку. `UNUserNotificationCenter` — только за `isSupported` (собранный `.app`; у голого бинаря и xctest `current()` бросает исключение); методы делегата `nonisolated` и в completion-варианте (у async-перевода системный completion зовётся вне главного потока), через границу акторов идёт только UUID. Подавление — запись действительно на экране: `WindowManager.isShowing` (приложение активно, key — главное окно или его шит, окно видимо, не свёрнуто, не заслонено) плюс на «Транскрибации» — это задача/результат страницы, в библиотеке — открыт список или сама запись. Разрешение спрашивается лениво — в `start()` и при включении тумблера `SettingsStore.notifyFileTranscription` (карточка «Библиотека транскрибаций» в «Расширенных»; при запрете — «Открыть настройки»), на старте никогда. Идентификатор уведомления — id записи (повтор заменяет прежнее); удалённые записи убираются из Центра уведомлений подпиской на `store.$records`; клик — `LibraryNavigator.open` (запись удалена — список).

`PermissionsManager` — синглтоны в корне; `MenuBarManager` — пункт «Повторить неудачную диктовку», `Audio/CLAUDE.md`.
