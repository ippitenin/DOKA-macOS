# Доступ для ИИ-агентов

Локальный MCP-сервер внутри DOKA: Claude Code, Cursor и другие агенты на этом Mac распознают файлы, читают библиотеку, запускают анализ, читают историю диктовки и словарь. Страница настроек — `UI/Main/AgentAccessView.swift` (под-страница «Общих», `GeneralSubpage.agents`). Общие правила проекта, команды, гейты и сквозные инварианты — в корневом `CLAUDE.md`, там же карта всех документов; пути вида `Storage/CLAUDE.md` — от `DOKA-app/Sources/DOKA`.

**Решения владельца (8.11.2026).** Агент умеет всё, что есть в приложении, но всё личное закрыто отдельными тумблерами (`AgentPermission`), по умолчанию открыто только «Распознавать файлы». Выключено — инструмент отвечает ошибкой с путём, где включить (`AgentPermission.denialMessage`, на языке интерфейса: агент пересказывает её человеку), а в `tools/list` видны все инструменты. Не входит: смена настроек, запуск диктовки (микрофон без человека), ключи сервисов — агент их не видит никогда.

**Обычный API для программ (8.11.2026, тот же сервер).** OpenAI-совместимый `POST /v1/audio/transcriptions` (multipart: `file`, `model` — любое, `language`, `response_format` json/text/verbose_json/srt/vtt, `timestamp_granularities[]`) и `GET /v1/models` — как локальный сервер TypeWhisper: любая программа отправляет звук и получает текст. Ключ — тот же токен, адрес `http://127.0.0.1:<порт>/v1`. Своё разрешение `openAIAPI`, по умолчанию ВЫКЛ. Решение владельца: НИЧЕГО не сохраняется (ни библиотека, ни история, ни статистика, ни архив звука). Модуль — `OpenAITranscriptionAPI` (прогон и временные файлы), `OpenAIResponses.swift` (`OpenAIPreflight` — решение до тела, `OpenAIError` — ошибки в формате OpenAI, сборка ответов), `MultipartFormData` (чистый разбор).

## Устройство

- **`AgentServerController`** (`@MainActor`, синглтон, `activate()` из `AppDelegate`) — жизненный цикл: сервер поднят, только пока включён `AgentAccessSettings.isEnabled` и прочитан токен; смена порта — перезапуск. Сообщения старого сервера (после смены порта или выключения) отбрасываются по порту. `respond(to:)` — маршрутизация: охрана → только `/mcp` → `POST` в `MCPHandler`, `GET` → 405 (SSE-потока у нас нет, спецификация это разрешает), уведомление → 202 без тела. Там же журнал обращений `AgentActivityLog` (50 последних вызовов, только в памяти; `totalCount` — все с запуска или «Очистить»). На странице — первые 20 (`collapsedCount`) обычным `VStack`, «Показать ещё N» раскрывает остальные хранимые; подпись (`AgentActivityLog.footer`) честно говорит «хранятся последние 50» или «показаны последние 50 из N — старые вытесняются» (решение владельца 9.11.2026: «Показать все» при вытеснении было бы неправдой). Хранить больше (на диске) не стали: журнал — «что агент сделал только что», не аудит.
- **Токен** — 32 байта base64url, Keychain, аккаунт `agent-access-token` (сервис общий `com.pitenin.doka`). Читается и создаётся ТОЛЬКО при включённом главном тумблере (пока функцией не пользуются, секрета нет) и ТОЛЬКО `Task.detached`: синхронное чтение Keychain в пути запуска замораживает приложение (корневой `CLAUDE.md`). «Сменить токен» отключает подключённых агентов сразу. На странице токен ЗАМАСКИРОВАН (`AgentServerController.masked`, видны последние 4 символа; текст нельзя выделить) — демонстрация и запись экрана его не покажут; целиком он уходит только кнопкой «Скопировать» через `ClipboardManager.setSecret`: `currentHostOnly` (без Universal Clipboard на iPhone) и маркеры `org.nspasteboard.ConcealedType`/`TransientType` (менеджеры буфера не кладут в историю).
- **`LocalAPIServer`** — `NWListener` с `requiredLocalEndpoint` = 127.0.0.1: из сети порт не виден. `allowLocalEndpointReuse = false` НАМЕРЕННО: с совместным использованием адреса другая программа могла бы встать на тот же порт и перехватывать запросы вместе с токеном. Цена — TIME_WAIT, поэтому соединение после ответа (`Connection: close`) закрывает КЛИЕНТ (ждём его EOF до 5 с), а занятый порт при старте повторяется один раз через 2 с. Один запрос на соединение, не больше 16 соединений сразу (сверх — 503), таймаут соединения 120 с — с запасом над самым долгим ожиданием инструмента. Порт по умолчанию 47800 (`AgentAccessSettings.defaultPort`); занят — статус «Не запустился: порт занят».
- **`HTTPRequestParser`** (`HTTPMessage.swift`) — чистый разбор HTTP/1.1: `parseHead` отдаёт заголовки ДО тела; только `Content-Length` из цифр (chunked → 501, «+5» → 400), заголовки ≤ 16 КБ; повтор `Content-Length`/`Host`/`Authorization`/`Origin`/`Content-Type` — 400 (подделка). Тело в памяти — ≤ 1 МБ (MCP передаёт пути, а не файлы).
- **Порядок на соединении** (`LocalAPIServer`): заголовки → `AgentServerController.preflight` (главный поток: охрана, маршрут, лимит, у API — `OpenAIPreflight`) → тело в память или ПОТОКОМ в файл → `respond`. Пока `preflight` не разрешил, тело не читается: без токена не залить ни байта. Простой: заголовки 30 с, тело 60 с; пока решаем и отвечаем — не меряется. `Decision.accept(…, onAbort:)` — если тело не дошло до обработчика (обрыв, простой, остановка), сервер зовёт `onAbort`: API снимает занятость и стирает временную папку.
- **`LocalAPIGuard`** — три барьера, чистая функция: `Host` только loopback (защита от DNS rebinding), `Origin` если есть — только loopback (браузер ставит его всегда, консольные клиенты — нет; страница с localhost, например MCP Inspector, проходит), `Authorization: Bearer` со сравнением без раннего выхода.
- **`MCPHandler`** — JSON-RPC 2.0, транспорт Streamable HTTP с ответом `application/json` без SSE: `initialize` (версия клиента, если поддерживаем, иначе новейшая из `supportedVersions`), `ping`, `tools/list`, `tools/call`; пакеты (массивы) отклоняются. Свой слой, а не SDK: методов пять. Описания инструментов и инструкция сервера — `AgentToolSpecs.swift`, на английском: это протокол для модели, не интерфейс.
- **`AgentTools`** — инструменты поверх существующего кода, нового пайплайна нет. Разрешение инструмента (`requiredPermission`) проверяется ДО обращения к сторам; доступ к записи библиотеки — `AgentAccessPolicy`: свои записи агента (`FileTranscriptRecord.createdByAgent`) читаются и меняются с одним «Распознавать файлы», чужие — с «Читать библиотеку» / «Изменять библиотеку». Без чтения библиотеки `list_transcripts` показывает только свои записи с пометкой.

## Страница: подключение универсальное

Решение владельца 8.11.2026: «это же должно быть универсально для пользователей» — страница не подстраивается под один продукт. Карточка «Подключение агента»: «Адрес» и «Токен» (их хватает любому агенту с MCP по HTTP), ниже список «Готовая настройка для» (`AgentClient`, `Agent/AgentClientSetup.swift`; выбор — `@AppStorage("agentAccessClient")`): Claude Code (команда), Cursor (`~/.cursor/mcp.json`, `url` + `headers`), VS Code (`.vscode/mcp.json`, `servers` + `type: http`), Gemini CLI (`~/.gemini/settings.json`, `httpUrl` + `headers`), Codex (`~/.codex/config.toml`, `http_headers`), «Другие» — мост `mcp-remote` для программ, которые умеют только запускать команду (Claude Desktop; для 127.0.0.1 флагов не нужно). Форматы сверены с официальной документацией 8.11.2026; Codex (у него пример именно с `Authorization` в документации не показан) проверен живьём 8.11.2026 на codex-cli 0.166.0: `http_headers` с `Authorization` подключается, `doka_status` вызывается. В интерактивном Codex вызов инструмента он подтверждает сам; в `codex exec` без человека нужен `mcp_servers.doka.default_tools_approval_mode = "approve"` — в фрагмент НЕ добавляем: подтверждение — защита человека. JSON собирается `JSONSerialization`, не склейкой строк. Вид страницы (9.11.2026): поле порта — системное `.roundedBorder`, как однострочные поля «Сервиса» (плоскую плашку `dsFieldBox` владелец забраковал: «должно быть нативно и консистентно»); клик в пустое место страницы снимает с него фокус и применяет порт (`onTapGesture` на содержимом, приём `DictionarySectionView`; без него macOS фокус не забирает). Список клиентов — постоянные 250 pt под самый длинный пункт. Значения «Адрес»/«Токен»/фрагмент — в плашке во всю ширину строки. Отдельная карточка «API для программ (формат OpenAI)» — тумблер `openAIAPI` (в списке разрешений агента его нет: `AgentPermission.agentCases`), адрес `/v1`, ключ, пример `curl`.

## Инварианты

- **`transcribe_file` не принимает файлы DOKA** — `AgentPathPolicy`: путь разрешается `realpath`, нужен обычный файл (FIFO с расширением `.wav` подвесил бы распознавание), и ни одна его родительская папка не совпадает по устройству+inode с папками данных (`AppDataFolder.defaultURL` — там же `Models` и `LipData`, `currentURL`, старая `Application Support/Whisper`), а файл во временной папке не начинается с `doka-` (WAV неудачных диктовок). Иначе агент с разрешением по умолчанию прочитал бы архив записи человека, аудио истории или клип губ (в нём весь звук диктовки) как «свою» расшифровку. Сравнение по inode, а не по строке: APFS не различает регистр, симлинки и `..` ведут туда же. Распознаётся уже разрешённый путь — подменить симлинк после проверки нельзя.
- **Числа из аргументов — только `Int(exactly:)` и в пределах ±1 000 000** (`Arguments.optionalInt`): `Int(Double)` вне диапазона Int — аварийная остановка, `{"limit": 1e300}` ронял DOKA одним запросом. Не возвращать прямое `Int(value)`.
- **Анализ записи человека требует и «Читать», и «Изменять библиотеку»**: анализ сохраняется в запись. Словарь — два разрешения: «Читать словарь» (`dictionary`) и «Изменять словарь» (`dictionaryWrite`): правило меняет текст, который человек диктует в другие приложения. Правило от агента — не длиннее 100 символов.

- **Распознавание — только через `FileTranscriptionController.start`** с `Target.agent(sourcePath:)`: все гейты действуют как у страницы (файл за раз → `.busy`, аренда слота модели, взаимоисключение с анализом и локальной диктовкой, заморозка после переноса «Папки данных»). `.agent` помечает запись `createdByAgent` и, как запуск из библиотеки (`keepsPagePhase`), не затирает файл, выбранный на странице. Сервис — активный `providerID`: агент его не выбирает. Параметры — без ролей и анализа (анализ — отдельный инструмент).
- **`createdByAgent` — опциональное поле `meta.json`**: у записей человека nil и не пишется; прежняя версия DOKA новый `meta.json` читает. Не делать его не-опциональным (ловушка из корневого `CLAUDE.md`).
- **Долгие операции не держат запрос минутами.** `transcribe_file` сразу возвращает id; `get_transcript` и `analyze_transcript` ждут не дольше `wait_seconds` ≤ 50 с (опрос раз в 0,5 с на главном потоке без блокировки), потом отвечают «ещё идёт» — агент спрашивает снова. Клиенты MCP рвут запрос примерно через минуту.
- **Повторный `analyze_transcript` по записи, у которой анализ уже идёт, только ждёт** — второй не запускает. Новый анализ отличается от прежних временем старта (`analysisStarts`). Причины отказа — `AnalysisController.Availability.message`, общий с подсказкой кнопки анализа.
- **Текст расшифровки — через `TranscriptOutput.prepare`**: те же правки пользователя и словарь (если включён), что у «Скопировать» и «Сохранить как…».
- Тумблеры и порт — `AgentAccessSettings` (свой объект, ключи UserDefaults `agentAccess*`; `rawValue` разрешений хранится — не переименовывать). Названия тумблеров — литеральные ключи `agent.permission.*`, поэтому `DYNAMIC_PREFIXES` скрипта локализации не пополнялся.

- **API: что проверяется до тела** (`OpenAIPreflight.decide`, по порядку): разрешение (403 с путём к тумблеру), занятость — один запрос за раз, остальным 429 ДО приёма тела (иначе параллельные загрузки по гигабайту забили бы диск), `multipart/form-data` с boundary (415), пустое тело (400), ≤ 1 ГБ (413), свободное место ≥ 2 × размер + 1 ГБ (507).
- **API: временные файлы** — `TMPDIR/doka-api-<uuid>` (0700, файлы 0600): тело потоком, файл вырезается кусками по 4 МБ из отображения тела (`.alwaysMapped`, гигабайт не копируется), тело стирается сразу; папка стирается при любом исходе (`release` в `defer` и в `onAbort`), забытые — на старте (`sweepLeftovers`). Префикс `doka-` закрыт для MCP `transcribe_file`.
- **API: распознавание** — активным сервисом (`model` игнорируется: программа не переключит DOKA на облако), без диаризации и анализа; формат — белый список страницы (`webm` нет → 400). Гейты локальной модели — ОБЩИЕ со страницей: `FileTranscriptionController.localStartRefusal(route:)` (модель, анализ, локальная диктовка, другой локальный файл); локальный прогон API держит аренду `fileSpeech`, а страница, библиотека и `AnalysisController.availability` видят его через `OpenAITranscriptionAPI.shared.isRunningLocal`. Выход — `TranscriptOutput.prepare` (правки и словарь, как у «Сохранить как…»), srt/vtt/verbose_json режутся `.medium`. В журнал — только «API: transcriptions (N s)» и итог, без текста. Декодирует чужой файл AVFoundation — риск ошибок самого декодера Apple остаётся, как у любого медиаприложения.

## Чего разрешения НЕ защищают (сказано на странице сноской и в README)

- **Агент с доступом к Терминалу или файлам** обходит любые разрешения приложения: читает файлы DOKA с диска и меняет её настройки через `defaults`. Тумблеры управляют только тем, что DOKA отдаёт по MCP; против такого агента работают его собственные запросы разрешений. Подписывать настройки HMAC отказались: данные и так лежат файлами.
- **Prompt injection**: агент, читающий чужие тексты, может получить чужую команду — личные разрешения включать на время задачи.
- Токен лежит открытым текстом в конфиге агента (`~/.claude.json`) и в истории Терминала — их видят программы на этом Mac.

Тесты: `HTTPRequestParserTests`, `LocalAPIGuardTests`, `MCPHandlerTests`, `AgentPermissionsTests`, `AgentPathPolicyTests`, `MultipartFormDataTests`, `OpenAIPreflightTests` (решения до тела, формат ошибок и ответов), `AgentClientSetupTests` (фрагменты настроек клиентов), `AgentActivityLogTests` (журнал: 50 хранимых, счёт всех, «Показать ещё N», подпись при вытеснении). Живая проверка (`SMOKE.md`, «Доступ для ИИ-агентов»): `curl` без токена → 401, с `Origin: https://example.com` → 403; команда или фрагмент со страницы для своего агента → «распознай файл …» → запись в «Библиотеке» с текстом у агента; выключенное разрешение → агент пересказывает путь к тумблеру; выключение главного тумблера сразу закрывает порт.
