# Сертификат «DOKA Dev» (одноразовая настройка)

> Если в связке ключей есть сертификат «Developer ID Application» (членство в
> Apple Developer Program), `build.sh` подписывает им, и «DOKA Dev» не нужен.
> Инструкция ниже — для сборки без программы.

Зачем: при ad-hoc подписи (`codesign -s -`) macOS считает каждую пересборку
«новым» приложением и сбрасывает разрешения микрофона и Accessibility.
Самоподписанный сертификат делает подпись стабильной — разрешения выдаются
один раз и переживают пересборки.

## Создание через Keychain Access

1. **Связка ключей → Ассистент сертификации → Создать сертификат…**
2. Имя: `DOKA Dev` (ровно так — build.sh ищет по имени),
   Тип идентификации: Самоподписанный корневой,
   Тип сертификата: **Подписывание кода**.
3. «Создать».

## Пометить доверенным для подписи кода

macOS требует, чтобы это сделал сам пользователь (появится запрос пароля):

```bash
security add-trusted-cert -r trustRoot -p codeSign \
  -k ~/Library/Keychains/login.keychain-db \
  <(security find-certificate -c "DOKA Dev" -p)
```

Либо через GUI: **Связка ключей → категория «Сертификаты» → DOKA Dev →
двойной клик → Доверие → «Подписывание кода»: Всегда доверять**, закрыть окно,
ввести пароль.

## Проверка

```bash
security find-identity -v -p codesigning   # должна появиться строка "DOKA Dev"
```

После этого пересоберите: `./build.sh` — в выводе будет
«Подписано сертификатом „DOKA Dev"», и разрешения перестанут сбрасываться.

> Примечание: ранее проект назывался Whisper и использовал сертификат
> «Whisper Dev». Если он остался в связке ключей, его можно удалить — для
> DOKA нужен именно «DOKA Dev» (или задайте своё имя через `DOKA_SIGN_ID`).
